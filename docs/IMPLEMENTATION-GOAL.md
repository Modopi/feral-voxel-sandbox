# FERAL 전체 기획 구현 Goal

이 문서는 구현을 지시하고 완료 여부를 판정하는 기준이다. 현재 구현 완료 또는 배포 완료를 뜻하지 않는다.

## 목표와 기준 문서

FERAL의 확정 기획·콘텐츠 데이터·복셀 디자인을 실제 게임에 통합하고, 정상적인 플레이로 이용할 수 있는 새 버전을 기존 공식 경로로 배포한다. 문서, 데이터, 모델, 개별 시스템의 완성에서 끝내지 않고 화면·입력·물리·저장·진행·배포까지 연결한다.

기준은 사용자의 최신 확정 사항, `docs/GAME-VISION.md`, `docs/CONTENT-PROGRESSION.md`, `docs/content/`의 분야별 명세와 통합 검증 문서, `design/content/`의 실제 데이터, `design/assets/`의 디자인 원본이다. 제작·충돌은 `docs/VOXEL-ASSET-RULES.md`, 개발·배포는 `AGENTS.md`와 `docs/RELEASING.md`를 따른다. 사용자의 최신 결정이 과거 문서보다 우선한다.

작업 시작 시 요구사항 목록을 만들고 각 항목을 구현 위치, 테스트, 실제 플레이 증거, 남은 문제와 연결한다. 기존 `docs/content/IMPLEMENTATION-STATUS.md`를 이 추적표로 사용한다. 과거 구현이나 에셋 생성 결과를 신규 게임 통합 완료로 계산하지 않는다.

## 구현 범위

1. **월드·환경·탐험:** 8환경·33블록, 지형·광물·채집물·건축 입지와 생물 스폰, 무한 청크 생성·활성화·저장. 최초 스폰을 거리 난도의 기준과 기본 리스폰 지점으로 유지한다. 중간 난도 5~6티어를 중심으로 하고, 먼 지역의 고난도 구역은 퍼져 있는 국소 영역으로 배치하여 우회 가능하게 한다. 탐험의 주요 발견물인 던전·공동체·유적을 환경에 맞게 배치한다.
2. **엔티티·생태:** 사물·기계·유기생명·무기생명의 분류, 34종의 실제 모델·행동·이동·스탯·부위 손상·드롭, 외부 먹이사슬과 던전의 폐쇄 생태. 유기생명은 개체별 칼로리 소비와 피격 유예·휴식에 따른 자연회복을 사용하고, 무기생명은 칼로리와 자연회복 없이 수리로 회복한다. 문명 속성과 공동체 상태는 분리한다.
3. **건축물·던전·보스:** 12건축물·84방, 출입구·통로·파괴·퍼즐·보상·내부 생태, 8보스·24페이즈·32기술. 예고·피해·회피·차폐·약점·기관 파손·전장 변화가 화면과 실제 판정에서 일치해야 한다. 개인 장비와 제작 기계를 이용한 공략을 연결한다.
4. **성장·연구·제작:** 1~10티어·31재료, 자유롭게 혼합하는 네 연구 분야, 39연구·142제작법·27설비·13컴포넌트와 관련 아이템 경로. 모든 지식과 제작물은 자체 연구·제작으로 도달할 수 있고 발견은 이를 가속한다. 재료의 고유 용도와 초기 투자 차이를 유지한다. 실제 재료·시간·에너지를 소비한다.
5. **자유 제작·물리·에너지:** 정의된 기능 컴포넌트와 복셀의 외형·재질·질량·내구·물성을 분리한다. 플레이어가 만든 구조물은 반드시 기계 엔티티로 유지하며, 조립·연결·작동·조종·파손·수리·분리·저장을 실제 게임에 연결한다. 역학·전기·열·화학·마법·신성의 생성·저장·전달·변환·소비와 피해·물성 반응을 구현한다. 액체 마나, 성물의 생산·저장, 마법의 물성 추가와 신성의 기존 물성 강화도 포함한다.
6. **생활·공동체·회수:** 거점의 생산·보급·회복, 문명 공동체와 상호작용·거래·기여·관련 활동, 사망 시 전체 소지 아이템의 현장 보존과 사망 위치 10m 이내 요정 회수. 여러 번의 사망, 가방 포화, 지역 이탈과 저장 재개에서도 중복·소멸이 없어야 한다.
7. **시각·조작·연동:** 기존 디자인을 실제 월드와 엔티티에 사용하고, 필요한 도구·장비·설비·컴포넌트의 모델·장착·조작 표현을 연결한다. 플레이어는 일반 게임 진입과 화면 조작으로 콘텐츠를 이용할 수 있어야 한다. 저장·불러오기, 모바일 입력과 화면, 기존 기능과의 호환성까지 포함한다.

위 수량은 원본 명세를 누락하지 않기 위한 점검 기준이며, 이름만 등록한 항목을 구현으로 세지 않는다. 문서의 ‘후속’, ‘미검증’ 표시를 자동으로 범위에서 제외하지 않는다. 미해결 연결 항목은 기존 원칙을 구현하는 데 필요한 범위에서 구체화하고 근거를 기록하며, 무관한 신규 콘텐츠를 임의로 늘리지 않는다. 비교용 장비 수치를 개별 무기 설계의 완성으로, 보스 원형을 미구현 고티어 변형의 완성으로 표시하지 않는다. 사용자가 후속으로 미룬 유기·무기 생명 제작은 이번 범위에서 제외한다.

## 효율적인 역할 배분

- 총괄은 공통 변수·단위·ID·API·저장 계약, 실제 게임 연결, 병합과 배포를 맡는다.
- 독립 작업은 환경·월드, 생명체·생태, 건축물·던전, 보스·전투, 성장·제작·에너지로 분담하고 독립 검토 담당을 둔다. 가용 에이전트 수와 의존성에 따라 담당을 묶거나 순차 배정한다.
- 공유 계약과 파일 소유권을 먼저 정한다. 여러 담당이 같은 파일을 동시에 수정하거나 같은 기능을 중복 구현하지 않도록 조정한다. 공통 파일 변경은 총괄 또는 지정 소유자를 통해 반영한다.
- 기존 로직·제작 도구·에셋을 재사용한다. 각 분야 결과는 작은 단위로 바로 통합·검증하여 마지막에 통합 문제가 몰리지 않도록 한다. 에이전트 수보다 완료까지의 의존 경로와 통합 비용을 기준으로 배정한다.
- 통상적인 구현 판단과 기존 기획에 부합하는 보완은 자율적으로 수행하고 기록한다. 핵심 방향을 반복 질문하지 않는다. 범위를 바꾸는 결정이나 필요한 외부 접근이 실제로 막힌 경우에만 필요한 사항을 명확히 보고한다.

## 반드시 유지할 규칙

- 새로 만들거나 변경하는 복셀은 지정 제작 SDK/편집기를 거친다. 같은 부위의 중복 점유를 생성 시점에 막고, 관절 피벗과 움직임 여유를 보존한다.
- 동일 엔티티 인스턴스의 자식 몸체는 자기 충돌을 제외한다. 다른 인스턴스와 외부 고체 지형에는 실제 형상으로 충돌한다. 종 ID를 소유자 ID로 쓰거나 외곽 박스로 빈 공간을 막지 않는다.
- 기존 월드·저장과 이미 배포한 버전을 보존한다. 필요한 이전은 호환성 검사와 복구 경로를 갖춘다. 게임 버전, 네이티브 버전, 저장 스키마를 혼동하지 않는다.
- 필수 검사와 제작 하네스를 우회하거나, 미구현 기능을 숨겨 전체 완료로 처리하지 않는다.

## 완료 조건

1. 요구사항 추적표의 범위 내 모든 항목에 구현과 검증 근거가 있고, 실제 게임에서 기능이 연결되어 있다. 데이터 등록·정적 도달성·렌더 이미지·개별 모델 테스트만으로 완료를 판정하지 않는다.
2. 새 월드의 정상 시작 상태에서 탐험 → 채집 → 연구 → 가공·제작 → 장비·기계 운용 → 던전·보스 → 다음 성장으로 진행할 수 있다. 재료·시간·에너지를 실제로 소비하는 경로로 10티어와 네 연구 분야의 접근성을 검사한다. 발견 보상 없이도 진행 가능해야 한다. 검사 도구의 자원 지급을 정상 플레이 도달의 증거로 사용하지 않는다.
3. 대표 플레이 경로는 실제 화면·일반 입력으로 검증하고, 전체 콘텐츠의 참조·비용·행동·저장 계약은 자동 검사로 보완한다. 개인과 기계 공략, 사망 회수, 재접속과 중단 복구를 확인한다.
4. 무한 월드의 장거리 이동·재방문·변경분 보존·활성 범위와 메모리, 최소 2시간의 생태 진행, 물리·파괴·에너지 수지와 보상 중복 방지를 검사한다. 성능은 측정 환경·방법·결과와 함께 기록한다.
5. 모바일 화면·터치 조작·앱 생명주기와 목표 기기 성능을 검증한다. 측정 대상 기기·장면·시간과 프레임·메모리 등의 합격 기준을 검사 전에 명시한다. 실제 기기가 필요한 발열·장시간 안정성·성능은 에뮬레이션이나 데스크톱 결과로 대체해 완료 처리하지 않는다. 접근할 수 없는 검증은 구체적인 미검증 조건과 필요한 환경을 남기며, 가능한 다른 작업은 계속 마무리한다.
6. 전체 필수 테스트, 에셋 하네스, 관련 브라우저 검증, APK 빌드와 업데이트 패키지 검사를 통과한다. 실패한 필수 검사·미해결 리뷰·병합 충돌을 해결한 뒤 저장소 지침에 따라 PR을 병합한다.
7. 새 게임 버전과 단조 증가하는 빌드 번호로 배포한다. 실제 검증한 코드·콘텐츠·에셋과 배포 산출물의 버전·해시가 일치해야 한다. README와 기존 공식 업데이트 경로를 사용하고, 과거 릴리스 파일을 덮어쓰지 않는다. GitHub Release, 공개 stable/catalog, 파일 해시와 클라이언트 업데이트·재시작·저장 복원을 확인한다. 클라이언트를 직접 확인하지 못했다면 공개 게시 확인과 구분해 보고한다.

중간 버전 배포는 가능하지만 그것만으로 전체 Goal을 완료 처리하지 않는다. 최종 보고에는 구현 범위, 실제 검증 근거, 새 버전·배포 위치와 남은 제한을 명시한다. 외부 환경 때문에 검증이 막혔다면 전체 완료와 구분하여 정확히 보고한다.
