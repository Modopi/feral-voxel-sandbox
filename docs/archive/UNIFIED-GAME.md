# 하나의 게임으로 통합

> **보관 문서.** 작성 당시 버전의 설명이며 현재 구조·규칙의 기준이 아니다. 현재 기준은 [소프트웨어 구조](../ARCHITECTURE.md), [현황](../STATUS.md), [게임 규칙](../GAME-RULES.md)이다. 옛 엔진의 기능을 통합 세션으로 옮길 때 동작을 참고하는 용도로만 쓴다.

> 사용자 확정: 2026-10-18 · 시작 버전: 게임 0.13.0
>
> FERAL은 맵마다 다른 게임이 아니라 **하나의 화면, 하나의 규칙·데이터, 하나의 런타임** 위에서 맵만 바뀌는 게임이다. 이 문서는 그 목표 구조와 단계, 저장 변환 규칙의 기준이다.

## 1. 결정 사항

| 항목 | 결정 |
| --- | --- |
| 통합 기준 | **새 런타임 + 기존 UI.** 월드·규칙·데이터는 무한 월드와 확정 기획 데이터를 가진 콘텐츠 런타임(`content-runtime/`) 하나를 쓴다. 화면·조작·HUD 편집·가방·설정은 기존 UI(`index.html`)를 그대로 쓴다. |
| 기존 맵 | **통합 시스템의 맵으로 이식.** 기본 섬·개척 원정·기계 시험장은 같은 UI·규칙 위의 맵 설정(프리셋)으로 다시 만든다. |
| 기존 저장 | 위치·지형 편집·아이템처럼 대응되는 부분을 변환한다. 대응되지 않는 항목은 목록으로 알린다. 원본 저장은 지우지 않는다. |
| 기존 전용 기능 | 운반·충격 피해·공기역학·구조체·첫 신호 캠페인·농사 등 기존 게임에만 있던 기능은 버리지 않고 런타임으로 옮긴다. |
| 화면·감각 기준 (2026-10-18 추가) | **개척 원정이 기준.** 가장 완성된 개척 원정 화면(상태·지도·장부·1인칭 손)을 공용으로 옮겨 모든 맵이 쓰고 확장한다. 조작 감각도 개척 원정을 따른다: 채집은 즉시, 지형·분리된 덩어리는 개척 원정 채굴 공식, 생명체는 외피가 깎이고 골격이 드러나는 층 구조. 타격 방식은 든 도구·무기가 정한다(도구 점타격·검 선/면·창 관통선·둔기 안쪽 뼈, 0.14.1). 통합 런타임의 단순화된 규칙으로 약화하지 않는다. |

## 2. 문제였던 구조

0.12.1까지 FERAL에는 진입 화면마다 다른 게임이 붙어 있었다.

| 영역 | 기본 섬·개척 원정 | 콘텐츠 탐험 | 기계 시험장 |
| --- | --- | --- | --- |
| 페이지 | `index.html` + `main.js` | `expedition.html` + `content-runtime/entry.js` | `machine.html` |
| 화면·HUD | 핫바, 36칸 가방, 체력·포만, HUD 편집기, 원정 장부 | 자체 패널·버튼 | 자체 화면 |
| 설정·알림·조작 | 그래픽·감도·시야각·왼손·소리, 알림 1개, 누르고 있기 버튼 | 설정 없음, 자체 알림 큐, 자체 조작 | 자체 |
| 아이템·제작 | `inventory.js` 47종 | 설계 데이터 31재료·142제작법 | 부품 전용 |
| 생명체·월드 | `entities.js` 3종, 고정 크기 섬·지역 전환 | `creatures.js` 34종, 무한 청크 | 고정 격자 |
| 저장 | `feral.world.v1`·슬롯 JSON | 압축 2세대 저장 | `feral.machine.v1` |

공통으로 쓴 것은 캐릭터 이동 계산, 월드 슬롯, 업데이트 메뉴, 버전뿐이었다. 0.11.0의 콘텐츠 통합과 0.12.0의 화면 연결이 기존 UI를 재사용하지 않고 새 화면을 만들면서 분리가 굳어졌다.

## 3. 목표 구조

```
worlds.html            월드 목록 (게임 화면이 아님)
index.html             유일한 게임 화면. 로딩 단계·진행도·실패 안내(모듈이 실패해도 동작하는 일반 스크립트)
 └ game.js             월드를 읽고 맵에 맞는 게임을 시작
    ├ shell.js         모든 맵이 함께 쓰는 화면·조작 (앱의 업데이트 파일 수 상한 128개 때문에 한 모듈)
    │   알림           알림 하나 (즉시 결과는 교체, 세계 사건은 대기열), 장소 발견 배너
    │   조작           스틱·시점·누르고 있기 버튼·키보드
    │   이동 버튼      달리기·웅크리기·기어가기·하강·제동 버튼 상태
    │   설정           그래픽·감도·시야각·소리·왼손·미니맵·사건 알림
    │   메뉴           일시정지 메뉴 탭, 백그라운드 저장, 오류 화면
    │   현장 HUD       체력·포만, 목적지, 지도·상태·상호작용 버튼, 현재 목표
    │   장부 창        탭·닫기·초점·안내 문구
    ├ hud-editor.js    UI 배치 편집기 (모든 맵 공통)
    ├ inventory-ui.js  36칸 가방·핫바·제작 (아이템 카탈로그 어댑터로 표시)
    └ 런타임           content-runtime/ — 맵 프리셋이 지형 생성기·시작 장비·활성 시스템을 정한다
```

- 새 화면 요소는 `shell.js`나 기존 공용 모듈에만 추가한다. 맵 전용 HUD·패널·CSS 파일을 새로 만들지 않는다.
- 같은 기능이 이미 있으면 그 코드를 옮겨 공용화한다. 새로 비슷한 기능을 만들지 않는다.
- 맵별 차이는 프리셋 데이터와 런타임 시스템의 활성 여부로 표현한다.
- `expedition.html`과 `machine.html`은 예전 주소를 위해 `index.html`로 넘기는 호환 페이지로만 남긴다.
- 앱 0.3.3은 게임 업데이트 하나에 파일 128개까지 받는다(`UpdateCore.MAX_FILES`). 0.13.0은 122개다. 새 파일을 늘리는 단계는 같은 버전에서 은퇴할 기존 파일을 함께 정리하거나, 상한을 올린 새 APK와 `minNativeCode` 증가가 필요하다. `tests/unified-game.test.js`가 여유 4개 이상을 확인한다.

## 4. 단계

각 단계는 별도 버전으로 배포한다. 단계가 끝날 때마다 이 표를 갱신한다. 0.14.0부터는 기존 맵을 하나씩 통합 런타임의 맵 설정으로 옮기고, 그 맵에 필요한 기존 전용 기능을 같은 단계에서 런타임으로 옮긴다(규칙·데이터 통합과 맵 이식을 함께 진행).

| 단계 | 버전 | 범위 | 상태 |
| --- | --- | --- | --- |
| P1 하나의 화면 | 0.13.0 | `main.js`에서 조작·설정·알림·메뉴·로딩을 `shell.js`로 옮기고, 개척 원정의 현장 HUD와 장부 창을 공용화한다. 콘텐츠 탐험을 `index.html`의 HUD·핫바·36칸 가방·장부 창·메뉴·설정·HUD 편집기로 옮긴다. `expedition.html`은 호환 페이지가 된다. | 완료 · 2026-10-18 공개 |
| P2 기본 섬을 통합 런타임으로 | 0.14.0 | 맵 설정 체계(`content-runtime/maps.js`). 기본 섬을 원본 섬 생성기 그대로의 지형, 같은 세 종의 생태, 평화 규칙, 샌드박스 도구, 캔 자원으로 블록 쌓기, 다섯 장소 발견, 미니맵으로 옮긴다. 기존 섬 저장을 변환하고, 기존 아이템·블록·종의 대응표를 만든다. | 완료 · 병합 후 공개([검증](../../verification/0.14.0.md)) |
| P3 개척 원정을 통합 런타임으로 | 0.15.x | 첫 신호 캠페인·마을·지역·기계 비행과 운반·충격 피해를 런타임으로 옮기고 개척 원정 저장을 변환한다. | 예정 |
| P4 기계 시험장과 기존 런타임 은퇴 | 0.16.x | 기계 시험장을 맵 설정으로 옮긴다. `main.js`와 기존 `world.js` 시뮬레이션·`entities.js`·`render.js`·`inventory.js`·`machine.html`을 은퇴시킨다(섬 생성 코드는 유지). | 예정 |

### P1 완료 기준

- 모든 월드 유형(기계 시험장 제외)이 `index.html` 한 페이지에서 시작한다. 기계 시험장은 P4에서 옮긴다.
- 콘텐츠 탐험이 기존 HUD 요소(스틱·동작 버튼·핫바·체력·포만·목적지·알림·조준 카드), 일시정지 메뉴(탐험·환경 설정·조작 안내·업데이트), 36칸 가방, 장부 창, UI 배치 편집기를 그대로 쓴다.
- 콘텐츠 탐험 전용 CSS(`content-runtime/expedition.css`)와 전용 패널·알림·조작 코드를 없앤다.
- 섬·개척 원정의 기존 동작과 검사가 유지된다.

### P2 완료 기준

- 기본 섬(`island` 유형)이 콘텐츠 탐험과 같은 런타임(`ExpeditionRuntime`)·같은 화면에서 시작한다. 맵 설정은 지형 생성기·규칙·시작 소지품·장소만 정한다.
- 섬 지형은 원본 섬 생성기(`world.js`)가 만든 칸과 같고, 블록은 설계 블록으로 대응한다. 생태는 설계 데이터의 같은 세 종(이끼사슴·구리여우·청금딱정)이다.
- 섬 규칙: 체력·식량이 줄지 않는 평화 규칙, 개발·생태 탭의 샌드박스 도구(관찰·물·불·산·개체 생성·24마리), 빈 손 사용은 관찰, 캔 자원으로 블록 쌓기(0.5 m 칸당 1개, 1 m는 8개, 물은 위로 밀어냄). 콘텐츠 탐험의 경제(기계 복셀 조립)는 바꾸지 않는다.
- 기존 섬 저장을 변환하고 원본을 보존한다. 대응되지 않는 항목은 여정 페이지에 목록으로 보여 준다.
- 개척 원정 감각(사용자 결정으로 추가): 채집은 즉시, 지형과 분리된 덩어리는 개척 원정 채굴 공식(0.18초·재질 경도·도구 성능·0.5/1 m)과 칸마다 산출, 빈 손 공격은 덩어리 밀기, 생명체는 외피가 깎이고 골격이 드러나며 드러난 뼈를 쳐야 부러진다. 상태·지도 페이지와 1인칭 손·공격 버튼은 개척 원정 화면을 공용으로 옮겨 쓴다.

## 5. 저장 변환 규칙

- 원본 키(`feral.world.v1`, `feral.slot.<id>`, `feral.machine.v1`)는 지우지 않는다. 변환 결과는 콘텐츠 런타임 저장 형식(`<원본 키>.a/.b` 2세대)으로 쓴다. 두 세대 저장이 있으면 원본은 다시 읽지 않는다. 월드를 삭제하거나 "새 세계"로 다시 만들면 원본도 함께 지운다.
- 변환은 같은 입력에 같은 결과를 내고, 새 월드 시작 소지품을 더하지 않는다.
- 지형은 원본 로더가 원본 저장을 원본 생성기에 적용한 결과와 새로 생성한 섬을 칸 단위로 비교해, 다른 칸만 옮긴다.
- 반쯤 캔 칸의 균열(채굴 손상도)은 같은 0.5 m 칸·같은 개척 원정 채굴 규칙이므로 그대로 옮긴다.
- 아이템 대응(`LEGACY_ITEMS`): 블록 조각은 대응 블록의 설계 채집량(칸당 1)으로, 소모품은 같은 개수로 옮긴다. 들열매·약초·날고기·야전 식량·야채 스튜(→ 보급 식량)·씨앗·돌 조각(→ 주운 돌)·원목 조각(→ 미가공 목재)·흙 조각(→ 흙)·모래·광석 결정(→ 철 원광)·식물 섬유·돌 곡괭이·나무 곡괭이(→ 섬의 시작 도구인 돌 곡괭이).
- 대응되지 않는 항목: 위 목록 밖의 아이템(무기·화살·회복약·합금·목재 조각 등), 기존 연구(같은 연구를 다시 진행), 직접 부은 물·산, 불, 떨어진 물체, 동물 개체의 개별 상태. 변환 보고서(`conversion`)로 저장하고 여정 페이지에 보여 준다.
- 변환이나 시작에 실패하면 로딩 화면이 실패를 안내하고 앱에 시작 실패(`runtimeFailed`)를 알려, 앱이 이전 게임 버전과 업데이트 직전 저장으로 되돌린다. 원본 키는 남아 있으므로 이전 버전에서 원본으로 계속할 수 있다.
