# 구조 손상과 월드 조립 — 게임 0.6.0

## 참고한 공식 자료

사용자가 언급한 “에어로…”는 **Create Aeronautics**로 판단했다. 공식 [Create Aeronautics 소개](https://www.curseforge.com/minecraft/mc-mods/create-aeronautics)는 조립·상호작용을 Simulated, 비행을 Aeronautics, 육상 주행을 Offroad로 구분한다. 기반인 [Sable](https://www.curseforge.com/minecraft/mc-mods/sable)은 블록과 엔티티가 상호작용을 유지하는 움직이는 sub-level과 Rapier 기반 물리를 설명한다. 공식 사이트: https://createsimulated.com/ . 2026-10-17 확인.

FERAL은 그 구조적 접근을 참고했다. 모드 코드나 자산을 복사하지 않았다. Three.js는 표현에 유지하고, 독립된 물리 계층에 Rapier를 사용한다. Babylon.js 이전은 이 변경에 포함하지 않는다.

## 실제 조작

1. 동력 연구 후 가방에서 차체·모터·바퀴를 제작한다. 회전익은 회전익 연구, 포탑은 투사체 연구가 필요하다. 기본 차량 설계는 기존처럼 출발 차량을 마련한다.
2. 부품을 핫바에 놓고 선택한다. 첫 차체는 지형 위에 놓고, 이후에는 조립체의 면을 조준해 **사용**으로 붙인다. 초록 미리보기는 배치 가능, 빨강은 겹침·고정 필요 등으로 배치 불가다.
3. 조립 렌치의 **공격**은 부품 회수, **사용**은 조립 고정/해제다. 온전한 부품은 아이템으로, 손상된 부품은 남은 체력 비율만큼 합금으로 회수한다. 가방 공간이 없으면 회수하지 않는다.
4. 합금을 들고 손상된 부품에 **사용**하면 수리한다. 재료가 없으면 상태를 바꾸지 않는다. 파괴되어 사라진 부품은 새 부품을 붙여 교체한다.
5. 가까이에서 **상호작용 / R**로 탑승·하차한다. 전후 이동은 추진, 좌우 이동은 조향, 점프는 육상 제동이다. 회전익 비행에서는 점프/상승으로 추력 증가, Q/하강으로 감소한다. 양쪽에 균형 있게 배치해야 안정적이다.
6. 내린 차량과 떨어진 조각은 현장에 남는다. 조각도 렌치로 회수할 수 있다. 지역 이동은 차량을 운반하지 않는다.

## 동물의 구조와 행동

`structure.js`의 면 연결 탐색을 생체 복셀과 기계 부품이 공유한다. `anatomy.js`는 다리의 부착 층부터 발 층까지 연결된 경로가 있어야 지지 다리로 센다. 발 한 복셀만 없어져도 부위 전체 분리 비트와 무관하게 기능을 잃는다.

| 지지 다리 | 이동 | 정상 대비 속도 | 높이·장애물 |
| --- | --- | --- | --- |
| 4 | 보행 | 100% | 기존 1.2m 단차 |
| 3 | 절뚝거림 | 55% | 몸을 낮추고 0.45m 이하 단차 |
| 대각선 2 | 기기 | 22% | 0.12m 이하 단차 |
| 같은 쪽/앞뒤 2 | 기기 | 12% | 지지 방향으로 기울어짐 |
| 1 | 끌며 이동 | 4.5% | 몸통을 지면 가까이 낮춤 |
| 0 | 방어·휴식 | 0% | 추적 이동 중지 |

기존 공포 배율은 남지만 손상 배율을 우회하지 않는다. 움직일 수 없는 포식자도 실제 가까운 공격 범위에서는 방어할 수 있다. 체력 0, 머리/몸통 파괴, 에너지 소진은 기존 사망 규칙을 유지한다. 자세 변환을 렌더링과 타격 판정이 함께 사용하고, 먼 거리에서도 제거된 복셀을 다시 그리지 않는다. 저장된 파생 자세는 신뢰하지 않고 손상 마스크에서 다시 계산한다.

## 독립된 조립체 물리

- 조립체는 0.5m 로컬 좌표의 부품 집합, 독립된 위치·쿼터니언·선속도·각속도·지역을 가진다. 현재 소유 본체 1개와 최대 147개 부품 규모다. 여러 독립 차량의 소유/관리 UI는 아직 없다.
- Rapier compound body에 살아 있는 부품별 질량과 충돌 형상을 넣는다. 제거하면 무게중심·관성도 바뀐다. 끊긴 연결 성분은 별도 강체로 분리하고 분리 위치의 속도를 넘긴다.
- 지형의 세부 0.5m 편집과 충돌 형상을 함께 갱신한다. 주변 지형의 수직 구간을 합치고, 관련 청크 변경 때 재생성한다. 중력·충돌·회전은 플레이어의 위치와 독립적으로 진행한다.
- 바퀴 접촉 때만 지상 추진·조향을 적용한다. 엔진 체력이 동력, 바퀴 체력이 접지/조향 능력에 반영된다. 회전익은 부품의 위치에 힘을 가하므로 한쪽 손실이 회전과 추락으로 이어진다. 강한 충돌은 접촉 부품을 손상한다.
- 보행 플레이어는 기존 지형 컨트롤러와 Rapier 캐릭터 충돌 보정을 함께 사용한다. 탑승 시에는 조립체의 좌석 위치를 따른다.
- 실제 기계의 바퀴 회전 관절·서스펜션·공력/양력장·기어/축 동력망·밧줄은 아직 모델링하지 않는다. 바퀴는 구형 접촉과 접지력 제어, 회전익은 단순 추력 모델이다. 동물은 지지 상태 기반 운동이며 전신 관절 래그돌이 아니다. 별도 기계 베타 맵은 기존 2D 모델을 유지한다.

## 의존성

`@dimforge/rapier3d-compat` **0.21.0**, Apache-2.0. npm 배포물의 `dist/rapier.mjs`를 Android WebView MIME 호환을 위해 `vendor/rapier/rapier.js` 이름으로 그대로 동봉했다. 내장 WASM 사용. 라이선스는 같은 디렉터리의 `LICENSE`에 있다. 코어 모델과 저장 형식에는 Rapier/Three 객체를 기록하지 않는다.
