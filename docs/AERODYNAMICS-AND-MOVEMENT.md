# 공기역학과 이동 자세 — 게임 0.7.0

앱 0.3.3(303)을 기존 앱 위에 설치한다. 게임 코드 700, 최소 앱 303, 저장 스키마 2. 0.6.0의 조립체·동물 구조 손상은 유지하며 전신 관절 래그돌은 추가하지 않았다.

## 항공 조립과 조작

개척 원정 가방에서 항공 연구 후 주날개·수평/수직 꼬리날개·프로펠러를 제작한다. 합금 89개의 **경량 비행기 부품 묶음**은 차체 6, 모터 1, 주날개 24, 수평 꼬리 4, 수직 꼬리 1, 프로펠러 1, 바퀴 3을 준다. 완성 기체를 생성하지 않으며 기존처럼 핫바의 부품을 월드에서 면에 직접 붙인다. 슬롯 공간과 재료 검사는 다른 제작과 동일하다.

차체의 처음 앞 방향은 북쪽(-Z), 위는 +Y다. 조립 격자는 0.5m이며 본체 중심의 첫 차체가 (0,0,0)이다. 이륙을 검증한 예제는 다음과 같다. 아래쪽 바퀴를 놓을 공간이 있도록 지면 위에서 고정한 차체를 만든 뒤 조립한다. 기계 안내 창에서도 같은 예를 볼 수 있다.

| 부품 | 로컬 격자 위치 |
| --- | --- |
| 차체 6 | X=0, Y=0, Z=-2,-1,0,1,2,3 |
| 모터 1 | (0,1,0) |
| 프로펠러 1 | (0,0,-3) |
| 주날개 24 | X=-4,-3,-2,-1,1,2,3,4 × Z=-1,0,1, Y=0 |
| 수평 꼬리 4 | X=-2,-1,1,2, Y=0, Z=3 |
| 수직 꼬리 1 | (0,1,3) |
| 바퀴 3 | (-4,-1,0), (4,-1,0), (0,-1,-2) |

렌치로 고정을 해제하고 탑승한 뒤 **비행 / F**를 켠다. 평평한 활주로에서 출력을 높이고 속도를 얻는다. 예제의 경우 대기 속도 약 20m/s부터 짧게 기수를 올려 이륙한다. 부품 위치·질량이 달라지면 이 속도도 달라진다.

| 입력 | 고정익 | 회전익 | 지상 차량 |
| --- | --- | --- | --- |
| 스틱 앞/뒤, W/S | 출력 증가/감소(초당 50%), 중립에서 유지 | 앞/뒤 추진 | 앞/뒤 주행 |
| 스틱 좌/우, A/D | 주날개와 수직 꼬리 조종 | 방향 전환 | 접지한 바퀴 조향 |
| ↑, Space/E | 기수 올리기 | 상승 추력 증가 | Space 제동 |
| ↓, Q | 기수 내리기 | 상승 추력 감소 | 없음 |
| 비행/F | 프로펠러 작동 전환 | 회전익 작동 전환 | 항공 부품·연구 필요 |
| 상호작용/R | 하차(기체는 현장에 남음) | 하차 | 하차 |

비행 계기는 화면 옆에 대기 속도, 출력, 주날개 양력/기체 중량, 실속 경고를 표시한다. 별도 중앙 정보창은 열리지 않는다. 모바일 하강 버튼은 비행 중에 나타나며 탑승 중 자세 버튼은 숨는다. 새 조작과 계기는 메뉴 → UI 배치 편집에서 이동/크기 조절할 수 있다.

## 공력 모델

`machine/aerodynamics.js`는 DOM·물리 엔진과 독립된 계산이다. 부품 위치에서 강체의 선속도와 회전으로 인한 속도를 함께 읽고, 공기 속도를 뺀 후 로컬 축으로 바꾼다. 기본 공기는 정지 상태이며 `AssemblyPhysics.wind`를 통해 상대 바람도 계산할 수 있다. 날씨/바람 UI는 없다.

- 한 날개 패널은 0.25m², 공기 밀도는 1.225kg/m³다. 동압은 `0.5 × 밀도 × 속도²`. 받음각과 조종면 편향으로 양력·항력 계수를 계산한다.
- 양력은 패널 평면 내 속도에 수직, 항력은 반대 방향이다. 15도부터 실속 구간으로 전이하며 큰 받음각에서는 평판 근사 계수와 항력 증가를 사용한다. 전진·후진 공기 흐름에서 수동 공력이 에너지를 만들지 않는지 검증한다.
- 수평 꼬리는 기수, 수직 꼬리는 방향, 좌우 주날개의 반대 편향은 기울기를 조절한다. 힘을 각 부품의 실제 위치에 가하므로 무게중심·배치·한쪽 날개 손실이 회전으로 이어진다.
- 차체는 공기 흐름을 받는 노출 면만 형상 항력을 만든다. 내부 면은 중복 계산하지 않는다. 얇은 날개/꼬리는 판 형상으로 렌더링하고 충돌도 얇게 만든다.
- 모터 출력과 프로펠러 체력에 따라 추력이 줄어든다. 여러 프로펠러는 연결된 모터 동력을 나눈다. 모터가 없어도 남은 속도에 따른 활공·실속·항력은 계속 계산한다.
- 날개 손상은 양력을 낮추고 항력을 높인다. 분리된 조각은 조종/동력 없이도 공력을 받는다. 작은 고속 조각의 수치 폭주를 막도록 패널의 한 틱 힘을 제한한다.
- 기존 일률적 선형 감쇠를 낮추고 속도/형상별 항력을 적용했다. 160m 지역과 높이 80m의 물리 경계 안에서 작동한다.

이는 게임용 패널 기반 근사다. CFD, 압축성, 후류 간섭, 프로펠러 슬립스트림, 구조 유연성, 바퀴 서스펜션은 모델링하지 않는다. 조종면은 패널 힘에 반영하며 별도 힌지 애니메이션은 없다. 별도 기계 베타 맵의 2D 시뮬레이션은 유지한다.

## 사람의 자세와 이동

| 동작 | 몸 높이 | 눈높이 | 기본 속도 | 입력 |
| --- | --- | --- | --- | --- |
| 걷기 | 1.5m | 1.36m | 3.2m/s | 이동 스틱/WASD |
| 달리기 | 1.5m | 1.36m | 4.8m/s | 달리기 버튼 전환, Shift 누르기 |
| 웅크리기 | 1m | 0.86m | 1.6m/s | 웅크리기 버튼/C 전환 |
| 기어가기 | 0.5m | 0.36m | 0.85m/s | 기어가기 버튼/Z 전환 |

동작은 1인칭 플레이어의 실제 지형 충돌·조립체 충돌·시야·속도·설치 겹침 판정에 적용된다. 낮은 자세에서 점프 버튼/Space는 먼저 일어서기를 요청한다. 천장 또는 조립체가 막으면 낮은 자세를 유지하고 벗어나면 일어선다. 낮은 자세에서는 달리기나 점프를 하지 않으며 기어갈 때 자동 계단 오르기도 하지 않는다. 자세는 저장되고, 구 저장은 서 있는 상태로 읽는다. 달리기 입력은 메뉴·앱 비활성화 시 해제한다. 별도의 3인칭 인체 애니메이션이나 전신 관절 물리는 추가하지 않았다.

## 0.6.0 실패와 재시도

앱 0.3.2는 `script-src 'self' 'unsafe-inline'` 정책으로 내장 WASM 컴파일을 차단했다. 같은 CSP를 사용한 브라우저에서 실패를 재현했다. 앱 0.3.3은 `wasm-unsafe-eval`을 추가한다. 일반 JavaScript `eval`/`new Function` 허용은 추가하지 않았고, 외부 네트워크 정책도 유지한다.

버전 목록의 **[실행 실패 · 재시도] → 다시 검증 후 실행**을 통해 같은 빌드를 다시 선택할 수 있다. 공개 패키지의 서명·해시·파일 목록·앱 호환성을 다시 검사한다. 검증 성공 후에만 수동 선택에 묶인 1회 활성화 권한을 기록하며 실패 차단 표시는 정상 시작 확인 때까지 남긴다. 재시도 자체의 다운로드/검증 실패나 재실행 실패도 이전 정상 코드·저장을 보존한다. 동봉 버전의 실패 코드가 0으로 기록되던 경우도 수정했다.

시작 중 앱이 백그라운드로 가면 감시를 멈춘다. 그 상태에서 프로세스가 종료되면 다음 시작에서 이전 버전으로 복구하고 **시작 중단**으로 표시한다. 포그라운드 복귀 시 감시는 90초이며 최소 12 프레임/3초 정상 렌더 확인을 유지한다. 과거 버전에서 이미 생긴 실패에는 확정 원인이 없으므로 **실행 실패** 표시와 재시도를 제공한다. 이 휴대폰의 당시 종료 원인은 로그 없이 확정할 수 없지만 WASM 차단 문제는 별도로 재현·수정했다.
