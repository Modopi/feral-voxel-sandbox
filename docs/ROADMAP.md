# FERAL 로드맵

[소프트웨어 구조](ARCHITECTURE.md)의 [목표]를 만드는 단계와 완료 기준이다. 단계가 끝나면 이 표의 상태와 구조 문서의 [현재]를 함께 고친다. 지금 공개된 버전과 되는 것은 [현황](STATUS.md)을 본다.

사용자 결정 순서: **런처·게임 세션 구조를 먼저 세우고, 게임 세션 안의 엔진 통합은 그 뒤에 단계적으로 다듬는다.**

사용자 결정(2026-10-18): 이미 끝난 성능 수정(P1, 0.15.1)은 배포하고, 그다음 **엔진 통합(S1→S2→S3)을 먼저 끝낸 뒤** 남은 성능 작업(P2)을 한다.

### L1 완료 기준 (0.15.0)

- 앱을 켜면 런처의 랜딩이 나온다. 게임 엔진과 3D 월드는 월드에 들어갈 때만 불러온다.
- 런처에서 할 수 있는 것:
  - 월드 목록: 고르기·이어하기, 마지막 플레이 표시
  - 월드 만들기: 프리셋을 고르고 이름·시드·지원하는 설정 조정
  - 월드 설정 편집, 이름 변경, 삭제(확인 창)
  - 전역 설정(화질·감도·시야각·소리·왼손 조작·미니맵·사건 알림)
  - 업데이트·게임 버전 화면
  - UI 배치 편집기는 게임 화면의 버튼을 직접 옮기는 도구라 세션 메뉴에 둔다(런처 설정 화면에 안내)
- 월드 목록 항목에 월드 설정(`config`, `configVersion` 1)을 저장한다. 기존 월드는 처음 읽을 때 유형에 맞는 프리셋 설정을 만들고 원래 항목과 저장 키를 그대로 둔다. 이전 게임 빌드가 같은 목록을 읽어도 동작한다.
- 게임 세션은 `play.html?world=<id>` 하나로 시작한다. 옛 엔진을 고르는 분기는 세션 라우터 한 곳에만 있다. 세션 메뉴의 "월드 목록"은 저장 후 런처로 돌아간다. 기계 시험장도 같은 입구로 들어간다.
- 통합 런타임 월드(섬·콘텐츠 탐험)는 생존·샌드박스 설정을 월드 설정에서 읽는다. 런처는 세션이 실제로 읽는 항목만 보인다.
- 시작 성공 신호: 런처가 화면을 그리고 세션 진입 모듈을 실행하지 않고 불러 본 뒤에 보낸다. 세션 진입 모듈은 불러오기만으로는 아무것도 시작하지 않는다.
- 버전이 바뀌어도 저장 유지(사용자 요청으로 추가): 저장 보관함이 앱의 버전별 저장 분리로 비거나 오래된 저장을 최신 저장 전체로 되살린다. 검증은 앱이 하는 것처럼 `feral.*`를 모두 지운 뒤 런처가 월드와 저장을 되살리고 월드가 저장한 상태로 이어지는지 본다.
- 업데이트 파일 수가 앱 상한(128) 안에서 여유 4개 이상이다. 늘어난 파일만큼 은퇴 파일(`worlds.html`·`world-menu.js`·`expedition.html`)을 정리한다. 결과: 123개 그대로.
- 검증:
  - 전체 회귀, 앱 규칙 서버에서의 실제 터치 경로(앱 시작 → 랜딩 → 만들기 → 설정 → 입장 → 저장 후 나가기 → 설정 편집 → 다시 입장)
  - 기존 월드·저장 유지, 이전 빌드 목록 호환, APK·패키지 바이트 일치

### P1 완료 기준 (0.15.1)

- 측정: 게임 안 프레임 계측 `FERAL.perf`와 장면별 측정 도구 `tools/profile-runtime.mjs`가 있고, 같은 도구로 0.15.0과 비교한 수치를 `verification/0.15.1-perf.json`에 남긴다.
- 신고된 장면(나무 한 그루를 캐서 분리된 덩어리가 생긴 뒤)의 프레임 루프 JS 시간이 다른 장면과 같은 수준이다.
- 지형 충돌체·물 메시·지형 메시가 바뀐 4m 구역(지형 메시는 청크)만 다시 만든다. 흔들리는 덩어리와 멀리서 한 채굴은 아무것도 다시 만들지 않는다는 자동 검사가 있다.
- 고정 단계는 프레임당 최대 3번이고, 배경 작업은 남은 시간 안에서만 돈다. 생물 AI는 5개 조로 나눠 처리한다.
- 게임 규칙과 저장 형식은 바꾸지 않는다(`saveSchema` 그대로).

### P2a 완료 기준 (0.18.0) — 충족

사용자 결정(2026-10-18): 엔진 통합을 끝낸 뒤 성능 최적화로 가고, 생물 AI는 거리별 갱신을 적용한다(가까운 생물은 그대로, 먼 생물은 덜 자주).

- 지형 생성이 웹 워커에서 돈다. 워커 청크는 화면 스레드가 만든 청크와 같다(지형 생성기 넷, 편집·예약 구역·지역 지형 버전 포함). 워커가 준비되기 전과 실패한 뒤에는 화면 스레드가 예산 안에서 만든다([구조 7장](ARCHITECTURE.md#지형-워커-현재-0180부터)).
- 생물 AI가 거리별로 갱신된다(32 m 안 0.25초, 64 m 안 0.5초, 그 밖 1초). 건너뛴 시간을 잃지 않고, 먼 생물도 벽에 막히며, 화면은 먼 생물을 보간한다([게임 규칙 10장](GAME-RULES.md#10-생명체-갱신-빈도-0180부터-사용자-결정-2026-10-18)).
- 생물 이동의 지형 확인과 기계 물리 다리의 질량 비교가 반복 경로에서 할당하지 않는다.
- 측정 도구에 맵마다 첫 채움(원하는 청크를 다 만들고 메시까지 그린 시간)을 더하고, 0.17.0과 같은 도구로 비교한 수치를 `verification/0.18.0-perf.json`에 남긴다.
- 저장 형식은 바꾸지 않는다(`saveSchema` 4 그대로).

### P2b 실기기 예산 (예정)

- 실제 Android 기기에서 `FERAL.perf` 수치를 받아 예산을 맞춘다. 이 환경에는 기기가 없어 수치를 받은 뒤 진행한다.
- 워커 뒤 첫 채움의 병목인 지형 메시 생성을 워커로 옮길지 기기 수치로 판단한다.

### S1 완료 기준 (0.15.2)

- `ExpeditionRuntime`이 맵 이름 대신 월드 설정을 받는다. 지형 생성기는 이름으로 등록한다(`infinite`·`island`).
- 세션 화면 코드의 `map.id` 비교를 없앤다. 미니맵 범위·출발지 이름 같은 차이는 설정이나 생성기에서 읽는다.
- 섬 전용 문구를 공용 페이지에서 없앤다.
- 세션 코드에서 맵·프리셋 이름을 비교하면 실패하는 자동 검사를 둔다. 예외는 세션 라우터뿐이다.

### S2 완료 기준 (0.16.0)

사용자 결정(2026-10-18):

- 생존: 통합 런타임 규칙(칼로리·체력·연구)으로 한다. 개척 원정의 경험치·레벨과 음식 버프는 없애고, 캠페인 보상은 런타임 아이템과 연구로 바꾼다.
- 사망: 사망 시스템은 하나이고 월드 설정 "사망 시 소지품 남김"으로 고른다. 개척 원정 프리셋 기본은 끔(소지품을 지닌 채 지역 야영지에서 깨어남), 콘텐츠 탐험은 켬(사망 장소 보존과 요정 회수).
- 지역: 한 월드 안에서 바다로 나뉜 섬들이고 저장도 하나다. 이동 버튼은 식량 1개를 쓰고 페이지를 다시 읽지 않고 옮긴다. 기계로 날아서 건널 수도 있다.

완료 기준:

- 개척 원정이 통합 런타임의 프리셋과 모듈로 돈다. 지역 지형 생성기, 첫 신호 캠페인, 마을·공동체를 옮기고, 아래 표의 해당 기능을 옮긴다.
- 개척 원정 저장을 원본 보존 방식으로 변환하고, 옮기지 못한 항목을 목록으로 보인다.
- 개척 원정의 화면·감각(이미 공용 `shell.js`)과 [게임 규칙](GAME-RULES.md)을 유지한다.

### S3 완료 기준 (0.17.0) — 충족

S3 (0.17.0): 기계 시험장 프리셋을 지형 생성기 `machine-field`와 모듈 `machine-field`로(시작 장비·예제 기계·출발점 복귀). 바퀴 기계가 실제로 달리도록 바퀴 접지를 넣었다(바퀴 서스펜션이 기계를 땅 위로 받치고 견인·옆 미끄럼 방지·조향 힘이 민다; 전에는 Rapier에서 바퀴 기계가 땅에 끌려 움직이지 않았다). 옛 시험장 격자를 공용 기계 패널로 옮기고, 비어 있던 기계 계기를 조종 중에 채운다. 옛 시험장 저장은 원본을 남기고 변환한다. 옛 기계 시험장 페이지·모델과 통합 런타임이 쓰지 않던 옛 가방·생태 코드(`machine/` 5개, `inventory.js`·`acquisition.js`·`entities.js` 등 6개, 모두 11개 파일)를 지우고, 세션 라우터와 프리셋의 엔진 선택을 없앴다.


- 기계 시험장이 통합 런타임의 프리셋(평지 시험장 지형·기계 조립)으로 돈다. 저장을 변환한다.
- `machine.html`, `machine/`(쓰이는 부품 규칙은 옮긴 뒤), 옛 가방의 제작 규칙(`inventory.js`의 `Inventory`·`RECIPES`, `acquisition.js`의 개척 원정 경로)과 `entities.js`의 옛 생태 중 통합 런타임이 쓰지 않는 부분을 지운다. 세션 라우터의 엔진 분기도 없앤다. `world.js`의 섬 생성 코드와 `main.js` 빈 모듈(앱 검사용)은 남는다.
