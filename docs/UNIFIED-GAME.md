# 하나의 게임으로 통합

> 사용자 확정: 2026-10-18 · 시작 버전: 게임 0.13.0
>
> FERAL은 맵마다 다른 게임이 아니라 **하나의 화면, 하나의 규칙·데이터, 하나의 런타임** 위에서 맵만 바뀌는 게임이다. 이 문서는 그 목표 구조와 단계, 저장 변환 규칙의 기준이다.

## 1. 결정 사항

| 항목 | 결정 |
| --- | --- |
| 통합 기준 | **새 런타임 + 기존 UI.** 월드·규칙·데이터는 무한 월드와 확정 기획 데이터를 가진 콘텐츠 런타임(`content-runtime/`) 하나를 쓴다. 화면·조작·HUD 편집·가방·설정은 기존 UI(`index.html`)를 그대로 쓴다. |
| 기존 맵 | **통합 시스템의 맵으로 이식.** 기본 섬·개척 원정·기계 시험장은 같은 UI·규칙 위의 맵 설정(프리셋)으로 다시 만든다. |
| 기존 저장 | 위치·지형 편집·아이템처럼 대응되는 부분을 변환한다. 대응되지 않는 항목은 목록으로 알린다. 원본 저장은 지우지 않는다. |
| 기존 전용 기능 | 운반·충격 피해·공기역학·구조체·첫 신호 캠페인·농사 등 기존 게임에만 있던 기능은 버리지 않고 런타임으로 옮긴다. |

## 2. 문제였던 구조

0.12.1까지 FERAL에는 진입 화면마다 다른 게임이 붙어 있었다.

| 영역 | 기본 섬·개척 원정 | 콘텐츠 탐험 | 기계 시험장 |
| --- | --- | --- | --- |
| 페이지 | `index.html` + `main.js` | `expedition.html` + `content-runtime/entry.js` | `machine.html` |
| 화면·HUD | 핫바, 36칸 가방, 체력·포만, HUD 편집기, 원정 장부 | 자체 패널·버튼 | 자체 화면 |
| 설정·알림·조작 | 그래픽·감도·시야각·왼손·소리, 알림 1개, 누르고 있기 버튼 | 설정 없음, 자체 알림 큐, 자체 조작 | 자체 |
| 아이템·제작 | `inventory.js` 47종 | 설계 데이터 31재료·142제작법 | 부품 전용 |
| 생명체·월드 | `entities.js` 3종, 고정 크기 섬·지역 전환 | `creatures.js` 34종, 무한 청크 | 고정 격자 |
| 저장 | `feral.world.v1`·슬롯 JSON | 압축 2세대 저장 | `feral.machine.v1` |

공통으로 쓴 것은 캐릭터 이동 계산, 월드 슬롯, 업데이트 메뉴, 버전뿐이었다. 0.11.0의 콘텐츠 통합과 0.12.0의 화면 연결이 기존 UI를 재사용하지 않고 새 화면을 만들면서 분리가 굳어졌다.

## 3. 목표 구조

```
worlds.html            월드 목록 (게임 화면이 아님)
index.html             유일한 게임 화면. 로딩 단계·진행도·실패 안내(모듈이 실패해도 동작하는 일반 스크립트)
 └ game.js             월드를 읽고 맵에 맞는 게임을 시작
    ├ shell.js         모든 맵이 함께 쓰는 화면·조작 (앱의 업데이트 파일 수 상한 128개 때문에 한 모듈)
    │   알림           알림 하나 (즉시 결과는 교체, 세계 사건은 대기열), 장소 발견 배너
    │   조작           스틱·시점·누르고 있기 버튼·키보드
    │   이동 버튼      달리기·웅크리기·기어가기·하강·제동 버튼 상태
    │   설정           그래픽·감도·시야각·소리·왼손·미니맵·사건 알림
    │   메뉴           일시정지 메뉴 탭, 백그라운드 저장, 오류 화면
    │   현장 HUD       체력·포만, 목적지, 지도·상태·상호작용 버튼, 현재 목표
    │   장부 창        탭·닫기·초점·안내 문구
    ├ hud-editor.js    UI 배치 편집기 (모든 맵 공통)
    ├ inventory-ui.js  36칸 가방·핫바·제작 (아이템 카탈로그 어댑터로 표시)
    └ 런타임           content-runtime/ — 맵 프리셋이 지형 생성기·시작 장비·활성 시스템을 정한다
```

- 새 화면 요소는 `shell.js`나 기존 공용 모듈에만 추가한다. 맵 전용 HUD·패널·CSS 파일을 새로 만들지 않는다.
- 같은 기능이 이미 있으면 그 코드를 옮겨 공용화한다. 새로 비슷한 기능을 만들지 않는다.
- 맵별 차이는 프리셋 데이터와 런타임 시스템의 활성 여부로 표현한다.
- `expedition.html`과 `machine.html`은 예전 주소를 위해 `index.html`로 넘기는 호환 페이지로만 남긴다.
- 앱 0.3.3은 게임 업데이트 하나에 파일 128개까지 받는다(`UpdateCore.MAX_FILES`). 0.13.0은 122개다. 새 파일을 늘리는 단계는 같은 버전에서 은퇴할 기존 파일을 함께 정리하거나, 상한을 올린 새 APK와 `minNativeCode` 증가가 필요하다. `tests/unified-game.test.js`가 여유 4개 이상을 확인한다.

## 4. 단계

각 단계는 별도 버전으로 배포한다. 단계가 끝날 때마다 이 표를 갱신한다.

| 단계 | 버전 | 범위 | 상태 |
| --- | --- | --- | --- |
| P1 하나의 화면 | 0.13.0 | `main.js`에서 조작·설정·알림·메뉴·로딩을 `shell.js`로 옮기고, 개척 원정의 현장 HUD와 장부 창을 공용화한다. 콘텐츠 탐험을 `index.html`의 HUD·핫바·36칸 가방·장부 창·메뉴·설정·HUD 편집기로 옮긴다. `expedition.html`은 호환 페이지가 된다. | 진행 중 |
| P2 하나의 규칙·데이터 | 0.14.x | 설계 카탈로그를 유일한 아이템·제작 기준으로 삼고 기존 47종 아이템의 대응표를 만든다. 기존 전용 기능(운반·충격·낙하 피해·공기역학·구조체·농사·샌드박스 도구·캐릭터 표시)을 런타임으로 옮긴다. | 예정 |
| P3 맵 프리셋과 저장 변환 | 0.15.x | 기본 섬(유한 섬)·개척 원정(첫 신호 캠페인 지역)·기계 시험장을 런타임의 맵 프리셋으로 다시 만들고 기존 저장 변환기를 추가한다. 기존 `main.js`·`world.js`·`entities.js`·`render.js`·`machine.html` 런타임을 은퇴시킨다. | 예정 |

### P1 완료 기준

- 모든 월드 유형(기계 시험장 제외)이 `index.html` 한 페이지에서 시작한다. 기계 시험장은 P3에서 옮긴다.
- 콘텐츠 탐험이 기존 HUD 요소(스틱·동작 버튼·핫바·체력·포만·목적지·알림·조준 카드), 일시정지 메뉴(탐험·환경 설정·조작 안내·업데이트), 36칸 가방, 장부 창, UI 배치 편집기를 그대로 쓴다.
- 콘텐츠 탐험 전용 CSS(`content-runtime/expedition.css`)와 전용 패널·알림·조작 코드를 없앤다.
- 섬·개척 원정의 기존 동작과 검사가 유지된다.

## 5. 저장 변환 규칙 (P3)

- 원본 키(`feral.world.v1`, `feral.slot.<id>`, `feral.machine.v1`)는 지우지 않는다. 변환 결과는 콘텐츠 런타임 저장 형식(`<원본 키>.a/.b` 2세대)으로 쓴다.
- 변환은 같은 입력에 같은 결과를 내고, 다시 실행해도 아이템이 늘지 않는다.
- 대응 항목: 플레이어 위치·자세, 지형 편집(설치·채굴한 칸), 인벤토리(대응표로 설계 ID 변환), 장비 착용, 발견 장소, 캠페인 진행.
- 대응되지 않는 항목(예: 대응하는 설계 아이템이 없는 아이템, 기존 종의 개별 개체 상태)은 변환 보고서로 저장하고 게임 안에서 목록으로 보여 준다.
- 변환에 실패하면 원본으로 계속 플레이할 수 있어야 한다.
