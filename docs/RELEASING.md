# FERAL 버전 관리와 배포

현재 저장소는 **공개**이며 게임 **0.15.2 / 1502**, 앱 **0.3.3 / 303**, 최소 앱 **303**이다. 공개 업데이트는 로그인이나 토큰 없이 조회·다운로드한다.

## 설치와 공개 업데이트

앱 **0.3.3**을 사용 중이면 메뉴 → 업데이트 → **지금 확인 → 저장 후 적용**으로 게임 0.15.2를 받는다. 0.15.0 이상에서 올 때는 어느 방법으로 받아도 저장 보관함이 월드를 이어 준다. **0.14.1 이하에서는 버전 목록에서 고르지 말고 "지금 확인 → 저장 후 적용"으로 받는다.** 앱 0.3.3은 버전 목록에서 고른 빌드에 그 빌드 몫의 저장만 주므로(처음이면 빈 저장), 0.14.1 이하에서 목록으로 0.15.0 이상을 고르면 빈 저장으로 시작한다. 이미 그렇게 됐다면 목록에서 이전 버전을 다시 골라 저장을 되찾은 뒤 "지금 확인 → 저장 후 적용"으로 올린다. 0.15.0부터는 저장 보관함이 최신 저장을 되살리므로 어느 방법으로 버전을 바꿔도 월드가 유지된다(`docs/ARCHITECTURE.md` 4장). 0.15.0부터 앱의 첫 화면은 런처이며, 업데이트 화면은 런처의 **업데이트**에도 있다. 0.14.1부터 공격 방식을 손으로 고르지 않고 든 도구·장착한 무기가 타격 모양(점타격·베기·관통·충격)을 정한다. 0.14.0부터 기본 섬이 콘텐츠 탐험과 같은 런타임에서 돌며, 기존 섬 저장은 처음 열 때 원본을 남긴 채 변환된다. 0.15.2부터 게임 세션은 맵 이름이 아니라 월드 설정으로 시작하고, 콘텐츠 탐험 월드도 런처에서 샌드박스를 켤 수 있다. 0.15.1은 성능 구조 변경(바뀐 구역만 다시 만들기·프레임 예산·생물 AI 분산)으로 규칙·저장 형식은 그대로다. 이번 변경은 게임 파일만 수정하여 앱 재설치가 필요 없다.

앱 0.3.2 이하이거나 처음 설치하는 경우 v0.15.2 Release의 `Feral-0.3.3-android.apk`를 설치한다. 기존 앱 위에 설치할 수 있고 앱을 삭제하거나 데이터를 지울 필요가 없다. 이 APK는 게임 0.15.0을 동봉한다. 앱 0.3.3에는 WebAssembly 실행 허용과 실패 버전 재시도가 포함된다.

0.6.0을 다시 실행하려면 상단 **게임 버전 → 0.6.0 [실행 실패 · 재시도] → 다시 검증 후 실행**을 선택한다. 새 게임의 메뉴 → 업데이트 → **실패한 버전 다시 실행**도 같은 선택 창으로 연결된다. 패키지를 다시 받아 서명·해시·앱 호환성을 검증한 뒤 한 번 시작한다. 실패한 버전의 자동 재적용은 계속 차단하며 재실패 시 기존 게임과 저장으로 복구한다. 동봉 버전은 오프라인 재시도할 수 있다.

메뉴 → 업데이트 → **지금 확인** 또는 **게임 버전 선택**을 이용한다. 공개 GitHub의 `updates/stable.feral`, `catalog.json` 및 불변 버전 패키지를 인증 없이 읽는다. 기존 토큰/IV 설정은 새 앱 시작 시 제거하며 토큰을 입력하거나 전송하지 않는다. 연결이 없어도 동봉 게임과 저장된 버전은 실행할 수 있다.

자동 확인이 켜져 있고 특정 게임 버전에 고정하지 않았으면 시작할 때 확인한다(15분 간격 제한). 다운로드 후 서명·해시·파일 목록을 검증하고 다음 실행 때 전체 버전을 적용한다. **저장 후 적용**은 현재 저장 성공 후에만 재시작한다. 앱의 게임 버전별 저장 분리, 최소 앱 버전 검사와 시작 실패 시 복구는 앱에 그대로 있다. 게임 0.15.0부터는 저장 보관함이 버전별 저장 분리로 비거나 오래된 저장을 최신 저장으로 되살린다.

앱과 동봉 게임 버전은 독립적이다. `game-version.json`은 `version.json`에서 생성하며, 동봉 게임 선택·실행 확인·저장 키에 게임 코드 1502를 사용한다. APK 호환성 판단에는 네이티브 코드 303을 사용한다. 게임 0.15.0의 최소 네이티브는 303이다.

## 버전의 기준

| 항목 | 현재 값 | 의미 |
| --- | --- | --- |
| version | 0.15.2 | 게임 표시 버전 |
| versionCode | 1502 | 게임 코드 |
| nativeVersion / nativeCode | 0.3.3 / 303 | APK 버전 |
| minNativeCode | 303 | 이 게임 코드를 실행할 수 있는 최소 APK |
| saveSchema | 2 | 월드 저장 형식. 앱 버전과 별개 |
| channel | stable | 사용자가 받는 배포 채널 |

`version.json`만 수정한 뒤 `node tools/version.mjs`를 실행하면 AndroidManifest, Gradle, package.json과 게임 version.js·game-version.json을 함께 맞춘다. UI는 실제 실행 중인 게임 버전과 Android APK 버전을 각각 표시한다.

다음 게임 패치는 0.15.3 / 1503 등으로 올린다. stable 코드 숫자는 항상 이전 stable 배포보다 커야 한다. 게임 코드만 변경했다면 minNativeCode 303을 유지할 수 있다. 네이티브 Java·권한·검증 키가 바뀌면 nativeCode를 증가한 새 APK를 배포하고 minNativeCode를 새 nativeCode와 같게 올린다. 지원하지 않는 앱에는 APK 설치가 필요하다고 표시한다. APK 자동 무인 설치는 구현하지 않는다.

## 다음 버전 배포 순서

1. 코드 변경 후 `version.json`의 버전과 versionCode 증가. `node tools/version.mjs` 실행.
2. CHANGELOG 맨 위에 해당 버전의 변경 사항 추가. 저장 형식 변경은 읽기 호환·변환과 복구 시험 추가. 구조·규칙이 바뀌면 같은 PR에서 `docs/ARCHITECTURE.md`·`docs/GAME-RULES.md`·`docs/ROADMAP.md`를, 게시 후에는 `docs/STATUS.md`와 아래 릴리스 기록을 고친다. 게임 파일을 바꾸지 않는 문서 전용 변경은 버전을 올리지 않으며, 배포 워크플로는 같은 버전·같은 패키지를 "이미 게시됨"으로 건너뛴다.
3. 검사는 세 단계다(2026-10-18 경량화).
   - 필수 회귀: `npm test`(`tests/*.test.js`, 약 20초). 모든 변경에 돌린다. PR 필수 검사 verify-authoring과 배포 워크플로도 이것만 돌린다.
   - 장기 검사(`tests/long/`, `npm run test:long`): 바꾼 영역만 돌린다. 진행·제작 데이터·`progression.js`·지형·던전은 10티어 경로(약 7분, CI `progression-route.yml`), 에셋 원본·생성기는 에셋 재생성(CI `asset-regeneration.yml`). CI는 해당 경로가 바뀐 PR·main에서만 이 둘을 돌린다.
   - 브라우저 검사: 화면·플레이를 바꾸면 런처·게임 세션 화면 검증, 개척 원정·기계 시험장 옛 엔진을 바꾸면 해당 `tests/*-check.cjs`(12개, S2·S3에서 통합 검증으로 옮기며 없앤다). 0.12.1부터 계속 실패하던 5개와 실행할 수 없던 기록용 2개는 지웠다.
   런처·게임 세션 화면 검증(`tools/verify-ui-reachability.mjs`, 런처·콘텐츠 탐험·섬·개척 원정)은 앱과 같은 MIME·CSP로 응답하는 `tools/android-asset-server.mjs`를 기본으로 쓴다. 일반 개발 서버는 `.mjs` 같은 파일을 JavaScript로 응답해 Android에서만 생기는 로딩 실패를 숨긴다.
4. `bash build-apk.sh`와 `python3 tools/build-update.py`로 로컬 결과 확인.
5. 검증된 변경을 main에 반영. **FERAL versioned release** Actions가 테스트·APK 빌드·서명 패키지 생성을 수행하고 GitHub Release에 결과를 올림.
6. Release 게시가 완료되면 별도 `updates` 브랜치의 `versions/<버전>.feral`과 `stable.feral` 갱신. 앱은 공개 raw.githubusercontent.com 주소에서 stable.feral을 인증 없이 읽음.
7. Release의 APK를 내려받아 실제 기기에서 업데이트 설치·이어하기 확인. 이미 배포한 번호는 재사용하지 않으며 수정 시 새 버전 배포.

워크플로는 main push와 수동 실행을 지원한다. 이미 배포한 동일 버전·동일 패키지는 중복 배포하지 않는다. 동일 번호의 내용 변경이나 낮은 번호는 실패한다. 네이티브 파일의 fingerprint가 달라졌는데 minNativeCode를 올리지 않은 경우도 배포하지 않는다.

배포 자동화는 저장소 범위 GITHUB_TOKEN(contents: write)을 사용한다. 개인 토큰을 GitHub Actions에 보관할 필요가 없다. 공유 시험 keystore는 초기 비공개 프로토타입의 연속 업데이트를 위한 것으로 production 비밀 키가 아니다. 외부 사용자에게 배포하기 전 별도 키·교체 정책을 설계해야 한다.

## 패키지와 시작 실패 복구

`.feral`은 Base64 ZIP과 서명된 메타데이터를 담은 JSON 파일이다. 네이티브 APK에 고정된 RSA 공개 키로 SHA256withRSA 서명을 확인한 뒤 버전, 최소 APK, 채널, ZIP 해시·크기, 각 파일 해시·누락·경로·풀린 크기를 검증한다. 전체 검증이 끝나야 pending 상태가 된다. 부분 다운로드는 활성 버전을 바꾸지 않는다.

다음 시작 시 APK에 고정된 bootstrap 페이지가 기존 HTTPS 출처의 `feral.*` localStorage를 백업하고 버전 포인터를 원자적으로 전환한다. 저장 출처와 키는 0.1/0.2와 동일하다. 전체 게임 파일을 한 버전에서만 읽으며 APK 파일과 혼합하지 않는다.

0.15.0부터는 런처가 화면을 그리고 게임 세션 파일을 실행하지 않고 불러 본 뒤 12 렌더 프레임과 3초가 지나면 성공을 알린다. 세션 파일을 불러오지 못하면 실패를 알린다. 0.14.1까지는 지형 준비 후 최소 12 렌더 프레임과 3초가 지나면 게임이 성공을 알렸다. 성공 전 실행 오류, 포그라운드 90초 시작 시간 초과, 프로세스 종료가 있으면 이전 정상 코드와 시작 전 저장을 복원한다. 백그라운드에서는 감시 시간을 멈추고, 그 상태에서 프로세스가 종료되면 시작 중단으로 기록한다. 복원 중 종료도 다음 실행에 복원을 재시도한다. 실패한 번호는 자동 재적용하지 않는다. 사용자가 재시도를 명시 선택하고 검증에 성공한 패키지에만 한 번의 시작을 허용하며, 정상 시작 확인 후 실패 표시를 해제한다. 성공 판정 후 모든 플레이 버그를 자동 감지하거나 모든 저장 손상을 복구하는 기능은 아니다.

한 개 이전 정상 버전을 유지한다. 활성·이전·준비 버전 외 파일은 시작 성공 후 정리한다. 테스트는 패키지 변조·경로 탈출·다운그레이드·네이티브 호환·시작 중 종료·저장 복구를 포함한다. 휴대폰 Keystore·네트워크·WebView 생명주기의 실기기 검증은 별도 필요하다.

## 릴리스 기록

### 0.15.2 — 세션 입구 정리: 월드 설정으로 시작 (통합 S1)

게임 1502 / 앱·최소 앱 303 / 저장 스키마 2. Java·권한·키·게임 규칙 변경이 없는 게임 전용 릴리스다. 통합 런타임이 맵 이름 대신 월드 설정(지형 생성기 이름과 규칙)으로 시작하고, 세션 코드의 맵 이름 비교를 없앴다(`tests/launcher.test.js`가 확인). 콘텐츠 탐험 월드의 프리셋에 샌드박스 설정(기본 끔)이 더해졌다. 새 저장은 지형 생성기 이름(`terrain`)을 남기고 이전 저장의 `map`도 읽는다. 0.15.1 이하 빌드는 월드 목록의 프리셋으로 지형을 고르므로 새 저장을 그대로 연다. 검증은 [검증 기록](../verification/0.15.2.md).

### 0.15.1 — 성능 구조: 바뀐 곳만 다시 만들기

게임 1501 / 앱·최소 앱 303 / 저장 스키마 2. Java·권한·키·규칙·저장 형식 변경이 없는 게임 전용 릴리스다. 사용자가 신고한 "나무 한 그루를 캐다 플레이할 수 없을 만큼 느려짐"을 구조로 고쳤다(`docs/ARCHITECTURE.md` 7장). 지형 세계가 바뀐 4m 구역을 기록해 지형 충돌체·물 메시가 그 구역만 다시 만들고, 고정 단계는 프레임당 최대 3번, 배경 작업은 남은 시간 안에서만, 생물 AI는 5개 조로 나눠 처리한다. 0.15.0과 같은 측정 도구(`tools/profile-runtime.mjs`)로 비교한 수치는 `verification/0.15.1-perf.json`과 [검증 기록](../verification/0.15.1.md)에 있다. 업데이트 파일은 124개로 앱 상한 128개까지 여유가 4개뿐이라, 다음에 파일을 더하는 버전은 은퇴 파일을 함께 정리해야 한다.

2026-10-18 08:23 UTC [PR #27](https://github.com/Modopi/feral-voxel-sandbox/pull/27) 병합 커밋 `705b1b1`에서 [배포 Actions](https://github.com/Modopi/feral-voxel-sandbox/actions/runs/39111266268)가 성공해 08:24 UTC에 [v0.15.1 Release](https://github.com/Modopi/feral-voxel-sandbox/releases/tag/v0.15.1)와 기존 공식 `updates/catalog.json`, `updates/stable.feral`, 불변 `updates/versions/0.15.1.feral`로 게시됐다. stable과 버전 패키지는 같은 파일(SHA256 `8edc56ed…b5afb6`)이며 로컬 빌드와 바이트 단위로 같고, 내부 아카이브 SHA256 `7346f69b…88fe2`가 카탈로그와 일치한다. 카탈로그는 23개 항목이며 0.15.0(`808e09b9…`)·0.14.1(`25648ce6…`) 항목의 아카이브 SHA256은 그대로다. Release의 APK(`7ea5d09c…cc9e`)는 CI가 다시 빌드한 것이다. Android 실기기 확인은 아직 하지 않았다.

## 0.3.1 — 앱 고정과 V_ 게임 빌드 선택

0.3.1 APK(versionCode/nativeCode 301)를 한 번 업데이트 설치한다. 게임 코드만으로는 네이티브 버전 선택 기능을 추가할 수 없으므로 이 최초 설치가 필요하다. 그다음 게임 테스트에는 APK 재설치가 필요 없다.

- 앱 상단 **게임 버전** 버튼은 네이티브 실행기에 있으며 0.2.5 게임으로 전환해도 계속 사용할 수 있다. 게임 메뉴 → 업데이트에도 선택 버튼이 있다.
- GitHub 읽기 연결 후 버전 목록에서 선택하고 **저장 후 전환**. 게임은 재시작하고 앱 자체는 0.3.1 유지. 최소 앱 버전이 더 높은 항목은 선택할 수 없다.
- 동봉 0.3.1은 오프라인에서도 선택 가능. 다른 버전 목록은 마지막 조회를 캐시하지만 패키지 다운로드에는 연결이 필요할 수 있다.
- 수동 선택한 게임은 고정된다. 자동 확인 토글을 다시 켜면 stable 추종으로 돌아간다. stable 자동 확인은 계속 버전 증가만 허용한다.
- 각 게임 빌드의 저장을 따로 유지한다. 처음 선택한 빌드는 새 월드로 시작하며, 다시 선택하면 마지막 진행을 복원한다. 시작 검증 실패 시 직전 게임과 직전 저장으로 복구한다.

배포는 최신 main에서 `V_0.3.2` 또는 `V_vehicle` 같은 브랜치를 만들어 push한다. `.github/workflows/release.yml`이 서명·검증 후 새 Release와 카탈로그 항목을 추가한다. V_ 브랜치에는 APK 빌드가 없고 stable 포인터는 바뀌지 않는다. SemVer 접두사가 있으면 표시 버전으로 사용하고 그 외에는 version.json의 표시 버전을 유지한다. 불변 빌드 ID는 `1000000 + GITHUB_RUN_NUMBER`, 태그는 `game-<빌드ID>`, 파일은 `updates/builds/<빌드ID>.feral`이다. 같은 브랜치를 반복 push해도 과거 빌드가 남는다. run 재실행은 같은 ID·같은 내용일 때만 허용한다.

`nativeVersion` / `nativeCode`는 APK 기준, `version` / `versionCode`는 게임 기준, `minNativeCode`는 호환성 기준이다. V_ 브랜치에서 Java를 수정해도 네이티브 앱에는 적용되지 않는다. 네이티브 변경은 main에서 새 APK 버전으로 배포한 뒤 해당 버전을 최소 기준으로 삼는다. 이미 발표한 main 버전은 다시 덮어쓰지 않는다.

이전 게임은 서명된 .feral 패키지가 있는 버전부터 선택 가능하다. 단순히 옛 Git 브랜치가 존재하는 것만으로 앱에 나타나지 않는다. 카탈로그의 배포 성공 항목만 표시한다.
