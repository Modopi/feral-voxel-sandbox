# 상세 콘텐츠 구현 추적

상태: **전체 범위 구현 진행 중**. 설계·시각 파일의 완성과 게임에서 작동하는 구현을 구분한다. 이 문서는 기존 0.10.x 게임의 기능 목록을 신규 콘텐츠 통합 완료로 계산하지 않는다.

기준 계약: [RUNTIME-CONTRACT.md](RUNTIME-CONTRACT.md). 정적 설계 감사: [INTEGRATION.md](INTEGRATION.md). 기존 게임 현황: [PROJECT-STATUS.md](../PROJECT-STATUS.md).

## 상태 판정

- **패키징 검증 완료**: 원본을 런타임이 읽을 수 있는 형태로 전달했고 원본 동일성·불변성·재현성을 검사했다. 플레이 동작을 보장하지 않는다.
- **구현 중**: 담당 파일/API를 개발하거나 모델 테스트를 진행한다. 표의 파일명은 담당 경로이며 존재나 완성 자체를 뜻하지 않는다.
- **통합 검증 대기**: 해당 모델의 검사가 끝나더라도 실제 화면·입력·저장·충돌 경로에서 추가 확인해야 한다.
- **미검증**: 근거가 아직 없으며 자동 검사 또는 실측이 필요하다. 출시 완료로 간주하지 않는다.

## 현재 패키지 검증 스냅샷

`version.json`은 0.11.0 / versionCode 1100을 가리키지만 아직 배포되지 않았다. 현재 canonical asset regeneration에는 119개 모델이 포함된다: 환경8, 생물34, 구조물12, 보스8, 장비57. 기존 115개 모델은 유지됐고 재료형 무기 3개와 전기 투사기 1개를 추가했다.

- `npm run build:assets`: 모델119개, 복셀55,511개, GLB 합계31,290,864바이트를 생성했다. [manifest SHA256](../../verification/visual-assets/gltf-validation.json)은 `a4f3de159fd8cbb22449f48770e89f8f4880fdb3b3dee7c5459c6dedabdc7b09`다.

## 전 구간 실제 소비 검증 진행 중

`tests/expedition-progression-path.test.js`는 **무좌표(기존 추상 설비) Progression 모델**에서 빈 인벤토리로 시작해 실제 atlas 채집 노드/원광 셀, 정상 채집 시간과 도구 마모, 연구 샘플, 설비 및 제작 입력을 소비해 네 분야·10티어에 도달하는 검사다. 발견 설계도·보상 지급·외부 에너지 주입은 금지한다. 에너지는 정상 제작한 응집기/성물, 연료/산성액, 수동 입력/발전기와 실제 공동체 기여에서만 얻는다. 저장된 경로는 seed 31415, 연구 38/39, 설비 26/27, 시뮬레이션 524,082초에서 중단됐다. `FERAL_ROUTE_RESUME`은 보존된 checkpoint SHA256·seed·claim/harvest ledger를 확인하고 이어서 기록하도록 고쳤으며, 이번 수정 후 31재료·10장구 및 최종 에너지 수지 경로는 아직 완료/보고되지 않았다. 원본 위상 도달 감사와 일부 개별 레시피에 재료를 지급하는 단위 검사는 이 전 구간 실제 비용 증거를 대체하지 않는다.

실물 설비 모드의 4m 접근 제한과 위치·명시 포트 연결별 `fixtureEnergy` 망은 위 추상 경제 모델과 별개다. 전 구간 비용 검사를 통과하더라도 실물 설비 배치·배선·이동 경로까지 완주했다고 표시하지 않는다. 상단 전력망 행은 이 분리를 따른다.


## 고티어 저장 용량 결함 수정 이력

정상 채집·연구·제작으로 만든 마도공학10/마도학10/성자9 연구 시점에서 성장 저장은2,360,384바이트, 지형 저장은65,809바이트였다. **실제 Chromium localStorage에 `ExpeditionSave`로 두 세대를 쓰자 두 번째 쓰기가 `QuotaExceededError`로 실패했다.** 첫 세대의 envelope는2,640,148문자다. 이 재현은 player/progression/atlas만 포함하고 생명체·기계·보스·기존 월드 저장은 포함하지 않아 실제 전체 상태보다 작다. 정상 첫 세대가 보존되는 오류 처리와, 이후 새 진행을 계속 저장할 수 없는 용량 결함은 구분한다. 저장 담당 수정 및 같은 실제 상태의 재검증 전까지 고티어 영속화를 완료 처리하지 않는다.


같은 실패 스냅샷을 압축 저장 수정 뒤 실제 Chromium에서 다시 검사했다. 두 세대 쓰기·읽기 모두 성공하고 복원 데이터가 원본과 완전히 같았다. 이전 무압축 JSON 봉투 읽기, 압축 세대로 이전 후 재읽기도 같았다. 두 세대 합계는393,922문자로 줄었다. 이 실행 환경에서 동기 쓰기는1,136ms/813ms, 구형 저장 이전은1,091ms였다. **이 상태의 용량 결함은 수정·재검증됐지만 메인 스레드 저장 지연 및 최종 더 큰 상태/실기기 성능은 별도 검사 대상**이다. 수치는 동시 개발 검사가 도는 데스크톱 Chromium이며 모바일 측정이 아니다.


## 이전 통합·패키지 측정 이력 (0.10.x)

최신 전체 HP 기반 사망 규칙을 원본에서 다시 컴파일한 뒤 패키징8개와 통합12개를 독립 실행해 **20개 통과**했다. 통합 검사에는 정상 채굴 시간/셀 소진/재접속, 회전된 기계의 실물 셀 타격, 연료의 열 전달 시 중복 피해 방지도 포함한다. 원본 모델/GLB/manifest 바이트는 바뀌지 않아 기존115개 형식 검사와127개 렌더 해시의 대상은 같다.

이 시점 앱 전체는 **115파일/11,291,017바이트**, ZIP 표본 **2,715,528바이트**다. 네이티브 제한128파일/압축8MiB/해제32MiB 이내이며, 이후 파일 추가 시 재검사한다. 압축 용량보다 남은13개 파일 여유가 먼저 줄어들 수 있다.

## 후속 기능 감사: 모델 범위와 구현 공백

아래는 구조 담당의 독립 읽기검토에서 분리한 후속 작업이며, 모델 테스트가 있다는 이유로 전체 기능을 완료 처리하지 않는다. 각 담당의 구현·검증 결과가 도착하면 갱신한다.

- 신도 가입·신별 퀘스트·독립 시련의 원장: `faith.js`, runtime serialization과 expedition UI 탭이 연결되어 있고, 저장 때 퀘스트/시련 상태와 `Progression.claims` 영수증을 상호검증한다. 실제 의뢰/시련 UI 완주와 현재 소스의 통합 결과는 계속 확인한다.
- 여덟 던전 고유 환경 장치: `DUNGEON-DEVICES.md`의 장치별 비용·연결·위치·상태, 동적 기하와 충돌을 `dungeon-devices.js`/`entry.js`에 연결했다. 현재 threshold/SDK shape 수정의 회귀 검사가 진행 중이다. 장치 시스템이 없다는 의미가 아니며, 실제 화면에서 각 퍼즐을 끝까지 해결하는 경로는 별도 검증한다.
- 보스: 네 개의 T9/T10 명시 변형이 JSON과 generated catalog에 들어갔고 focused 보스/물리45개·애니메이션/시점9개가 통과했다. 실제 화면 난도와 회피는 미검증이다.
- 기계 무장·재질 외형: 재료형 패턴3종과 arc_thrower의 런타임 경로가 있고, 손 무기 작업면은 선택 재료 팔레트로 표시되며 canonical 형상은 유지된다. 무기 제작/장착/전투/회수·저장과 기계 발사 테스트는 현재 소스 기준으로 재검증 중이다. 이는 특정 완제품 차량 형태를 구현했다는 뜻이 아니다.
- `gear_baseline` 전체 세트는 개별 무기 기술 목록의 완성 증거가 아니다. 별도 패턴의 모델·저장 테스트와 실제 전투 연결을 구분한다.
- 건물·고정 설비의 피해에 에너지 종류를 전달하고 재질 반응을 적용하는 경로는 기계·지형의 열 처리와 별도로 검사한다.

유적 설계도 즉시 해금·멱등 보상은 이미 구현·검사된 경로다. 2시간 생태 모델 검사와 전 구간 비용 검사는 실제 브라우저 완주·장거리 여행·실기기 검증과 구분하되, 이를 코드 자체의 부재라고 표시하지 않는다. EU↔J 계수와 피해/방호/축성 배율은 별도 밸런스 제안값이며 기능 존재 여부와 섞지 않는다.


39개 연구를 모두 정상 비용으로 마친 더 큰 checkpoint(원본 저장3,551,814문자)도 실제 Chromium에서 동기2세대와 worker3세대 모두 원본과 완전히 같게 복원됐다. 압축2세대 합계576,666문자이며 worker 스냅샷 준비 요청83.3ms, 별도 스레드 압축/검증3,193ms, 메인 스레드 커밋7.4ms였다. 같은 환경의 동기 쓰기는4,098ms/1,785ms였다. 이는 CPU를 공유하는 개발 환경 측정이며 최종 모든 장비 제작 후 상태 및 모바일 성능은 추가 측정한다.
