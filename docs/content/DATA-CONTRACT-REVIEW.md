# 상세 콘텐츠 데이터 계약 독립 검토

상태: **최종 1차 명세 독립 검토 완료**. 기준은 [공통 계약](README.md)과 [통합 설계](../CONTENT-PROGRESSION.md) 및 실제 기존 코드다. 이 문서는 구현 완료·밸런스 확정·저장 자동 이전을 보증하지 않는다. 검토자는 다른 담당의 문서나 데이터를 수정하지 않는다.

## 1. 검토 기준과 소유권

문서는 개념 → 분류 → 구성과 관계 → 동작 규칙 → 항목 데이터 순으로 읽을 수 있어야 한다. 모든 수치 데이터의 변수 사전은 현재 코드 근거, 신규 경로, 유지/신규/변경/폐기 후보, 타입·단위, 유효 범위, 밸런스 목표 범위, 기본/오버라이드, 결정 근거, 검증·이전 계획을 설명해야 한다. 개념이 다르면 이름이 비슷해도 같은 변수로 간주하지 않는다.

| 기준 데이터 | 단일 소유자 | 참조하는 데이터 |
|---|---|---|
| 블록·외부 환경·스폰 예산 | 환경 담당 | 건축물 팔레트, 생명체 서식지 |
| 일반 종·생태·신체·종별 스탯 | 생명체 담당 | 외부·실내 스폰과 보스 소환 |
| 건축물·던전·방·공간 연결 | 건축물 담당 | 환경 후보, 보스 경기장 |
| 보스·페이즈·스킬·부위 파괴 | 보스 담당 | 던전 보스 참조 |
| 아이템·연구·가공·드롭 풀·전투 비교 기준 | 성장 담당 | 블록 자원, 생명체 드롭, 건축물 보상 |

외부 참조가 아직 없으면 미해결 참조로 남긴다. 임의 문자열을 생성해 연결 완료로 취급하지 않는다. 동일 이름 데이터의 두 군데 정의는 값이 현재 같더라도 소유권과 동기화 규칙이 없으면 중복 정의다.

## 2. 실제 코드에서 확인한 기존 의미

|---|---|---|

| 생물 에너지 | `entities.js`: 초기 `energy=60+random()*40`, 먹기 상한 150, 번식 소비 50, 소모와 기아사망 | kcal로 정의된 값이 아님. 신규 칼로리와 직접 등치·무손실 이전 주장 금지 |

| 기존 드롭 | `animalDrops(type)`: meat/essence/bio/crystal 수량 | 신규 아이템 ID로 매핑하는 별도 작업. 원재료·완성 재료·생체 자원 의미를 이름만으로 합치지 않음 |

| 신규 지식 초안 | `content/catalog.js`: MATERIALS/RESEARCH/COMPONENTS, 자체 work와 선행 ID | 런타임 인벤토리에 통합되지 않음. 기존 Inventory unlocks와 다른 식별자 공간 |
| 기존 지역·건축물 | `frontier/terrain.js`: 유한 World에서 지역 전환; villages/dungeon/boss 좌표에 직접 블록 배치 | 절대 청크 좌표·방 그래프·폐쇄 생태·거리 난도는 신규. 기존 지형을 자동 재생성하지 않음 |

## 3. 데이터가 도착하면 실행할 교차 검증

1. 각 JSON의 `schemaVersion=1`, `status=proposed`, 배열 `entries`, 비어 있지 않은 고유 id/name을 검사한다. JSON 숫자는 유한해야 하며 개수·티어·인덱스는 정수 조건을 만족해야 한다.
2. 모든 수치 leaf 경로를 열거하고 변수 사전에 대응되는 행·단위·기본값 또는 항목별 표가 있는지 검사한다. `[min,max]`만 있으면 분포·샘플 시점·시드·저장 정책이 필요하다.
3. 종, 블록, 아이템, 드롭 풀, 연구, 보스, 건축물, 방 ID의 실제 존재와 소유자를 검사한다. 같은 이름이 있는 것만으로 의미 호환을 인정하지 않는다.
4. 본문 표의 HP·속도·회복·피해·시간·규모·범위와 JSON 값을 비교한다. 한쪽만 바꾸는 상태를 통과시키지 않는다.
5. 방 AABB가 던전 크기 안에 들어가고 문·통로가 연결되는지 검사한다. 방 스폰 상한 합과 던전 활성 상한 관계, 보스 소환이 어느 예산을 사용하는지 명시한다.
6. 외부 생물과 내부 폐쇄 생태의 생산층·먹이·회복·번식 조건을 검사한다. 종 ID와 생성 수만 있는 표를 폐쇄 생태 구현 명세로 간주하지 않는다.
7. 보스 부위가 영구 파괴되면 해당 부위 스킬이 모든 후속 페이즈에서 비활성화되는지, 대체 스킬이 남는지 검사한다. HP 페이즈 전환이 부위를 복구하거나 무한 회복시키지 않아야 한다.
8. 보스 기본 공격 피해와 에너지 원천·비용·공격별 총 타격 수·피격 간격·동시 위험 상한을 연결한다. 순간 피해와 초당 피해를 혼동하지 않는다.
9. 자체 연구만으로 모든 기술에 도달하는 것 외에 모든 완성품을 실제 제작할 원재료·설비·에너지도 비독점 경로로 확보 가능한지 검사한다. 최초 성물과 첫 신성의 순환을 별도로 검사한다.
10. 거리 난도는 초기 보호권과 원거리 평균, 고난도 파편 점유율, 우회 경로를 함께 검사한다. 6m 통로는 특정 시제품 기계의 진입 기준일 뿐, 임의 크기 이동 요새까지 입장 가능하다는 주장이 되어서는 안 된다.
11. 사망 보관의 비소멸·10m 회수, 가방 포화·여러 사망·재접속·청크 해제 시 보존·중복 수령 방지 계약을 검사한다. 새 결정 없이 배치 기계의 파괴 복구까지 확대하지 않는다.
12. 무기생명에 칼로리·자연회복이 없고, 문명 속성은 생명 개체에만 있으며 공동체 데이터가 별도인지 검사한다. 제작 구조물에 entityType organic/inorganic을 쓰지 않는다.

## 4. 교차 검토 이력과 최종 1차 결과

모든 데이터는 작성 중 수정될 수 있다. 아래는 발견 시 근거와 담당별 수정 요청을 기록한 것이며 미수정 런타임 버그 목록이 아니다. 실제 게임 실행은 변경하지 않았다.

| 검토 항목 | 확인 결과 | 조치·판정 |
|---|---|---|
| 기존 의미 차이 | 2절의 코드 근거 확인 | 13개 주의사항이며 신규 버그 13건이라는 뜻이 아님 |
| 일반종 재생 산식 | 최초 식에서 CP가 최소 보유량보다 작으면 min 결과가 음수일 수 있음 | 생명체 담당에게 max(0,…) 또는 사전 조건 명시 요청 |
| 비활성 생태 시간 | 환경은 60s×120단계 후 집계 갱신, 생명체는 3600s 후 정지 | 두 정책이 동시에 존재할 수 없어 한 소유자 기준으로 통일 요청 |
| 그룹 기본/오버라이드 | 사슴의 종 그룹1~3과 환경2~4, overlay cap2와 그룹최대4 | 외부 그룹은 환경 우선인지, cap 초과 시 전체기각/부분배정인지 요청 |
| 야외/제작 채집 정의 | 환경 2s·열매3/약초2, 성장 4s·열매2/약초1; 유체 용기와 수피컵 조건도 차이 | 환경은 위치·분포·재생, 성장은 수율·시간·도구를 소유하는 연결 요청 |
| 폐쇄 생태 생산 단위 | foodUnits와 CP 연결이 초기에는 미정. 1unit=100CP라면 저택 생산900CP/h 대 일반종 기초소모2923CP/h | 단위 확정 후 생산·초기재고·수용력 재산정 요청. 포식 관계와 번식·회복·보스는 별도 검증 |
| 외부 입구 접근 | 환경 초기4m vs 기계 시제품 내부5m/통로6m | 외부 접근도 구조 최종 규격을 참조하도록 요청 |
| 보스 부위 파괴 | 8종 disabledSkillIds가 모두 실제 기술이며 모든 페이즈에 남는 기술 존재 | 데이터 참조 검사 통과. 현재 소환0으로 별도 일반종 예약 충돌 없음 |
| 보스 회피 시간 | 32기술의 walkRequiredS가 0.3+worstSafeDistanceM/3.2와 0.0001s 이내 일치 | 산술 검사 통과. 실제 벽·높이·경로 회피 가능성까지 통과한 것은 아님 |
| 다중 부위 피격 | 모든 기술 maxHitsPerTargetPerCast=1, 기계 여러 부품 총 피해도 시전 상한 계약 | 계약 확인. 충돌 어댑터 런타임 검증 필요 |

공통 양식이 존재하는 것과 모든 변수의 문서/JSON 값이 일치하는 것은 별도다. 최종 통합 결과와 구현 범위는 [INTEGRATION](INTEGRATION.md)에 기록한다. 수정 중 파일의 순간적 불일치를 영구 미해결로 오인하지 않도록 아래 최종 확인 상태를 따로 갱신한다.

### 최종 1차 명세 확인 상태

작성 중 데이터의 수정본을 다시 읽고 다음을 독립 확인했다.

- 회복 산식에 `max(0, min(...))`가 추가되어 음수 회복 가능성을 제거했다.
- 생명체의 오프라인 시각 정책은 환경 `world.population`을 참조한다. 같은 개체를 실내·외에서 중복 진행하지 않는 규칙도 명시됐다.
- 환경 채집 노드는 `sourceId`로 성장 데이터를 참조하고, 충돌하던 수율·시간·도구 필드를 제거했다.
- 8개 던전의 일반종 초기 기초 대사량을 직접 합산했다. 생산량은 명시된 1BU=100CP 기준 기초 대사의 2.00~2.02배다. 종별 방 최대 개체수 합이 종의 던전 상한을 넘는 사례는 없다. 이것은 포식·번식·회복까지 포함한 동적 생태 안정성 증명은 아니다.
- 통합 도구 `node tools/audit-content-design.mjs`를 검토자가 별도로 실행해 `valid=true`, errors 0을 재현했다. 검사 시점 데이터는 블록33, 환경8, 일반종34, 건축물12, 보스8, 성장369개다. 발견 보상을 제외한 도달성은 아이템150, 연구39, 에너지6이다. 새 항목 추가 시 수는 달라질 수 있다.
- 구조물의 외부 우회로 예약폭이 데이터 검사에 반영되었다. 실제 복셀 충돌·경로·차량 회전은 후속 런타임 검사다.

- 환경 블록의 `world_form`, `processing_family`와 `processed_form` 역할이 명시되었다. 분리·운반·직접 조립은 기존 물성을 보존하고, 명시적 가공에서만 성장 재료 물성으로 전환한다. 가공 판재와 잡철 블록은 대응 재료의 밀도·HP·내열·내산과 일치하도록 정리되었다.
- 생명체 문서에서도 개념·분류·구성·동작·항목 표 및 변수 사전을 확인했다. 일반종 `type`의 기존 의미, CP의 독립 단위, 자연회복 산식, 야외/실내 그룹 소유권, 부위 손상 보존과 사망물품 제외 규칙이 기록돼 있다.

독립 검토에서 발견한 음수 회복·오프라인 정책·채집 수치 중복·출입 폭·생태 생산 단위·블록 물성 소유권은 수정본에서 해소됐다. 전체 동적 생태 안정성, 난도 생성 시뮬레이션, 충돌·항법·저장 이전은 아직 수행하지 않았다. 통합 도구 통과를 게임 실행·브라우저·저장 호환·밸런스 검증 완료로 확대하지 않는다. 문서 모든 문장의 수치를 전수 파싱해 일치시킨 것이 아니라 공통 변수표 존재, 교차 소유권, 핵심 계산과 참조를 검토한 결과다.

## 5. 구현 전 통과 조건

- 외부 참조 누락·중복 의미·본문/JSON 수치 불일치가 0건이거나, 명시적으로 후속 범위로 분리되고 첫 구현에 사용되지 않음.
- 숫자마다 단위, 범위, 기본/오버라이드, 근거가 추적됨.
- 생성·생태·보스·연구에 구체적 반례 검증이 정의됨.
- 모든 확정 원칙은 데이터에 반영되고, 새 밸런스 값은 제안임이 유지됨.
- 데이터 검증 통과와 런타임·브라우저·저장·밸런스 테스트 통과를 별도로 기록함.


## 6. 마감 추가 변경 재검토

마지막 보스 변경은 세 가지 공통 페이즈 이름만 바꾸는 수준에서 벗어나 24개 `phase.state`로 이동·약점 노출·수위·비행·방패·궤도·기믹을 명시한다. HP 경계도 보스별로 구분돼 있다. 24개 상태와 그 스케줄을 독립 대조하다 공생체 1단계의 약점 노출 사건이 실행되지 않는 불일치를 발견했고, 해당 기술을 스케줄에 추가한 수정본을 재확인했다. 코어 파괴 후에는 외피 뒤 몸체가 상시 노출되며, 다시 파괴 기절을 얻지 않는 규칙도 추가됐다.

- 24페이즈에서 `after_skill` 노출 사건의 기술이 실제 해당 스케줄에 존재하고, 코어 파괴로 금지된 기술을 제외해도 사용 가능한 공격이 남는다.
- 96개 페이즈×기술 조합에서 보행 회피 시간 산식을 재계산했다. 산성충 2단계의 속도0.85배까지 적용해도 정지 조준·빈 평지 가정의 보행 여유시간이 음수가 되는 조합은 없다. 실제 장애물·애니메이션·몸체가 있는 공간의 플레이 검증은 아니다.
- 보스 외피의 흡수 EU를 먼저 차감하고 남은 에너지만 몸체 HP와 부위 누적파손에 기록하는 계약을 확인했다. 비교 유효 DPS가 기준 외피를 이미 포함한다는 전제를 명시해 저항을 이중 적용하지 않는다. 구체적 외피·충돌 어댑터는 아직 런타임 구현 전이다.
- 성장 `energy_units`가 공통 EU/EU/s를 소유하며 보스와 일반종이 이를 참조한다. 채널별 계정은 분리되고 현실 J 대응은 없다. 정의된 변환 외의 채널 교환과 입력 차감 전 출력 지급을 금지한다.
- 확대된 통합 감사 도구는 질량 예산, 생태 기초 CP, 방 연결·예약, 발견 제외 아이템·연구·에너지 도달성을 포함하며 마지막 재실행도 오류0이다.

**최종 판정:** 상세 콘텐츠의 첫 데이터 명세와 분야 간 계약 검토를 마쳤다. 데이터 숫자는 여전히 밸런스 제안이다. 무한 월드·완전한 폐쇄 생태·모든 티어 변형·저장 이전·전투 런타임을 구현 완료했다고 판정하지 않는다. 실제 개발에는 INTEGRATION의 순서와 미검증 게이트를 적용한다.
