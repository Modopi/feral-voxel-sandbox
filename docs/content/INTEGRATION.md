# 상세 콘텐츠 통합 검증

상태: **1차 상세 명세·정적 교차 검증 완료**. 모든 신규 수치는 밸런스 제안이다. 실제 플레이·지형 생성·성능 검증과 구분한다.

## 작업의 경계

사용자 요청으로 런타임 기능 확장보다 상세 명세를 먼저 작성한다. 담당별 개념·분류·변수 사전·실제 JSON을 작성하고, 분야를 연결한 후 개발한다.

- `design/content/`의 값은 제안 데이터이며 게임에 아직 연결하지 않았다.
- `design/content/catalog.js`는 사용자 확정 분류·재료와 초기 연구/컴포넌트 제안을 담은 미통합 공통 계약 초안이다. 재료 ID·이름·티어·계열의 회귀 검사에 사용한다. 실제 값·가공·연구 경로는 `design/content/progression.json`이 소유하며, 현재 게임 저장이나 아이템을 이전하지 않는다. 초기의 별도 지식 감사 함수는 범위가 더 넓은 통합 감사 도구로 대체했다.
- 현재의 순수 모델 테스트 통과나 설계 데이터 감사는 모바일 성능·플레이 밸런스·보스 조작 검증을 대신하지 않는다.
- 게임 버전·네이티브 버전·저장 스키마·배포 상태는 이번 문서 작업으로 변경하지 않는다.

## 검증 기록

### 산출 범위

| 소유 분야 | 실제 데이터 | 위키 |
|---|---|---|
| 환경 | 8환경, 33블록, 외부 스폰·광맥·채집 노드·난도·우회 계약 | ENVIRONMENTS.md |
| 생명체 | 일반종·문명 역할 원형 34개, 신체 프로필·먹이·회복·드롭 | CREATURES.md |
| 건축물 | 던전8·기타시설4, 총84방과 연결·생태·퍼즐·보상 | STRUCTURES.md |
| 보스 | 8보스, 24페이즈, 고유기술32개와 기믹·상태·원장 | BOSSES.md |
| 성장 | 369항목: 재료31·연구39·제작법142·설비27·컴포넌트13·장비기준10·원천16·보상풀8 등 | PROGRESSION.md |

모든 분야 문서는 개념·분류·구성관계·동작규칙을 설명하고, 변수 사전에 **현재 코드 위치·변수 / 새 JSON 경로 / 상태 / 타입·단위 / 유효·밸런스 범위 / 기본·개별값 / 근거 / 검증·이전**을 구분한다. 실제 JSON은 표의 식별자와 수치를 담는다. 기존 변수와 의미가 다르면 명확히 신규 또는 변경으로 표시한다.

### 재현 가능한 자동 검사

`npm run audit:design` 또는 `node tools/audit-content-design.mjs`로 실행한다. 결과: [audit.json](../../verification/content-design/audit.json).

- 문서 상태·식별자, 확정 재료31종의 ID·이름·티어·계열 보존.
- 환경의 블록·생명체·던전·채집 원천, 생명체의 먹이·보상·내부 생산원 참조.
- 블록 질량=밀도×부피. 수치형 가공 질량예산의 입력=제품+가공잔재. 조립물은 입력 질량 보존 계약을 검사하며 실제 조립체 질량 시뮬레이션은 별도.
- 건축물 방 범위·출입구·통로 끝점·연결성·외부 우회로의 부지 예약·스폰 상한·보상 위치.
- 던전 초기 일반종 기본 칼로리 소비와 생산량·용수량의 산술 일치. 포식 관계의 장기 안정성까지 증명하는 검사는 아니다.
- 보스 전장·장비 기준·목표 처치시간, 페이즈 구간·스킬 참조·약점 노출 이벤트 도달성, 습지 감속을 포함한 예고시간의 산술 조건.
- 발견/보스 보상을 제외하고 원료 도구·연구 샘플·설비·에너지를 포함한 고정점 도달성: **아이템150·연구39·에너지6, 막힌 제작법0**. 수량을 실제로 소비한 플레이나 소요시간 측정은 아니다.

`tests/content-design.test.js`는 유효 데이터뿐 아니라 첫 성물의 순환 의존, 존재하지 않는 드롭, 방 밖으로 끝나는 통로, 부족한 회피 예고, 실행되지 않는 약점 노출 기술을 의도적으로 넣어 오류 검출을 확인한다. 전체 Node 검사 기록: [node-tests.txt](../../verification/content-design/node-tests.txt).

### 독립 검토로 수정한 사항

[독립 검토 기록](DATA-CONTRACT-REVIEW.md)에 근거를 남겼다.

- 회복 예산이 음수가 되면 HP가 감소할 수 있던 식을 하한0으로 보정.
- 환경과 종의 오프라인 진행, 채집 수량·시간·도구, 에너지 단위의 소유권 통일.
- 중첩 환경의 집단 크기와 개체 상한, 외부 접근폭과 내부 기계 통로의 충돌 수정.
- 던전의 생산량이 초기 개체의 기본 소비보다 적던 초안 수정 및 식량 단위 통일.
- 외부 우회로 폭이 부지 예약 밖으로 나가던 문제 수정.
- 원형 블록과 가공재의 물성 소유권을 분리하여, 분리·직접 조립만으로 물성이나 질량이 바뀌지 않도록 명시.
- 수목원 보스 첫 페이즈의 약점 노출 이벤트를 실제 사용 기술과 연결.
- 보스마다 공격 순서 외에도 수위·고도·차폐·노출·이동 방식 등이 달라지도록 페이즈 상태를 구체화.

## 구현 준비 상태와 다음 작업

설계 데이터와 교차 계약은 첫 구현의 입력으로 사용할 수 있다. 실제 완성도 판단은 아래 구현 검증 이후다.

1. 새 저장/콘텐츠 어댑터를 만들고 기존 월드·종 번호·아이템·해금 값의 이전 경계를 구현한다.
2. 숲·구릉 대표 구간에서 실제 복셀 건물 생성·길찾기·파괴·기계 통과를 검증한다. 현재 건축 템플릿은 단층이며 다층 변형 완료를 뜻하지 않는다.
3. 내부·외부 생태를 시간 진행시키며 포식·번식·초기 재고 소진·재방문을 검증한다. 최소2시간 동적 시뮬레이션을 다음 게이트로 둔다.
4. 원료부터 연구·가공·개인장비/기계까지 실제 재료·에너지를 소비하며 플레이 경로를 완주한다.
5. 개인·기계 공략의 실제 보스 예고·차폐·부위·페이즈·DPS를 검증하고 수치를 조정한다.
6. 사망 보관과 10m 요정 회수, 여러 사망·가방 포화·지역 이탈·저장 중단을 검사한다.

무한 지형 표본 생성, 모바일 성능, 실제 항법·충돌, 시간 기반 생태 평형, 저장 이전은 아직 수행하지 않았다. 모든 문서 숫자의 전수 자동 파싱도 하지 않았으며 데이터·본문 대조는 담당별 작성 검토와 독립 표본 검토를 병행했다. 고티어 보스의 추가 변형, 비행/무장 컴포넌트의 최종 기능 계약, 에너지 전달→재질 반응의 실제 함수는 후속 구현·설계 항목이다. 이 항목을 미해결인 채로 완료 배포라고 표시하지 않는다.


## 후속 시각 에셋 원형

[시각 에셋 저장·재사용 안내](VISUAL-ASSETS.md)에 환경8·종34·보스8·건물12의 복셀 원본/GLB와 직접 렌더74장을 연결했다. 동일 콘텐츠 ID로 수치 설계와 연결되며, 개별 위키에 이미지와 원본 다운로드 경로가 있다. 실제 런타임에 통합하지 않은 미술 원형이다.

전체178테스트,62GLB 공식 형식 검사,Blender 실제 가져오기,브라우저 도감 확인을 통과했다. 기존 검사에 시각 계약·제작 SDK·형상 연산·실제 충돌 회귀검사를 추가했다. 해당 결과는 시각 파일의 재사용 가능성과 데이터 정합성을 확인하며, AI·애니메이션·충돌·파괴·모바일 성능 검증은 별도다.
