# 던전 퍼즐 장치의 상태와 범위

원본 `design/content/structures.json`의 8개 퍼즐 해결법·필요 부품·보상 분리는 유지한다. 예전의 공통 비용과 시간만으로 문을 여는 처리는 장치별 위치, 저장량, 연결, 동작 상태를 사용하는 퍼즐 상태로 대체했다. 아래 수치와 단위 환산은 퍼즐 실행을 위한 게임 내 보정값이다. 일반적인 역학·유체·열 시뮬레이터를 뜻하지 않는다.

각 퍼즐 상태는 던전 인스턴스의 `deviceState`로 저장된다. 장치 초기 유체·열·운동은 인스턴스 생성 때 한 번 생성되며, 재접속·수리·부품 교체가 이를 되돌리지 않는다. 기존 생태 저수조는 원본 정의의 48,000L 상태로 보존하고 소형 퍼즐 액체 회로와 별도로 샘플링한다.

## 구현된 퍼즐 동작

| 원형 | 상태 변화와 조작 | 해결 기준·수치 | 구현 범위 |
|---|---|---|---|
| 뿌리 저택 | 설치된 접합부로 운반문을 들어 올린다. | 기계 입력 10EU/s, 0.1m/EU; 4.5m 이동에 최대 45EU가 든다. | 문의 실제 상자 위치가 이동한다. 접합부가 없어지면 문은 3m/s로 내려간다. 문 질량·목재 하중은 풀지 않는다. |
| 채광 요새 | 낙석을 통로 옆으로 민 뒤 운반교 지지를 수리한다. | 이동량 0.03m/EU, 최대 3m(100EU); 지지 수리는 나무 2개와 돌 2개를 소비한다. | 낙석의 실제 상자 위치가 바뀌고 수리된 지지가 보인다. 마찰 일·교량 하중을 계산하지 않는다. |
| 침수 시설 | 펌프로 산성 액체를 통행 수조에서 수신량으로 옮긴다. | 초기 400L, 단면적 4m², 펌프 10L/s·10EU/s; 깊이 0.05m 이하(200L 이하)에서 해결한다. | 수조와 수신량·유출량을 분리해 총량을 보존한다. 산성 위험은 수조의 실제 4m² 영역에만 샘플링한다. |
| 지열 주조소 | 유한 열원 밸브를 닫고 펌프로 냉각수를 순환한다. | 열 경로 600EU와 열원 400EU로 시작한다. 열용량 표기는 10EU/°C, 냉각수 20L, 60EU/L 이동량, 순환 1L/s·10EU/s다. | 경로·열원·냉각수·손실의 EU 합계를 보존한다. 해결 기준은 경로 200EU 이하(계산상 40°C)이며, 위험 표본 한계는 45°C로 둬 안전 여유를 유지한다. 일반 열전달·주변 온도 계산은 없다. |
| 절벽 관측소 | 관절·제어기로 풍향판을 목표 각도로 돌려 고정한다. | 목표 π/2 rad에서 계산 풍력이 3N으로 줄어들며, 해결 한계는 5N이다. | 회전판은 한 SDK 부위의 겹치지 않는 복셀 상자로 다시 표현한다. 바람은 지정 통로 표본에 일정 힘과 속도 벡터로 제공되며 기상장을 계산하지 않는다. |
| 봉인 수목원 | 마나 회로 경로를 수신조로 바꾸고 수관 액체를 펌프 이송한다. | 초기 60L, 회로 단면적 0.24m², 펌프 10L/s·10EU/s; 6L 이하에서 해결한다. | 액체·수신량과 생태 저수조 48,000L를 분리한다. 파손 시 유한 액체를 유출량으로 옮긴다. 수관 회로 단면에서만 깊이와 압력 위험을 표본화한다. |
| 잊힌 수도원 | 전달축의 기계 입력으로 제단을 정렬한 뒤 별도 신성 에너지를 소비한다. | 정렬 π/2 rad, 10EU/s; 신성 에너지 10EU를 1EU/s로 소비한다. | 기계 에너지와 신성 에너지 잔액은 별도 경로다. 전달축을 신성 에너지 전달에 쓰지 않는다. 신앙 보상 원장과 퍼즐 상태는 분리한다. |
| 관성 탑 | 초기 속도로 움직이는 운반대를 에너지 소비로 제동하고 목표 위치에서 잠근다. | 초기 위치 2.75m·속도 1m/s, 질량 보정값 500kg, 감속 0.4m/s², 제어 1EU/s, 목표 4m ±0.5m, 정지 기준 0.1m/s 이하. 운동에너지는 100J/EU로 환산하고 회수량은 600EU 한도다. | 위치·속도를 시간 적분한다. 제동 전력이 없으면 현재 속도로 계속 움직인다. 지지 파손은 잠금을 풀지만 속도나 운동에너지를 임의로 지우지 않는다. |

이 장치들은 입력·저장·소비를 추적하는 제한된 상태 모델이다. `metrics`, 유체·열 보존 값과 이동 상태는 회귀 검사에 쓰인다. 미기재 질량·힘·온도 등은 일반 물리량으로 추정하지 않는다.

## 런타임 API와 보급

`DungeonSystem.devices`는 다음 계약을 제공한다.

- `status(id, {progression})`는 요약, 상태, 조작 목록과 공급 목록을 돌려준다. 조작 항목은 `{id,label,items,hold,disabled?,detail?}`이며, 공급 항목은 연결 소유자·에너지 종류·배선 길이·유효성·저장 EU·장치 EU를 포함한다.
- `act(id, actionId, {position, progression, claimId, angleRad, targetM, ...})`는 조작 거리, 부품, 재료, 청구 멱등성을 검사한다. 설치·교체·수리 비용은 성공한 조작에서만 소비한다.
- `connectSupply`와 `disconnectSupply`는 실제 FixtureEnergy 소유자 ID와 에너지 종류를 사용한다. 연결은 출력 포트와 저장 포트가 모두 있는 활성 설비, 접근 권한, 던전에서 8m 이내 거리와 해당 배선 재료를 요구한다. `charge`는 연결된 설비의 유한 잔액만 장치 예약량으로 옮기며 개인 잔액과 합산하지 않는다.
- `update(dt, {progression, manualInstanceId, position})`는 장치 상태를 시간에 따라 갱신한다. 누르는 조작의 수동 기계 입력은 활성 장치에서 10EU/s 한도이며, 플레이어 위치가 퍼즐 부품의 조작 범위(4m) 안이어야 한다. 펌프·제동기 등은 저장 EU도 실제 소비한다.
- `geometry(id)`는 실제 표시·충돌 상자를 반환한다. SDK 제작 primitive를 장치 pose와 크기로 변환하며, 회전판도 SDK `fill`로 단일 부위 안의 중복 점유를 제거한다. 동적 부위와 유체는 `DungeonSystem.renderBoxes` 및 `solidAt`과 공유한다. 유체 상자는 비고체다.
- `sampleAt(position)`는 표본이 있는 경우 `depthM`, `heatC`, `acidDps`, `windVelocity:{x,y,z}`, `platformVelocity:{x,y,z}`, `hazards`, `safe`를 포함한다. 침수 수조·수목원 액체·주조소 열 표본은 표시 영역에 대응하며, 관성 탑 속도는 운반대 상부와 발 위치가 가까울 때만 적용한다.
- `damage(instanceId, partId, amount)`는 장치 부품의 HP를 줄인다. 파괴된 부품은 이후 형상에서 제외되고 저장에도 남는다. 파괴 자체는 퍼즐 해결이나 보상을 지급하지 않는다.

장치 초기 상태와 청구 기록은 `instance.deviceState`에 저장한다. 기존에 해결된 퍼즐은 해결 상태로 보존한다. 이전 저장의 이미 지불된 진행 중 퍼즐은 남은 장치 진행으로 이전해 비용을 다시 청구하지 않는다. 기존 보상 키·보스 원장·아카이브와 고철 채널은 그대로 유지한다.

## 검증 범위

`tests/content-dungeon-devices.test.js`는 저장 재개, 고유 장치 동작, 공급 설비의 유한 잔액, 수량 보존, 위험 표본, 부품 파손과 60Hz 임계값을 검사한다. `tests/expedition-physics.test.js`는 렌더·정적 충돌 형상 갱신과 물리 연결을 추가로 검사한다. 이 검사는 범용 유체·열역학 시뮬레이션이나 장시간 실제 기기 성능 검증으로 해석하지 않는다.
