# FERAL 상세 콘텐츠 위키 — 개발 전 설계 초안

이 위키는 [통합 설계](../CONTENT-PROGRESSION.md)의 후속 상세 명세다. 사용자 요청에 따라 환경·생명체·건축물·보스·성장을 담당별로 설계하고 교차 검증한다. 확정 원칙 외 모든 명칭·수치·패턴·배치·비용은 **실행 전 밸런스 제안**이며 구현·플레이 검증 완료를 뜻하지 않는다.

[복셀 형상·소유권·충돌 공통 규칙](../VOXEL-ASSET-RULES.md) — 신규 에셋과 향후 런타임 통합 시 적용.

## 공통 계약

- 길이 m, 시간 s, 속도 m/s, 각도 degree, 피해 HP. 복셀의 기본 구조 셀은 기존 구현과 같은 0.5m를 기준으로 제안한다. 세부 생물 모델의 표현 해상도와 혼동하지 않는다.
- 비교용 기본 플레이어는 HP 100, 보행 3.2m/s, 달리기 4.8m/s. 후반 체력·방어·장비 DPS는 성장 담당 명세에서 제안한다. 전체 테스트에는 장비 단계별 기준을 사용한다.
- 타격 피해는 최종 기본 피해량으로 표기하되, 실제 구현은 에너지 투입·전달·대상 반응을 거친다. 임의 HP 피해표를 에너지 체계 완료로 표현하지 않는다.
- 일반 종의 원형은 생명체 담당, 보스 스탯·스킬은 보스 담당, 건물 배치·방 그래프는 건축물 담당, 외부 지형·블록·스폰 예산은 환경 담당, 아이템·가공·연구·보상 풀은 성장 담당이 소유한다.
- 엔티티 유형은 object/machine/organic/inorganic. 플레이어 제작 구조물은 무조건 machine. 생명 제작은 후속. 문명 속성은 생명 개체에만 두고 공동체 데이터와 분리한다.
- 에너지는 mechanical/electrical/thermal/chemical/magic/divine. 신규 재료 ID는 design/content/catalog.js의 MATERIALS 사용. 이 파일은 미통합 초안이며 기존 inventory와 자동 대응하지 않는다.
- 모든 연구·완성품에 자체 연구·제작 경로가 있어야 한다. 던전 발견을 강제 재료로 쓰지 않는다. 최초 신성은 퀘스트·기여·보스·시련에서 확보할 수 있다.
- 초기 스폰 중심의 거리 난도, 평균 5~6티어, 국소 고난도 지역 우회, 사망 아이템 비소멸/10m 요정 회수를 지킨다.
- JSON은 design/content/에 둔다. 게임 런타임에 아직 연결하지 않는다. 파일별 루트는 schemaVersion:1, status:"proposed", entries:[...] 형태로 통일한다. 각 항목에 id/name 포함. 외부 참조는 아래 식별자 사용. 문서와 JSON의 수치가 일치해야 한다.
- 구성되지 않은 상세값은 임의의 확정 사실로 쓰지 않는다. 제안 수치를 명시하고 검증 방법을 함께 기록한다.

## 분야별 필수 문서·데이터 양식

사용자 추가 요구: 수치표를 나열하기 전에 **개념 → 분류 → 구성과 관계 → 동작 규칙 → 실제 항목 데이터** 순으로 설명한다. 적용되지 않는 부분은 이유를 기재하고, 데이터와 별개로 형태·행동·공간의 설계 의도를 설명한다.

각 담당 문서에는 **변수 사전**을 반드시 포함한다. 현재 구현을 확인하고 다음 열을 공통으로 사용한다.

| 개념/분류 | 현재 변수·위치 | 새 데이터 경로 | 상태 | 타입·단위 | 허용 범위/열거형 | 제안 기본값/항목별 값 | 결정 근거·연관 규칙 | 검증·이전 방식 |
|---|---|---|---|---|---|---|---|---|
| 예: 개체 HP | 실제 확인한 파일과 변수, 없으면 없음 | 실제 JSON 필드 경로 | 유지/신규/변경/폐기 후보 | number / HP | 유효성 범위와 밸런스 범위 구분 | 구체값 또는 항목표 참조 | 플레이어 기준·역할·계산식 | 테스트와 구 저장 영향 |

- 현재 변수는 실제 코드 근거를 확인한다. 비슷한 이름만으로 같은 의미라고 간주하지 않는다.
- 유효성 범위(음수 금지 등)와 밸런스 목표 범위(종별 HP 등)를 구분한다. 단위와 null/누락 의미를 적는다.
- 기본값과 개별 오버라이드를 구분한다. 랜덤 범위에는 분포·표본 시점·시드/저장 정책을 적는다.
- 식별자 참조와 외부 소유권을 명시한다. 타 분야 값은 복사해서 다르게 정의하지 말고 참조한다.
- JSON 각 항목은 모든 수치 필드에 대해 문서 변수 사전의 근거를 추적할 수 있어야 한다.
- 기존→신규 매핑은 자동 이전 확정이 아니다. 현재 미구현인 계약은 명시한다.
- 분야별 장문 설명의 세부 구조는 개념과 분류에 맞춰 구성하되, 변수 사전과 실제 데이터의 공통 양식은 유지한다.

## 공동 식별자 표

| 환경 ID | 환경 | 던전 ID | 보스 ID |
|---|---|---|---|
| grove | 이끼 숲·초원 | root_manor | rootback_beast |
| ridge | 붉은 구릉·광산권 | mining_fort | mine_carapace |
| marsh | 습지·산성 수역 | floodworks | sluice_acidworm |
| thermal | 화산·열곡 | geothermal_foundry | furnace_carapace |
| coast | 해안·고원 | cliff_observatory | spire_glider |
| mana_grove | 마나림 | sealed_arboretum | arboretum_symbiote |
| sacred | 성역이 겹친 환경 | forgotten_monastery | sanctuary_warden |
| anomaly | 국소 이상 지역 | inertia_tower | observatory_sentinel |

환경 담당은 sacred/anomaly의 중첩 환경 여부를 명시한다. 모든 환경을 특정 티어에 영구 고정하지 않는다. 던전·보스 담당은 대표 시제품의 기준 티어와 다른 티어 변형 규칙을 구분한다.
