# FERAL 소프트웨어 구조

구조의 기준 문서다. 아래 [현재]는 0.19.0 작업 트리의 코드 구조이며, 공개 배포 상태와 검증 범위는 [현황](STATUS.md)과 [검증](../verification/0.19.0.md)에서 구분한다. 과거 WebView 구조는 Git 이력과 이전 버전 검증 기록에 남아 있다.

## 1. 확정한 방향

- 런처에서 월드를 선택하고, 하나의 게임 세션이 월드 설정을 읽는다. 섬·콘텐츠 탐험·첫 신호·기계 시험장은 같은 실행기의 지형·규칙·모듈 기본값이다.
- 게임 계산·물리·렌더·화면을 컴파일된 네이티브 실행으로 전환한다. JavaScript는 데이터 내보내기와 이전 저장 추출에만 사용한다.
- 행동 판정과 화면 동작은 독립된 두 트랙이다. 같은 고정 시간축을 읽지만 화면의 손·도구 메시가 판정을 일으키지는 않는다.
- 기존 저장은 원본을 보존하며 변환한다. 변환에 실패한 저장을 새 월드로 대신 열지 않는다.
- 즉시 채집, 분리된 물체의 추가 파괴, 외피·골격, 재료·에너지 보존, 정확한 빈 공간 충돌을 유지한다.

## 2. 실행 구조 [현재]

```text
Android Godot 앱 / Linux Godot 실행기
 ├ Godot 4.6.3: 네이티브 렌더러 · 창/터치/오디오 · Control 화면
 ├ Jolt: 한 물리 공간의 지형 · 플레이어 · 생물 · 기계 · 분리 물체
 └ C++17 GDExtension (feral_library_init)
    ├ FeralGame: 런처/세션 · 입력 · 고정 단계 · 화면/물리 어댑터
    ├ Actions: 독립된 타격 트랙과 화면 트랙
    ├ World: 복셀/지형 생성 · 분리 · 유체/열 · 구역 리비전
    ├ Gameplay: 소지품 · 제작/연구 · 설비/에너지 · 생존/공동체/신앙/무기
    ├ Simulation: 생물/골격 · 던전/보스 · 기계 · 첫 신호 모듈
    ├ WorldTools: 샌드박스 도구의 실제 월드/소지품 변경
    └ Storage: 월드 목록/설정 · 두 세대 저장 · 이전 저장 변환
```

게임 코드는 `native/src/`, 실행 설정은 `native/project.godot`, 콘텐츠는 `native/data/`다. 기존 `app/src/main/assets/` 코드는 기준 데이터·이전 저장 픽스처·회귀 비교에 남겨 두며 새 APK 게임 루프에서 실행하지 않는다. `native/addons/FeralMigration/`의 GDScript는 Android 플러그인을 패키징하는 **에디터 내보내기 도구**다.

렌더러는 모바일 호환성을 위해 Godot Compatibility(OpenGL ES)로 설정한다. C++ 물리·게임 계산과 네이티브 렌더링이라는 선택은 WebGPU나 WebAssembly 전환과 별개다. Godot 바인딩과 C++ 표준 라이브러리의 내부 심볼은 공유 라이브러리 밖으로 공개하지 않는다. 공개 진입점은 `feral_library_init` 하나이며 빌드에서 동적 심볼 표를 검사한다.

## 3. 입력과 두 행동 트랙 [현재]

`입력 → ActionIntent → 60Hz Actions → HitQuery → 실제 접촉 → 피해/변형`이 판정 경로다. 별도로 렌더 프레임은 `sample_visual()`을 읽어 손과 도구의 위치·회전을 그린다.

- 점타격: 지정한 `hitFrame`에 조준선의 첫 표면을 찾고 유한한 반경을 판정한다. 기본 곡괭이는 6번째 단계, 반경 0.28m이며 UI에서 조정할 수 있다.
- 휘두르기: `activeStartFrame`부터 `activeEndFrame`까지 히트박스 중심의 키프레임을 샘플링한다. 직전 위치와 현재 위치 사이를 쓸어 판정하며 큰 회전은 세분한다.
- 한 공격의 동일 대상/칸 중복, 접촉 수, 피해 예산을 제한한다. 낮은 렌더 FPS 때문에 타격 횟수가 늘어나지 않는다.
- 화면 동작을 숨기거나 미리보기 시간축을 움직여도 실제 판정은 바뀌지 않는다. 편집기 미리보기는 별도 Actions 인스턴스로 실행하며 월드에 피해를 전달하지 않는다.
- 화면 프레임당 물리 따라잡기는 최대 3단계다. 시간축 프레임은 60Hz 시뮬레이션 단계 번호이며 디스플레이의 그린 프레임 번호가 아니다.

## 4. 데이터 범위와 저장 [현재]

| 범위 | 저장과 책임 |
| --- | --- |
| 전역 설정 | Storage의 설정 두 세대. 이전 감도·시야각 등의 값은 네이티브 단위로 변환하고 원본 설정/UI 배치는 보존한다. |
| 월드 설정 | 목록의 `configVersion`, `preset`, `seed`, `terrain.generator`, `rules`, `modules`. |
| 월드 상태 | `world`, `gameplay`, `simulation`, `worldTools`, `player`를 같은 스냅샷으로 저장한다. |
| 행동 설정 | `user://action_profiles.json`; 잘못된 프로필은 적용 전 검증한다. |

전체 게임 저장 호환 번호는 `version.json`의 `saveSchema=5`, 네이티브 저장 봉투 자체의 형식 번호는 1이다. 둘은 다른 목적이다. 파일 저장은 체크섬과 순서를 가진 두 세대를 사용한다. 최신 세대가 손상됐으면 이전 정상 세대를 읽는다. 알려지지 않은 원본 필드와 가져오기 아카이브는 보존한다.

Android 플러그인은 기존 앱과 같은 패키지·WebView 출처에서 localStorage의 `feral.*` 및 IndexedDB 보관함을 추출한다. 이 WebView는 게임을 실행하지 않는다. C++은 기존 압축 봉투를 검증·해제하고 World/Gameplay/Simulation 로더로 실제 상태를 복원한다. 네 가지 프리셋의 실제 JS 저장 픽스처로 이 경로를 검사한다.

추출 실패, 봉투 오류, 의미 검증 실패를 구분하며 미완료 가져오기는 재검증한다. 실패한 월드와 원본을 보존하고 시작을 막는다. 기존 저장에 시작 보급품을 다시 지급하지 않는다. 네이티브 진행을 예전 JS 앱으로 역변환하는 기능은 없다.

## 5. 하나의 물리 공간 [현재]

- 지형은 4m 구역의 정적 복합 충돌체다. 분리 물체와 기계, 지지를 잃은 설비는 각각 하나의 RigidBody3D에 정확한 복합 상자 형상을 둔다.
- 복셀마다 Godot 노드나 독립 강체를 만들지 않는다. 합쳐진 상자도 실제 점유 공간만 덮으며 외곽 AABB로 구멍을 막지 않는다.
- 잎 등 비고체는 질량/시각 데이터에 남아도 지형 충돌을 요구하지 않는다. 비고체만 있는 물체는 3차원 64m, 고체 물체는 수평 64m 활성 범위를 사용한다. 범위 밖 물체의 저장은 지우지 않는다.
- Jolt의 최종 자세·속도를 World/Simulation/Gameplay에 되돌린다. 별도의 JS 물리 세계와 번갈아 계산하지 않는다.
- 생물의 관절·손상 외피·골격은 한 소유자의 복합 형상으로 연결한다. 부위 손상 리비전과 자세 갱신을 구분한다.
- 유체 셀과 게임용 부력·항력, 기계 동력 계산은 C++ 규칙이며 결과 힘을 같은 Jolt 몸체에 적용한다. 정밀 유체 역학을 구현한 것은 아니다.

## 6. 콘텐츠와 화면 [현재]

`tools/native/export-content.mjs`는 정식 콘텐츠·에셋 제작 API의 결과를 JSON과 아이콘으로 내보낸다. 새 네이티브 모델을 임의의 대체 큐브로 재작성하지 않는다. 생성 결과의 정확한 바이트를 `--check`로 검사한다.

런처, HUD, 가방, 제작/연구, 설비/에너지, 기계 편집기, 무기, 공동체/신앙, 지도, 행동 편집기는 Godot Control로 만든다. 입력은 C++ 명령으로 상태를 바꾼다. 기계 패널의 격자 조립과 실제 조종, 행동 편집기의 두 시간축은 공용 화면이다. 일시정지/설정 화면은 물리를 멈추며, 일반 플레이 패널에서는 시뮬레이션이 계속된다.

## 7. 성능과 검증

형상 변경, 유체 변경, 자세 변경의 리비전을 분리한다. 칸 체력만 줄 때 메시·충돌체를 다시 만들지 않는다. 지형의 바뀐 구역만 대기열에 넣고 플레이어/활성 몸체 가까운 구역을 먼저 처리한다. 기본 메시 작업 예산은 물리 단계당 최대 3구역이며, 한 구역을 끝낼 때 4ms를 넘었으면 다음 단계로 넘긴다. 단일 구역 작업 자체를 중단하는 선점형 예산은 아니다. 스트리밍은 고체의 실제 범위와 양자화한 구역 캐시를 사용한다.

네이티브 검사는 `tools/native/test.sh`가 실행한다: C++ 규칙 검사, 실제 Jolt 검사, 전체 세션 시작/타격/저장, 화면 진입, 실제 나무 세 개 분리 후 전체 런타임 측정. 데스크톱 헤드리스 CPU 시간·llvmpipe 화면 검사는 Android GPU FPS나 발열 검사를 대신하지 않는다. 기존 `npm test`와 JS 성능 기록은 이전 규칙·데이터 회귀용이며 네이티브 코드의 통과 근거로 혼용하지 않는다.

## 8. 빌드와 업데이트

Linux x86_64와 Android arm64용 C++ 라이브러리를 실제 컴파일한다. 버전 고정·도구 준비·빌드는 `tools/native/`가 관리한다. APK는 Godot Android 내보내기 템플릿에 arm64 GDExtension과 데이터, 저장 변환/업데이트 플러그인을 포함한다.

C++ 코드 변경은 새 APK 설치가 필요하다. 서명된 배포 메타데이터에 APK 해시·크기·패키지·앱 서명을 포함하며, 다운로드 뒤 모두 검증하고 사용자가 설치를 누르면 Android 설치 화면으로 넘긴다. 앱 제거 없이 같은 패키지에 업데이트해야 저장이 유지된다. `.feral`의 네이티브 콘텐츠 스냅샷만으로 C++ 실행 코드가 바뀌는 것은 아니다. 상세 배포 절차와 이전 WebView 버전 선택의 적용 범위는 [배포](RELEASING.md)에 명시한다.
