# FERAL 소프트웨어 구조

이 문서는 FERAL의 구조에 관한 **유일한 기준**이다. 다른 문서와 다르면 이 문서가 맞고, 이 문서가 코드와 다르면 버그로 본다(문서나 코드 중 하나를 고친다).

- **[현재]**: 코드에서 확인한 사실. 기준 커밋 `3a7f871`(게임 0.14.1).
- **[목표]**: 사용자가 확정한 구조. 아직 구현되지 않은 부분은 [로드맵](ROADMAP.md)의 단계에서 만든다.
- 구조를 바꾸는 코드 변경은 같은 PR에서 이 문서를 고친다. 단계가 끝나면 해당 [목표]를 [현재]로 옮긴다.

## 1. 결정 사항 (사용자 확정)

| 결정 | 내용 |
| --- | --- |
| 런처와 게임 세션 분리 | 앱의 첫 화면은 게임 밖의 **런처**다. 어느 월드에 들어갈지, 새 월드를 만들지, 기존 월드 설정을 고칠지, 게임 전체의 환경 설정을 여기서 한다. 월드에 들어가면 **게임 세션**이 시작된다. |
| 월드 설정은 런처에서 | 월드마다 다른 규칙·지형 같은 설정은 런처에서 만들고 고친다. 게임 세션은 그 설정을 읽어서 따른다. |
| 게임 시스템은 하나 | 맵마다 다른 게임을 만들지 않는다. 맵(섬·개척 원정·기계 시험장·콘텐츠 탐험)은 하나의 시스템 위의 **프리셋**(월드 설정의 기본값 묶음)이다. |
| 진행 순서 | 런처·게임 세션 구조를 먼저 세우고, 게임 세션 안의 엔진 통합은 그 뒤 단계적으로 다듬는다. |
| 화면·감각 기준 | 화면과 조작 감각은 개척 원정을 기준으로 한다. 즉시 채집, 개척 원정 채굴 규칙, 분리된 덩어리 깎기, 생명체 외피와 골격을 약화하지 않는다. 타격 방식은 든 도구·무기가 정한다. 세부 규칙은 [게임 규칙](GAME-RULES.md). |
| 복셀 에셋 | 제작 경로·소유권·충돌은 [복셀 에셋 규칙](VOXEL-ASSET-RULES.md)을 따른다. |

## 2. 전체 구조 [목표]

```
Android 앱 (네이티브)                플랫폼: 게임 파일 버전·서명 검증·백업·시작 감시·버전 선택
 └ WebView: 한 버전의 게임 파일 전체
    ├ 런처 (게임 밖)                 랜딩 · 월드 목록 · 월드 만들기/설정 · 전역 설정 · 업데이트
    │   └ 저장소 계층                전역 설정 · 월드 목록과 월드 설정 · 월드 저장 (형식 버전과 변환)
    └ 게임 세션 (게임 안)            worldId 하나로 시작. 월드 설정을 읽어 시스템을 조립
        ├ 세션 화면                  shell.js 공용 화면(HUD·가방·장부·메뉴), 개척 원정 화면 기준
        ├ 엔진                       하나의 런타임 (content-runtime/)
        └ 콘텐츠 데이터              design/content → catalog.generated.js
```

### 층별 책임

| 층 | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| 플랫폼 (Java) | 게임 파일 버전의 다운로드·서명/해시 검증·전환, 시작 전 `feral.*` 저장 백업, 시작 실패 시 이전 코드·저장 복구, 게임 버전 선택, 빌드별 저장 분리 | 월드·게임 규칙을 알지 않는다 |
| 런처 | 월드 목록 표시·선택, 월드 만들기(프리셋 선택 후 설정 조정), 월드 설정 편집·복제·삭제, 전역 설정, 업데이트 화면 | 게임 엔진과 3D 월드를 띄우지 않는다. 월드 저장 내용을 해석하지 않는다(요약 표시 제외) |
| 저장소 계층 | 세 범위의 데이터(4장)를 읽고 쓰고, 형식 버전을 검사하고 변환한다 | 화면을 그리지 않는다 |
| 게임 세션 | 월드 설정에 맞춰 엔진을 만들고, 게임 화면·입력·저장·나가기를 맡는다 | 월드 설정을 바꾸지 않는다(런처의 일). 맵 이름으로 동작을 나누지 않는다 |
| 엔진 | 월드 상태와 규칙(지형·생명체·채굴·전투·제작·저장 직렬화) | DOM·화면에 의존하지 않는다 |

## 3. 앱 시작 흐름

### [현재]

1. 네이티브가 `/bootstrap`을 연다. bootstrap은 `feral.*` 저장을 백업하고 활성 게임 버전을 정한 뒤 `/assets/index.html`을 연다.
2. `index.html`은 게임 화면이다. `game.js`가 주소의 `?world=`를 읽고, 없으면 **기본 섬**을 고른다.
3. 월드 유형(`type`)에 따라 **서로 다른 엔진**을 실행한다: `island`·`expedition` → `content-runtime/game.js`, `frontier` → `main.js`, `machine` → `machine.html`로 페이지 이동.
4. 처음 보이는 "FERAL / 탐험 시작" 화면은 랜딩이 아니라 기본 섬의 로딩 화면이다. 통합 런타임은 로딩이 끝나면 이 화면을 스스로 닫는다.
5. 게임이 지형 준비 뒤 12프레임·3초를 그리면 `AndroidApp.runtimeHealthy`로 시작 성공을 알린다. 월드 목록(`worlds.html`)도 표시 뒤 같은 신호를 보낸다. 성공 전에 오류가 나거나 90초가 지나면 네이티브가 이전 코드·저장으로 되돌린다.

### [목표]

1. 네이티브 → `/bootstrap` → **런처**(`index.html`).
2. 런처는 엔진을 띄우지 않고 바로 랜딩을 보인다.
3. 런처는 화면을 그린 뒤 게임 세션 진입 모듈을 **실행하지 않고 불러 보기만 한다**. 그 다음에 시작 성공을 알린다. 엔진 파일이 깨진 업데이트도 시작 실패로 잡혀 되돌려진다. 이를 위해 세션 진입 모듈은 불러오는 것만으로는 아무것도 시작하지 않고 `start(world)`를 내보낸다.
4. 사용자가 월드를 고르면 `play.html?world=<id>`로 이동해 세션을 시작한다. 세션에서 나가면 저장 후 런처로 돌아온다.
5. 세션 시작 실패(지형 생성 오류 등)는 오류 화면과 "런처로 돌아가기"로 처리한다. 이미 성공 신호를 보낸 뒤라 네이티브 자동 복구 대상은 아니다. 지금의 월드 목록 경로와 같은 한계다.

## 4. 데이터 범위와 저장

### 세 범위

| 범위 | 내용 | 바꾸는 곳 | 바뀌는 빈도 |
| --- | --- | --- | --- |
| 전역 설정 | 화질·감도·시야각·소리·왼손 조작·미니맵·사건 알림, UI 배치, 업데이트 선택 | 런처 설정 화면(세션 메뉴는 같은 부품을 씀) | 가끔 |
| 월드 설정 | 이름, 프리셋, 시드, 지형 생성기, 규칙, 시작 조건 | 런처 | 만들 때 대부분 정하고 드물게 수정 |
| 월드 저장 | 지형 변경·플레이어·소지품·생명체·진행 기록 | 게임 세션 | 플레이 중 계속 |

### 저장 키

| 데이터 | [현재] | [목표] |
| --- | --- | --- |
| 전역 설정 | `feral.settings`, `feral.ui.layout.v1` | 그대로 |
| 월드 목록 | `feral.worlds.v1`: `{id, name, type, seed}` 배열. 목록이 없으면 기본 월드 3개 | 같은 키에 항목마다 `config`(월드 설정)를 더한다. `type`은 `config.preset`과 같은 값으로 남겨 이전 빌드도 읽을 수 있게 한다 |
| 월드 저장 | 기본 섬 `feral.world.v1`, 기계 베타 `feral.machine.v1`, 그 밖 `feral.slot.<id>`. 통합 런타임 월드는 `<키>.a`/`<키>.b` 두 세대 압축 저장 | 기존 키를 그대로 쓴다. 저장 키 이름을 옮기지 않는다 |

- 앱의 게임 버전 직접 선택은 빌드마다 `feral.*` 전체를 따로 보관·복원한다(플랫폼 기능). 런처가 쓰는 전역 설정과 월드 목록도 여기에 포함된다.

### 저장 형식 변환 원칙

- 저장 형식을 바꾸거나 다른 엔진의 저장을 옮길 때는 원본 키를 지우지 않고 새 형식으로 쓴다. 새 형식이 있으면 원본은 다시 읽지 않는다. 월드를 삭제하거나 "새 세계"로 다시 만들 때만 원본도 지운다.
- 변환은 같은 입력에 같은 결과를 내고, 새 월드 시작 소지품을 더하지 않는다.
- 옮기지 못한 항목은 변환 보고서(`conversion`)로 저장하고 사용자에게 목록으로 보인다.
- 변환이나 시작에 실패하면 시작 실패(`runtimeFailed`)를 알려 앱이 이전 게임 버전과 직전 저장으로 되돌리게 한다.
- [현재] 기존 섬 저장(`feral.world.v1`, `feral.slot.<id>`, 형식 1·2) → 통합 런타임 두 세대 저장(0.14.0). 지형은 원본 로더 결과와 새 섬을 칸 단위로 비교해 다른 칸만, 반쯤 캔 칸의 균열은 그대로 옮긴다. 아이템·블록·종 대응표는 `content-runtime/maps.js`의 `LEGACY_*`, 변환은 `applyLegacyIsland`. 대응되지 않는 항목: 표 밖의 아이템(무기·화살·회복약 등), 기존 연구, 부은 물·산, 불, 떨어진 물체, 동물 개별 상태.

## 5. 월드 설정 [목표]

월드 설정은 "이 월드는 어떤 규칙으로 도는가"를 담는 데이터다. 프리셋은 이 설정의 기본값 묶음일 뿐이며, 세션은 프리셋 이름이 아니라 설정 값을 보고 동작한다.

```json
{
  "configVersion": 1,
  "preset": "island",
  "seed": 63026,
  "terrain": { "generator": "island" },
  "rules": { "survival": false, "sandbox": true, "startStructures": false, "starterKit": true }
}
```

| 항목 | 의미 | 바꿀 수 있는 때 | [현재] 대응 |
| --- | --- | --- | --- |
| `preset` | 만들 때 고른 프리셋. 표시와 기본값 출처로만 쓴다 | 만들 때 | 월드 목록의 `type` |
| `seed` | 지형·배치 시드 | 만들 때 | 월드 목록의 `seed` |
| `terrain.generator` | 지형 생성기 등록 이름(`infinite`·`island` 등) | 만들 때(바꾸면 지형이 달라짐) | `maps.js`의 `atlas` |
| `rules.survival` | 체력·식량 감소 | 언제든 | `maps.js` `rules.survival` |
| `rules.sandbox` | 샌드박스: 관찰·물·불·산·개체 생성 도구, 개발·생태 탭, 캔 자원으로 블록 쌓기, 빈 손 사용은 관찰 | 언제든 | `maps.js` `rules.sandbox` |
| `rules.startStructures` | 시작 건축물 생성 | 만들 때 | `maps.js` `rules.structures` |
| `rules.starterKit` | 시작 소지품 지급 | 만들 때 | `maps.js` `starter`, 런타임 `starter` 옵션 |

- 런처는 그 프리셋의 세션이 **실제로 지원하는 항목만** 보인다. 세션이 읽지 않는 설정을 화면에 두지 않는다. 아직 옛 엔진에서 도는 개척 원정·기계 시험장은 이름·시드 외에 바꿀 항목이 없다고 표시한다.
- 항목 목록은 엔진이 지원하는 만큼 늘린다. 항목을 더할 때 이 표와 `configVersion` 변환을 함께 고친다.
- 기존 월드는 처음 읽을 때 `type`에 맞는 프리셋 기본값으로 설정을 만든다. 원래 항목은 지우지 않는다.

## 6. 게임 세션

### 시작 약속 [목표]

- 입력은 `play.html?world=<id>` 하나다. 세션은 저장소 계층에서 그 월드의 목록 항목과 월드 설정을 읽는다.
- 세션은 월드 설정을 바꾸지 않는다. 마지막으로 플레이한 시각 같은 표시용 기록만 남길 수 있다.
- 나가기: 저장에 성공하면 런처로 돌아간다. 저장에 실패하면 나가지 않고 안내한다.

### 세션 안의 엔진 [현재]

게임 세션 안에 **엔진이 세 개** 있고, 월드 유형이 그중 하나를 고른다.

| 엔진 | 월드 유형 | 코드 | 화면 |
| --- | --- | --- | --- |
| 통합 런타임 | 기본 섬, 콘텐츠 탐험 | `content-runtime/` (약 9,900줄) | `index.html` + `shell.js` 공용 화면 |
| 개척 원정 엔진 | 개척 원정 | `main.js`, `world.js`, `entities.js`, `inventory.js`, `render.js` (약 5,000줄), `frontier/` (약 3,700줄) | `index.html` + `shell.js` 공용 화면(0.13.0부터) |
| 기계 시험장 | 기계 베타 맵 | `machine.html`, `machine/` (약 1,400줄) | 자체 페이지·자체 HUD, 전역 설정 메뉴 없음 |

세 엔진이 함께 쓰는 것: `shell.js`(알림·입력·설정·메뉴·현장 HUD·장부 창·상태/지도 페이지), `inventory-ui.js`(36칸 가방), `hud-editor.js`, `equipment.js`(개척 원정 채굴 공식), `physics.js`(캐릭터 이동), `updates.js`(세션 안 업데이트 화면), `world-slots.js`(월드 목록).

### 알려진 구조 문제 [현재]

| 문제 | 위치 |
| --- | --- |
| 월드 유형이 실행할 엔진을 고른다 | `game.js` |
| 통합 런타임 화면 코드에 맵 이름 분기가 남아 있다(미니맵 범위, 출발지 이름) | `content-runtime/game.js`의 `runtime.map.id==='island'` |
| 맵 규칙이 코드 고정값이라 월드마다 바꾸거나 저장할 수 없다 | `content-runtime/maps.js`의 `MAPS` |
| 게임 밖 화면이 없다. 타이틀은 게임 페이지 안의 로딩 화면이다 | `index.html` `#titleScreen` |
| 전역 설정과 업데이트가 게임 안 메뉴에만 있어 월드에 들어가야 바꿀 수 있다 | `index.html` 일시정지 메뉴, `shell.js` `initSettings` |
| 월드를 만든 뒤 설정을 고칠 화면이 없다(이름 변경·삭제만) | `worlds.html`, `world-menu.js` |
| 저장 키 규칙이 월드마다 다르다 | `world-slots.js` `saveKey` |
| 섬 전용 문구가 공용 페이지에 있다("섬 전용" 샌드박스 제목) | `index.html` |
| `main.js`에 더 이상 실행되지 않는 기본 섬 경로가 남아 있다 | `main.js` |
| 기계 시험장이 별도 페이지·별도 화면이다 | `machine.html`, `machine/view.js` |

### 세션 통합 원칙 [목표, 단계적]

- 엔진은 `content-runtime/` 하나로 모은다. 다른 두 엔진의 기능은 버리지 않고 옮긴다. 대상 목록은 [로드맵](ROADMAP.md#세션-통합-때-옮길-기능).
- 맵마다 다른 점은 두 가지로만 표현한다.
  1. 월드 설정 값
  2. 등록된 모듈 이름: 지형 생성기, 첫 신호 캠페인처럼 켜고 끄는 시스템
- 세션 코드에서 맵·프리셋 이름을 비교하지 않는다. 전환기 동안 옛 엔진을 고르는 분기는 세션 진입점 한 곳(`play.html`의 세션 라우터)에만 둔다. 이 분기는 옛 엔진이 사라지면 함께 없앤다.
- 세션 화면 요소는 `shell.js`나 기존 공용 모듈에만 추가한다. 맵 전용 HUD·패널·알림·조작·CSS를 새로 만들지 않는다.

### 바꿀 수 없는 제약

- 앱 0.3.3은 게임 업데이트 하나에 파일 128개까지 받는다(`UpdateCore.MAX_FILES`). 0.14.1은 123개이고 `tests/unified-game.test.js`가 여유 4개 이상을 확인한다. 파일을 더하는 변경은 은퇴할 파일을 같은 버전에서 지우거나, 상한을 올린 새 APK와 `minNativeCode` 증가가 필요하다.
- Android WebView는 앱 내부 주소의 파일 형식을 확장자로 정한다. `.mjs`처럼 등록되지 않은 확장자는 모듈로 불러올 수 없다(0.12.1 원인). 검증은 앱과 같은 규칙의 `tools/android-asset-server.mjs`로 한다.
- 업데이트는 전체 버전 단위로 검증하고 다음 실행에 적용한다. 부분 파일 교체와 플레이 중 자동 재시작은 하지 않는다. 절차는 [배포](RELEASING.md).

## 9. 용어

| 플랫폼 | Android 네이티브 앱. 게임 파일 버전과 복구를 맡는다 |
| 모듈 | 엔진 안에서 이름으로 등록해 설정으로 켜고 끄는 시스템(지형 생성기, 캠페인 등) |
