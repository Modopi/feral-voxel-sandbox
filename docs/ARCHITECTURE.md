# FERAL 소프트웨어 구조

이 문서는 FERAL의 구조에 관한 **유일한 기준**이다. 다른 문서와 다르면 이 문서가 맞고, 이 문서가 코드와 다르면 버그로 본다(문서나 코드 중 하나를 고친다).

- **[현재]**: 코드에서 확인한 사실. 기준: 게임 0.15.2.
- **[목표]**: 사용자가 확정한 구조. 아직 구현되지 않은 부분은 [로드맵](ROADMAP.md)의 단계에서 만든다.
- 구조를 바꾸는 코드 변경은 같은 PR에서 이 문서를 고친다. 단계가 끝나면 해당 [목표]를 [현재]로 옮긴다.

## 1. 결정 사항 (사용자 확정)

| 결정 | 내용 |
| --- | --- |
| 런처와 게임 세션 분리 | 앱의 첫 화면은 게임 밖의 **런처**다. 어느 월드에 들어갈지, 새 월드를 만들지, 기존 월드 설정을 고칠지, 게임 전체의 환경 설정을 여기서 한다. 월드에 들어가면 **게임 세션**이 시작된다. |
| 월드 설정은 런처에서 | 월드마다 다른 규칙·지형 같은 설정은 런처에서 만들고 고친다. 게임 세션은 그 설정을 읽어서 따른다. |
| 게임 시스템은 하나 | 맵마다 다른 게임을 만들지 않는다. 맵(섬·개척 원정·기계 시험장·콘텐츠 탐험)은 하나의 시스템 위의 **프리셋**(월드 설정의 기본값 묶음)이다. |
| 진행 순서 | 런처·게임 세션 구조를 먼저 세우고(0.15.0), 게임 세션 안의 엔진 통합은 그 뒤 단계적으로 다듬는다. |
| 화면·감각 기준 | 화면과 조작 감각은 개척 원정을 기준으로 한다. 즉시 채집, 개척 원정 채굴 규칙, 분리된 덩어리 깎기, 생명체 외피와 골격을 약화하지 않는다. 타격 방식은 든 도구·무기가 정한다. 세부 규칙은 [게임 규칙](GAME-RULES.md). |
| 복셀 에셋 | 제작 경로·소유권·충돌은 [복셀 에셋 규칙](VOXEL-ASSET-RULES.md)을 따른다. |

## 2. 전체 구조

```
Android 앱 (네이티브)                플랫폼: 게임 파일 버전·서명 검증·백업·시작 감시·버전 선택
 └ WebView: 한 버전의 게임 파일 전체
    ├ 런처 index.html + launcher.js  랜딩 · 월드 목록 · 월드 만들기/설정 · 전역 설정 · 업데이트   [현재]
    │   └ 저장소 계층                world-slots.js(월드 목록·월드 설정) · settings.js(전역 설정)   [현재]
    └ 게임 세션 play.html + game.js  worldId 하나로 시작해 월드 설정을 따른다                     [현재]
        ├ 세션 화면                  shell.js 공용 화면(HUD·가방·장부·메뉴), 개척 원정 화면 기준
        ├ 엔진                       [현재] content-runtime/ 하나(0.17.0부터 모든 프리셋)
        └ 콘텐츠 데이터              design/content → catalog.generated.js
```

### 층별 책임

| 층 | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| 플랫폼 (Java) | 게임 파일 버전의 다운로드·서명/해시 검증·전환, 시작 전 `feral.*` 저장 백업, 시작 실패 시 이전 코드·저장 복구, 게임 버전 선택, 빌드별 저장 분리 | 월드·게임 규칙을 알지 않는다 |
| 런처 | 월드 목록 표시·선택·이어하기, 월드 만들기(프리셋 선택 후 설정 조정), 월드 설정 편집·삭제, 전역 설정, 업데이트 화면, 앱에 시작 성공 알림 | 게임 엔진과 3D 월드를 띄우지 않는다. 월드 저장 내용을 해석하지 않는다(저장 유무 표시만) |
| 저장소 계층 | 세 범위의 데이터(4장)를 읽고 쓰고, 형식 버전을 검사하고, 저장 보관함으로 버전이 바뀌어도 저장을 유지한다 | 화면을 그리지 않는다 |
| 게임 세션 | 월드 설정에 맞춰 엔진을 만들고, 게임 화면·입력·저장·런처로 나가기를 맡는다 | 월드 설정을 바꾸지 않는다(마지막 플레이 시각만 기록). 맵 이름으로 동작을 나누지 않는다([현재] 예외는 6장 문제 표) |
| 엔진 | 월드 상태와 규칙(지형·생명체·채굴·전투·제작·저장 직렬화) | DOM·화면에 의존하지 않는다 |

## 3. 앱 시작 흐름 [현재]

1. 네이티브가 `/bootstrap`을 연다. bootstrap은 `feral.*` 저장을 백업하고 활성 게임 버전을 정한 뒤 `/assets/index.html`(런처)을 연다.
2. 런처는 엔진을 띄우지 않고 바로 랜딩(이어하기·월드 선택·환경 설정·업데이트)을 보인다. 동시에 저장 보관함(4장)에서 필요한 저장을 되살린다. 월드는 되살리기가 끝난 뒤에 열린다.
3. 런처는 화면을 그린 뒤 게임 세션 진입 모듈(`content-runtime/game.js`)을 **실행하지 않고 불러 보기만 한다**. 성공하면 12프레임·3초 뒤 `AndroidApp.runtimeHealthy`로 시작 성공을 알린다. 실패하면 `runtimeFailed`를 알려 앱이 이전 게임 버전과 저장으로 되돌린다. 세션 진입 모듈은 불러오는 것만으로는 아무것도 시작하지 않고 `start(world)`를 내보낸다.
4. 사용자가 월드를 고르면 `play.html?world=<id>`로 이동해 세션이 시작된다. 세션 메뉴의 "저장 후 런처로"는 저장에 성공해야 런처로 돌아간다.
5. 세션 시작 실패(지형 생성 오류 등)는 로딩 화면의 다시 시도·런처로 돌아가기로 처리한다. 런처가 이미 시작 성공을 알린 뒤라 네이티브 자동 복구 대상은 아니다. 세션 안에서도 지형 준비 뒤 같은 성공 신호를 보내며, 네이티브는 시험 중인 버전에만 반응한다.
6. 예전 주소 `index.html?world=<id>`는 `play.html?world=<id>`로 넘어간다.

## 4. 데이터 범위와 저장

### 세 범위

| 범위 | 내용 | 바꾸는 곳 | 저장 위치 |
| --- | --- | --- | --- |
| 전역 설정 | 화질·감도·시야각·소리·왼손 조작·미니맵·사건 알림 / UI 배치 / 자동 업데이트 | 런처 설정 화면과 세션 메뉴(같은 `settings.js` 부품) / 세션의 UI 배치 편집기 / 업데이트 화면 | `feral.settings` / `feral.ui.layout.v1` / 네이티브 |
| 월드 설정 | 이름, 프리셋, 시드, 지형 생성기, 규칙 | 런처 | `feral.worlds.v1` 항목의 `config` |
| 월드 저장 | 지형 변경·플레이어·소지품·생명체·진행 기록 | 게임 세션 | 기본 섬 `feral.world.v1`, 기계 베타 `feral.machine.v1`, 그 밖 `feral.slot.<id>`. 통합 런타임 월드는 `<키>.a`/`<키>.b` 두 세대 압축 저장 |

- 월드 목록(`feral.worlds.v1`)은 `{id, name, type, seed, config, createdAt?, lastPlayedAt?}` 배열이다. 목록이 없으면 기본 월드 3개(기본 섬·개척 원정·기계 베타)를 보인다. `type`은 `config.preset`과 같은 값으로 남겨 이전 게임 빌드도 목록을 읽을 수 있다.
- 저장 키 이름은 옮기지 않는다(사용자 저장 보존).

### 저장 보관함: 버전이 바뀌어도 저장 유지 [현재, 사용자 결정]

사용자 결정: 업데이트나 게임 버전 전환으로 월드가 초기화되면 안 된다.

- 원인이던 플랫폼 동작: 앱 0.3.3은 게임 버전 목록에서 고른 빌드마다 `feral.*` 저장 전체를 따로 보관·복원한다. 한 번도 실행하지 않은 빌드는 빈 저장으로 시작하고, 고른 버전에 고정돼 자동 업데이트가 꺼진다. "지금 확인 → 저장 후 적용"(일반 업데이트)은 저장을 그대로 둔다. 이 동작은 APK에 있어 게임 파일로 바꿀 수 없다.
- 저장 보관함(`world-slots.js`)은 모든 `feral.*` 키의 최신 전체 사본을 IndexedDB `feral-vault`에 둔다. 앱은 IndexedDB를 바꾸지 않는다.
  - 복사: 엔진이 저장할 때마다(통합 런타임 자동·수동 저장), 런처에서 월드·설정을 바꿀 때, 세션이 시작될 때 바뀐 키만 복사하고 지워진 키는 사본에서도 지운다. 사본 전체에 저장 시각·쓴 빌드·`saveSchema`를 남기고, 저장 공간에는 어느 사본과 맞췄는지(`feral.vault.v1`)를 남긴다.
  - 되살리기: 런처가 시작할 때 이 빌드의 저장 공간이 비었거나 사본보다 오래됐으면 사본 전체로 바꾼다(키 단위로 섞지 않는다). 쓰는 중 실패하면 원래 저장을 되돌린다.
  - 보관함을 모르는 빌드(0.14.1 이하)의 저장이 남아 있으면 그곳이 플레이어가 멈춘 곳이므로 그대로 두고 사본을 그것으로 바꾼다.
  - 더 높은 `saveSchema`로 쓴 사본은 낮은 스키마의 빌드가 가져오지도 덮지도 않는다. 저장 형식이 이전 빌드에서 읽을 수 없게 바뀌면 `saveSchema`를 올린다.
- 한계: 0.14.1 이하에서 버전 목록으로 0.15.0을 고르면 그 순간에는 보관함이 비어 있어 빈 저장으로 시작한다(이전 저장은 앱이 그 빌드 몫으로 보관 중이다). 이번 업데이트는 "지금 확인 → 저장 후 적용"으로 받아야 한다. 이미 빈 저장으로 시작했다면 버전 목록에서 이전 버전을 다시 골라 저장을 되찾은 뒤 "지금 확인 → 저장 후 적용"으로 올린다. 0.15.0부터는 어느 방법으로 바꿔도 저장이 따라온다.
- 앱의 시작 실패 복구(시작 전 `feral.*` 백업과 복원)는 그대로다.

### 저장 형식 변환 원칙

- 저장 형식을 바꾸거나 다른 엔진의 저장을 옮길 때는 원본 키를 지우지 않고 새 형식으로 쓴다. 새 형식이 있으면 원본은 다시 읽지 않는다. 월드를 삭제하거나 "새 세계"로 다시 만들 때만 원본도 지운다.
- 변환은 같은 입력에 같은 결과를 내고, 새 월드 시작 소지품을 더하지 않는다.
- 옮기지 못한 항목은 변환 보고서(`conversion`)로 저장하고 사용자에게 목록으로 보인다.
- 변환이나 시작에 실패하면 시작 실패(`runtimeFailed`)를 알린다.
- [현재] 기존 섬 저장(`feral.world.v1`, `feral.slot.<id>`, 형식 1·2) → 통합 런타임 두 세대 저장(0.14.0). 지형은 원본 로더 결과와 새 섬을 칸 단위로 비교해 다른 칸만, 반쯤 캔 칸의 균열은 그대로 옮긴다. 아이템·블록·종 대응표는 `content-runtime/maps.js`의 `LEGACY_*`, 변환은 `applyLegacyIsland`. 대응되지 않는 항목: 표 밖의 아이템(무기·화살·회복약 등), 기존 연구, 부은 물·산, 불, 떨어진 물체, 동물 개별 상태.
- [현재] 기존 개척 원정 저장(`feral.slot.<id>`, 형식 2, `campaign`이 있는 것) → 통합 런타임 두 세대 저장(0.16.0). 생성기의 `legacySave`가 맡는다(`content-runtime/maps.js` `applyLegacyFrontier`).
  - 지역마다 그 지역을 만든 지형 버전(`terrainVersion`, 없으면 1)을 지형 생성 전에 넘기고(`atlasOptions` → `FrontierAtlas.regionTerrain`), 그 버전의 원래 지형과 저장 지형을 칸 단위로 비교해 다른 칸만, 반쯤 캔 칸의 균열은 그대로 옮긴다(섬과 같은 `copyLegacyCells`).
  - 캠페인 기록은 `first-signal` 모듈 상태가 된다(`runtime.loadModule`). 모듈 검사를 통과하지 못하면 새 원정으로 시작하고 그 사실을 목록에 남긴다.
  - 아이템은 `FRONTIER_ITEMS`로, 연구 기록은 연구 작업 5초로, 유적 핵은 모듈 기록으로 옮기고 시작 보급은 주지 않는다. 대응되지 않는 항목: 경험치·레벨, 표 밖의 아이템(야채 스튜·장비 등), 기존 제작 해금, 기계 설계, 부은 물·산, 불, 떨어진 물체, 동물 개별 상태, 땅에 놓인 아이템.
- [현재] 기존 기계 시험장 저장(`feral.machine.v1`, 형식 1, `blueprint`가 있는 것) → 통합 런타임 두 세대 저장(0.17.0). 생성기의 `legacySave`가 맡는다(`content-runtime/machine-field.js` `applyLegacyMachineField`).
  - 0.5 m 부품 설계를 50 cm 기계 하나로 들여온다(`MachineSystem.importDesign`, 가방에서 꺼내지 않는다). 부품은 목재 복셀이고 체력 비율을 지킨다. 옛 앞쪽(-Z)이 기계의 앞(+Z)이 되게 돌려 (x, y, z) → (-x, y, -z), 방향은 `π - yaw`, 핵심 칸이 옛 위치에 선다.
  - 모터는 열기관(나무 연료 8개), 바퀴는 바퀴 변속기, 열기관마다 모든 바퀴에 역학 연결. 위가 비어 있는 가장 앞쪽 차체에 조종 장치를 단다(조종석에서 앞이 보이게).
  - 시험장 시작 장비는 새 시험장처럼 주고 예제 기계는 놓지 않는다. 대응되지 않는 항목: 부서진 부품(체력 0), 핵심에서 떨어진 부품(옛 화면은 무게로만 지녔다), 시험장 재료 수치(시작 장비로 대신), 개척 원정 조립체 기록.
- [현재] 0.15.0 이전 월드 목록 항목은 `config`가 없다. 읽을 때 `type`에 맞는 프리셋 기본값으로 설정을 만들고, 런처에서 처음 저장할 때 `config`를 붙인다. 다른 항목은 바꾸지 않는다.

## 5. 월드 설정 [현재]

월드 설정은 "이 월드는 어떤 규칙으로 도는가"를 담는 데이터다. 프리셋은 이 설정의 기본값 묶음일 뿐이며, 세션은 프리셋 이름이 아니라 설정 값을 보고 동작한다. 코드는 `world-slots.js`(`PRESETS`·`RULES`·`worldConfig`·`createWorld`·`updateWorld`).

```json
{
  "configVersion": 1,
  "preset": "island",
  "seed": 63026,
  "terrain": { "generator": "island" },
  "rules": { "survival": false, "sandbox": true, "starterKit": true, "dropOnDeath": true }
}
```

| 항목 | 의미 | 바꿀 수 있는 때 |
| --- | --- | --- |
| `preset` | 만들 때 고른 프리셋. 표시와 기본값 출처로만 쓴다(0.17.0부터 엔진을 고르지 않는다) | 만들 때 |
| `seed` | 지형·배치 시드 | 만들 때 |
| `terrain.generator` | 지형 생성기 이름(`infinite`·`island`·`frontier`·`machine-field`). 프리셋이 정한다 | 만들 때 |
| `rules.survival` | 생존: 체력·식량 감소와 피해. 끄면 평화 규칙 | 언제든 |
| `rules.sandbox` | 샌드박스: 관찰·물·불·산·개체 생성 도구, 개발·생태 탭, 캔 자원으로 블록 쌓기, 빈 손 사용은 관찰 | 언제든 |
| `rules.startStructures` | 출발지 주변 시작 건축물 | 만들 때 |
| `rules.starterKit` | 시작 소지품(돌 곡괭이·목재·돌·씨앗) | 만들 때 |
| `rules.dropOnDeath` | 사망 시 소지품 남김: 쓰러진 자리에 소지품을 남기고 10 m 안에 가면 요정이 돌려준다. 끄면 소지품을 지닌 채 깨어난다(0.15.3부터) | 언제든 |
| `modules` | 켜는 런타임 모듈 이름(아래 [런타임 모듈](#런타임-모듈-현재-0154부터)). 프리셋이 정하고(개척 원정: `first-signal`, 0.16.0부터 · 기계 시험장: `machine-field`, 0.17.0부터) `worldConfig`가 늘 프리셋에서 가져온다. 저장된 사본은 읽지 않는다 | 만들 때 |

프리셋마다 세션이 실제로 읽는 항목과 기본값:

| 프리셋 | 지형 생성기 | 항목(기본값) |
| --- | --- | --- |
| 콘텐츠 탐험(`expedition`) | `infinite` | 생존(켬), 샌드박스(끔), 시작 건축물(켬), 사망 시 소지품 남김(켬) |
| 기본 섬(`island`) | `island` | 생존(끔), 샌드박스(켬), 시작 소지품(켬), 사망 시 소지품 남김(켬) |
| 개척 원정(`frontier`) | `frontier` | 생존(켬), 사망 시 소지품 남김(끔, 사용자 결정). 모듈 `first-signal`(0.16.0부터) |
| 기계 시험장(`machine`) | `machine-field` | 없음(생존 끔). 모듈 `machine-field`(0.17.0부터) |

- 런처는 그 프리셋의 세션이 **실제로 읽는 항목만** 보이고, 다른 항목은 저장소 계층에서 거부한다. 콘텐츠 탐험의 샌드박스는 0.15.2(S1)에서 도구·생태·문구를 일반화하고 열었다.
- 만든 뒤 바꿀 수 없는 항목(지형을 만들거나 시작 상태를 정하는 것)은 편집 화면에서 잠기고, 저장소 계층도 거부한다.
- 항목을 더할 때 이 표, `RULES`·`PRESETS`, 세션의 적용 코드, `configVersion` 변환을 함께 고친다. 더 높은 `configVersion`의 월드는 잘못 읽지 않고 "읽을 수 없음"으로 표시한다.
  - 기본값만 더하는 항목은 `configVersion`을 올리지 않는다. 그 항목이 없는 설정은 `worldConfig`가 프리셋 기본값으로 채우고, 이전 빌드는 모르는 항목을 읽지 않는다(`dropOnDeath`, 0.15.3).
- 통합 런타임은 맵 이름이 아니라 월드 설정을 받는다: `ExpeditionRuntime.create(seed, save, {config})`. 지형은 `config.terrain.generator`로 등록된 생성기(아래)에서, 규칙은 `config.rules`에서만 온다. 설정에 없는 규칙은 꺼진다. 규칙의 기본값은 `PRESETS` 한 곳에만 있다. 설정 없이 만들면(테스트·도구) 생존·시작 건축물이 켜진 전체 규칙으로 돈다.
- 규칙은 월드 저장에 복사하지 않는다. 저장에는 지형 생성기 이름(`terrain`)만 남고, 저장을 다시 열면 그 생성기를 쓴다. 0.15.1 이하 저장의 `map`(`expedition`·`island`)은 생성기 이름으로 읽는다.

### 지형 생성기 [현재, 0.15.2부터]

지형 생성기는 이름으로 등록한 모듈이다(`content-runtime/maps.js`의 `GENERATORS`). 생성기는 지형에 속한 것만 맡고, 세션 코드는 생성기 값을 읽을 뿐 이름을 비교하지 않는다.

| 생성기 | 지형 | 시작 위치 이름 | 장소 | 미니맵 | 생태 | 옛 저장 가져오기 |
| --- | --- | --- | --- | --- | --- | --- |
| `infinite` | 무한 청크(`WorldAtlas`) | 출발지 | 없음 | 플레이어 중심 160 m | 서 있는 곳의 환경 | 없음 |
| `island` | 원본 섬 생성기(`IslandAtlas`, `world.js`) | 상륙 지점 | 다섯 곳 | 섬 전체 160 m | 숲(`grove`)의 세 종 | 0.13.0 이하 섬 저장(`feral.world.v1`) |
| `frontier` | 개척 원정 지역 섬들(`FrontierAtlas`, `frontier/terrain.js`) | 원정 야영지 | 지역마다 개척 원정의 장소(`regionLandmarks`) | 플레이어 중심 160 m | 숲(`grove`)의 세 종 | 옛 개척 원정 저장(0.16.0) |
| `machine-field` | 46 m 평지 시험장(`MachineFieldAtlas`): 높이 4 m 바닥, 2 m 벽, 옛 장애물 자리의 기둥 셋, 옛 광맥 자리의 고철 더미 | 시험장 입구 | 출발 패드·고철 더미 | 시험장 64 m | 없음(생명체를 두지 않는다) | 옛 기계 시험장 저장(`feral.machine.v1`, 0.17.0) |

- 샌드박스 도구(개체 생성·근처에 24마리)와 생태 탭은 생성기의 생태를 쓴다. 생태가 없는 생성기는 그 자리의 환경 생태(초식·포식·분해의 세 역할)를 쓴다.
- 세계 패널 설명은 생성기 설명에 월드 설정(평화 규칙·사망 규칙·샌드박스)을 덧붙여 만든다.
- 생성기가 `respawn(x, z)`를 주면 쓰러진 자리에서 가까운 그 위치에서 깨어난다(개척 원정: 그 지역의 야영지). 없으면 시작 위치다.
- `frontier` [현재, 0.15.3부터, 0.16.0부터 개척 원정 프리셋]: 지역 `(rx, rz)`는 개척 원정의 지역 지형(`frontierWorld`, 마을·둥지·유적·길·작업장 그대로)을 `(rx·320, rz·320)` m에 놓은 160 m 섬이고 사이는 바다다. 지역 시드·등급은 개척 원정의 `regionInfo`와 같다. 지역 지형은 최근 6개만 메모리에 두고, 옛 개척 원정 저장에서 온 지역의 지형 버전은 지형 상태(`regionTerrain`)에 남긴다. 지역마다 야영지 둘레에 시작 채집물이 있다.

## 6. 게임 세션

### 시작 약속 [현재]

- 입력은 `play.html?world=<id>` 하나다. 세션 라우터(`game.js`)는 저장소 계층에서 그 월드의 목록 항목과 월드 설정을 읽는다.
- 세션은 월드 설정을 바꾸지 않는다. 마지막 플레이 시각(`lastPlayedAt`)만 기록한다.
- 나가기: 저장에 성공하면 런처로 돌아간다. 저장에 실패하면 나가지 않고 안내한다.

### 세션 안의 엔진 [현재, 0.17.0부터 하나]

게임 세션 안의 엔진은 **통합 런타임 하나**다(`content-runtime/`, `start(world)`로 시작, `play.html` + `shell.js` 공용 화면). 모든 프리셋이 이 위에서 돌고, 세션 라우터(`game.js`)는 엔진을 고르지 않고 이것을 시작한다. 프리셋에는 `engine` 값이 없다.

통합 런타임이 쓰는 공용 부품: `shell.js`(알림·입력·메뉴·현장 HUD·장부 창·상태/지도 페이지), `settings.js`(전역 설정 부품), `updates.js`(업데이트 화면 부품), `inventory-ui.js`(가방), `hud-editor.js`, `equipment.js`(개척 원정 채굴 공식), `physics.js`(캐릭터 이동), `world-slots.js`(월드 목록·설정). 개척 원정의 지형·캠페인 규칙(`world.js`, `frontier/terrain.js`·`campaign.js`·`content.js`)은 통합 런타임이 그대로 쓴다.

0.16.0에서 개척 원정 엔진(`main.js` 계열: `render.js`, `frontier/view.js`·`model.js`·`motion.js` 등 14개 파일)을, 0.17.0에서 기계 시험장 페이지(`machine.html`, `machine/`의 화면·모델·조립 상태)와 옛 가방·생태 코드(`inventory.js`, `acquisition.js`, `entities.js`, `anatomy.js`, `animal-art.js`, `animal-skeleton.js`)를 지웠다. 공기역학 판 모델은 `content-runtime/aerodynamics.js`로, 쿼터니언 회전은 `structure.js`로 옮겼다. 옛 아이템 그림 중 카탈로그가 다시 쓰는 것만 `item-art.js`에 남았다. `world.js`(섬 지형 생성·옛 섬 저장 읽기)와 그 `loose-voxels.js`는 저장 변환에 쓰여 남는다. `main.js`만 설명 한 줄짜리 빈 모듈로 남는다: 설치된 앱 0.3.3의 업데이트 검사가 `main.js`가 없는 패키지를 거부하기 때문이다(아래 [바꿀 수 없는 제약](#바꿀-수-없는-제약)).

### 알려진 구조 문제 [현재]

| 문제 | 위치 | 해결 단계 |
| --- | --- | --- |
| 옛 엔진을 위해 있던 주변 사건 알림(`#events`)은 지금 아무 코드도 채우지 않는다. 기계 계기(`#flightReadout`)는 0.17.0부터 조종 중에 속도·높이·출력·질량·바퀴 접지·손상을 보인다 | `play.html`, `settings.js`, `hud-layout.js` | 사건 알림은 쓸 곳을 정하거나 지운다 |

### 세션 통합 원칙 [현재, 0.17.0에서 엔진 통합 완료]

- 엔진은 `content-runtime/` 하나다(0.17.0). 다른 두 엔진의 기능은 버리지 않고 옮겼다. 목록은 [로드맵](ROADMAP.md#세션-통합-때-옮길-기능).
- 맵마다 다른 점은 두 가지로만 표현한다.
  1. 월드 설정 값
  2. 등록된 모듈 이름: 지형 생성기, 첫 신호 캠페인처럼 켜고 끄는 시스템
- 세션 코드에서 맵·프리셋 이름을 비교하지 않는다 [현재, 0.15.2부터]. `tests/launcher.test.js`가 통합 런타임과 공용 세션 화면 파일에서 맵·프리셋·생성기 이름을 담은 값의 비교(`map.id`, `config.preset`, `world.type`, `terrain.generator` 등)를 찾으면 실패한다. 옛 엔진을 고르던 세션 라우터(`game.js`)의 분기는 0.17.0에서 없앴다.
- 세션 화면 요소는 `shell.js`나 기존 공용 모듈에만 추가한다. 맵 전용 HUD·패널·알림·조작·CSS를 새로 만들지 않는다.

### 런타임 모듈 [현재, 0.15.4부터]

- 월드 설정의 `modules`(이름 목록)가 켜는 시스템이다. 등록은 `runtime.js`의 `MODULES` 한 곳이다. 모르는 이름은 세션을 시작하지 않고 오류로 알린다.
- 모듈은 `new Module(runtime, state)`로 만들고, 런타임이 고정 단계마다 `tick(dt)`를 부르고, 저장할 때 `serialize()`를 런타임 저장의 `modules.<이름>`에 넣는다. 설정에서 빠진 모듈의 저장 상태는 지우지 않고 그대로 저장한다.
- `modules`는 프리셋이 정한다(개척 원정: `first-signal`, 기계 시험장: `machine-field`). `worldConfig`가 프리셋에서 가져온다.
- 모듈은 월드에 물건을 둘 수 있다: `descriptors()`가 공용 장면 서술(`kind: 'module'`, id `<모듈>/<물건>`, VoxelAssetBuilder 에셋)을 돌려주면 런타임이 장면 목록에 더한다. 목록은 모듈 상태가 바뀔 때만 다시 만든다(리비전). 그 물건을 공격하면 런타임 공격(쿨다운·무기 내구)을 거쳐 모듈의 `strike(hit, 피해)`가 받는다.
- 모듈 화면 [현재, 0.16.0부터]: 화면 코드는 모듈 이름으로 `content-runtime/game.js`의 `MODULE_VIEWS`에 등록한다. 세션 화면은 등록된 화면마다 같은 훅만 부른다: `objective`·`waypoint`·`place`(HUD), `renderJourney`·`renderCommunity`·`mapInfo`·`renderTravel`·`milestones`(공용 장부 창의 탭), `focusCard`·`interactLabel`·`interact`(조준·상호작용), `machineCards`(공용 기계 패널의 카드, 0.17.0), `frame`(프레임마다). 맵 전용 페이지·HUD·CSS를 만들지 않고, 공용 장부 창·현장 HUD·초점 카드를 채운다.

| 모듈 | 코드 | 맡는 것 |
| --- | --- | --- |
| `first-signal` | `content-runtime/first-signal.js`(규칙·월드 물건), `first-signal-view.js`(화면), `signal-assets.js`(모양). 캠페인 자료와 순수 규칙은 `frontier/campaign.js`·`frontier/content.js`를 그대로 쓴다 | 첫 신호 캠페인: 지역별 마을·평판·외교·동맹·의뢰, 유적 중계기·회수, 수호자, 야영지 시설·작물·신호 복원·점화·반복 원정, 채집 지점, 지역 이동 |
| `machine-field` | `content-runtime/machine-field.js`(시작 장비·예제·출발점 복귀·옛 저장 변환), `machine-field-view.js`(HUD 장소·목표, 기계 패널의 시험장 카드) | 기계 시험장: 시작 장비 한 번(연구 셋·재료·연료·부품), 경량·중량 예제 기계를 출발 패드에(앞 예제와 그 조각을 대신), 기계를 출발 패드로 되돌리기. 조립·조종·충돌·수리는 통합 런타임의 기계 시스템과 공용 기계 패널(격자 조립)이 한다 |

`first-signal`의 규칙(사용자 결정: 통합 런타임 규칙):

- 지역은 `frontier` 생성기의 지역 섬이다. 플레이어가 선 섬이 현재 지역이며, 이동 버튼(식량 1개, 야영지나 섬 가장자리에서, 다시 읽기 없음)으로 옆 지역 야영지로 옮기거나 바다를 건너 도착해도 그 지역이 된다. 지역 안의 위치는 개척 원정과 같은 지역 좌표(0~160 m)로 계산한다.
- 생존은 런타임 규칙이다. 경비·수호자·유적 방어장 피해는 `runtime.hurt`로 가고(장비 피해 감소 적용, 생존을 끈 월드에서는 피해 없음), 야영 취사장 휴식은 체력과 칼로리를 채운다. 경험치·레벨·음식 버프는 없다.
- 개척 원정 아이템은 카탈로그 아이템으로 대응한다(`content-runtime/maps.js` `FRONTIER_ITEMS`, 모듈은 `ITEM_MAP`으로 다시 내보낸다). 화면은 비용·보상을 카탈로그 이름으로 보인다.

  | 개척 원정 | 통합 런타임 |
  | --- | --- |

## 7. 성능 구조 [현재, 0.15.1부터]

사용자 결정(2026-10-18): 느려진 한 장면을 임기응변으로 막지 않고, 같은 원인이 생기지 않는 구조로 고친다. 0.15.0에서 나무 한 그루를 캐다 플레이할 수 없을 만큼 느려진 원인은 한 곳이 아니었다. 칸 하나가 바뀌면 지형 충돌체·물 메시를 통째로 다시 만들었고, 분리된 덩어리가 조금만 흔들려도 지형 충돌체를 매 단계 다시 만들었다. 느린 프레임 뒤에는 고정 단계를 더 많이 돌려 더 느려졌다. 그래서 아래 다섯 원칙을 모든 엔진 시스템에 적용한다.

1. **측정이 먼저다.** 게임 안 프레임 계측 `FERAL.perf`(프레임 루프의 단계별 시간)와 장면별 측정 도구 `tools/profile-runtime.mjs`(섬 대기·걷기·나무 채굴·분리된 나무, 원정 대기·걷기)를 쓴다. 이 도구는 이전 빌드에도 같은 기준으로 돌릴 수 있다. 성능을 바꾸는 버전은 전후 수치를 `verification/<버전>-perf.json`에 남긴다.
2. **바뀐 곳만 다시 만든다.** 지형 세계(`atlas.js`)는 칸이 바뀌면 그 칸이 속한 4m 구역(8×8×8칸, `SECTION_CELLS`)을 변경 기록에 남긴다. 구역 면에 닿은 칸은 이웃 구역도 남긴다. 지형·물에서 무언가를 만드는 캐시는 이 구역 단위로 두고, `changesSince(cursor)`나 `terrainSectionRevision()`이 알려 준 구역만 다시 만든다. 전역 리비전 하나로 전체를 다시 만드는 코드를 새로 쓰지 않는다.
3. **프레임마다 쓸 시간을 정한다.** 고정 시뮬레이션 단계(1/60초)는 프레임당 최대 3번이다. 기기가 따라오지 못하면 프레임을 늦추는 대신 시뮬레이션을 느리게 한다. 청크 생성·지형 메시 같은 배경 작업은 이전 프레임이 남긴 시간(1.5~6ms) 안에서만 하고, 플레이어가 고친 청크를 새 청크보다 먼저 처리한다. 코드는 `content-runtime/frame-profiler.js`.
4. **주기적인 일을 한 프레임에 몰지 않는다.** 생물 AI는 활성 생물을 5개 조로 나눠 0.05초마다 한 조씩 처리한다. 생물 하나하나는 그대로 0.25초마다 dt 0.25초로 갱신한다.
5. **반복 경로에서 할당하지 않는다.** 칸 조회·메시 생성·충돌체 범위 계산처럼 프레임마다 수천 번 도는 곳에서는 배열·문자열·클로저를 만들지 않는다. 싼 조건을 먼저 보고, 물리 광선처럼 비싼 질의는 결과가 판단을 바꿀 때만 한다.

| 캐시 | 단위 | 다시 만드는 때 | 코드 |
| --- | --- | --- | --- |
| 지형 충돌체 | 4m 구역. 고체 칸을 정확히 덮는 큰 상자로 합친다(꽉 찬 구역은 상자 하나) | 구역이 원하는 범위에 들어올 때, 구역 안 고체 칸이 바뀔 때. 원하는 범위는 플레이어 주변과 움직이는 몸체마다의 경계 상자+여유다. 몸체가 흔들리거나 쉬어도 구역이 같으면 그대로다 | `physics.js` `terrainAt` |
| 물 메시 | 4m 구역 | 구역의 지형이나 물이 바뀔 때. 걸으면 구역을 더하고 빼기만 한다 | `environment-view.js` |
| 지형 메시 | 16m 청크 | 청크의 칸이 바뀔 때. 고친 청크 먼저, 가까운 순, 시간 예산 안 | `scene.js` `syncTerrain`, `chunkGeometry` |
| 생물 부위 충돌체 | 부위와 크기 | 부위 형상이 실제로 바뀔 때. 행렬 분해의 끝자리 오차로 다시 만들지 않도록 크기를 1/10000로 반올림한다 | `physics.js` `partShape` |
| 광역 충돌 갱신 | 물리 세계 | 몸체를 더하거나 지웠을 때, 플레이어 캡슐이 움직였을 때만 질의 전에 갱신한다 | `physics.js` `synchronize` |

충격 판정도 같은 원칙을 따른다. 플레이어가 맞는 충격(0.15.5부터)은 물리 단계마다 지형 물체·기계의 지난 포착 상태(속도·위치)로 접근 속도 4 m/s와 거리를 먼저 보고, 그때만 플레이어 캡슐과 정확한 충돌체 시험을 한다. 물체·기계가 지형·물체·기계·생명체에 부딪는 충격(0.15.8부터)은 몸체의 칸을 하나하나 훑지 않는다. 움직이는 물체·기계의 충돌체가 몸무게의 5배를 넘는 접촉 힘만 Rapier 이벤트로 알리고(`watchImpacts`), 그 쌍만 접촉 법선과 충돌 전 속도로 판정한다(`matterImpacts`·`impactPair`). 가만히 놓인 몸체는 이벤트를 내지 않으므로, 수백 칸짜리 나무가 쓰러져도 판정 비용은 칸 수가 아니라 실제 충돌 수에 비례한다. 판정은 세계 단계 뒤, 포착 전에 해서 충돌 전 속도를 쓴다. 부서진 지형 칸이 받치던 것의 분리는 물리 단계 밖의 지연 대기열(`pendingDetach`, 틱당 한 칸)에서 한다.

분리된 덩어리를 나누거나 새로 만들 때는 복셀 제작 SDK로 모델을 다시 짓는다. 0.15.7까지는 칸마다 기존 칸 전부와 겹침을 검사해(칸 수의 제곱) 548칸 나무에서 칸 하나가 떨어질 때 약 90 ms가 걸렸다. 0.15.8부터 SDK는 할당 없는 겹침 검사와 가장 긴 축을 따라 쓸어 보는 검사(sweep and prune)를 쓰고, 덩어리는 모든 칸을 한 번에 검사하는 `addBoxes`로 짓는다. 검사 규칙(같은 부위의 겹침 거부, 실패하면 아무것도 바꾸지 않음)은 같고, 무작위 상자로 모든 쌍 검사와 결과가 같음을 시험한다(`tests/asset-authoring.test.js`). 런타임 SDK(`content-runtime/voxel/`)와 에셋 파이프라인 SDK(`tools/asset-pipeline/`)는 같은 코드임을 시험으로 지킨다.

남은 문제와 다음 단계:

| 문제 | 해결 방향 | 상태 |
| --- | --- | --- |
| 지형 생성이 화면과 같은 스레드에서 돈다. 콘텐츠 탐험은 첫 로딩 뒤 주변 청크를 다 채우는 데 약 30초가 걸린다(예산 안에서 돌아 프레임은 지킨다) | 지형 생성을 웹 워커로 옮긴다 | 목표 · 엔진 통합 뒤([로드맵](ROADMAP.md) P2) |
| 생물 AI 자체의 비용(시야 광선·지형 조사)이 생물 수에 비례한다 | 거리별 갱신 빈도(LOD). 먼 생물의 행동이 달라지므로 게임 규칙 변경으로 사용자 확인 후 | 목표 · 엔진 통합 뒤(P2) |
| 기계 물리 다리(`machine-physics.js`)는 프레임마다 기계 하나의 질량 분포를 JSON으로 비교한다(연료가 타며 질량이 바뀐다). 충돌체 모양 비교는 0.17.0부터 기계 리비전이 바뀔 때만 한다 | 질량도 바뀐 기계만 다시 계산 | 목표 · P2 |

### 바꿀 수 없는 제약

- 앱 0.3.3은 게임 업데이트 하나에 파일 128개까지 받는다(`UpdateCore.MAX_FILES`). `tests/unified-game.test.js`가 여유 4개 이상을 확인한다. 0.15.8까지 124개로 여유가 없었고, 0.16.0에서 옛 개척 원정 엔진 파일을 지워 112개, 0.17.0에서 기계 시험장 페이지와 옛 가방·생태 코드를 지워 103개가 됐다.
- 앱 0.3.3의 업데이트 검사는 패키지에 `main.js`와 `version.js`가 있어야 받는다(`UpdateCore.java`). 그래서 엔진을 지운 뒤에도 `main.js`를 빈 모듈로 둔다. 이 검사를 없애려면 새 APK가 필요하다.
- Android WebView는 앱 내부 주소의 파일 형식을 확장자로 정한다. `.mjs`처럼 등록되지 않은 확장자는 모듈로 불러올 수 없다(0.12.1 원인). 검증은 앱과 같은 규칙의 `tools/android-asset-server.mjs`로 한다.
- 업데이트는 전체 버전 단위로 검증하고 다음 실행에 적용한다. 부분 파일 교체와 플레이 중 자동 재시작은 하지 않는다. 절차는 [배포](RELEASING.md).
