# Native rewrite integration contract (implementation work, 2026-11-08)

The user's target is the entire game, not a demo or a reduced replacement. Preserve the four world presets, saved worlds and material semantics. Native runtime: Godot 4.6.3 + C++ GDExtension. All gameplay is C++; Godot provides native rendering, one physics world and Control UI. No JavaScript game runtime, no GDScript gameplay. JS may export the existing canonical authored data at build time and read the old WebView storage once for migration only.

Shared pure C++ types are `src/common.hpp`, namespace `feral`, `Json` = nlohmann::json. Headless unit tests compile with `g++ -std=c++17 -Inative/src -Inative/third_party`. Godot adapter alone includes godot-cpp headers. Do not edit another owner's files, root build metadata, shipped legacy assets, or version files without coordination. Do not commit or push independently. No agent runs the full old test suite or full performance scenarios. Add meaningful focused tests for your subsystem.

Data: root will export complete canonical CONTENT into `native/data/content.json`, keyed authored assets into `native/data/assets.json`, presets into `native/data/presets.json`. `Content::index()` supplies global lookup by item/block/etc ID. Inspect the legacy JS for exact behavior and state schemas, not just docs.

Interfaces to implement (extend deliberately and notify root):

* `World` in world.hpp/cpp: `World(const Content&)`; `configure(Json config)`; `load(Json state)`; `save() -> Json`; `block(Cell)->string`; `set_block(Cell,string)`; `surface_height(double x,double z)->double`; `stream(Vec3 player,int radius=2)`; `raycast(Vec3 origin,Vec3 direction,double reach)->Contact`; `damage(Contact,double amount)->Json`; `detach(Cell)->vector<string>`; `bodies() -> map<string,BodyState>&`; `terrain_boxes(Cell section)->vector<Box>`; `mesh(Cell section)->MeshData`; `dirty_sections()->vector<Cell>` (consumes pending dirtiness); `loaded_sections()->vector<Cell>`. MeshData has vertices/normals/colors vectors of Vec3 and indices vector<uint32_t>. World voxels are 0.5 m; sections are 4 m. Preserve actual empty space; do not fill it with coarse collision AABBs. Use exact merging and exposed-face meshing. Root adapter owns Godot body lifetimes/poses.
* `Actions` in actions.hpp/cpp: accepts input intent, advances an independent fixed simulation timeline, emits point-hit or swept-volume queries. Rendering gets a read-only pose from the same clock. Root invokes contact resolver and applies hit results; gameplay must never be driven by displayed animation callbacks. Define clear standalone API and notify root immediately. Include data-driven editable profiles; built-ins pick/knife/axe/sword/spear/hammer. Same-cell dedup and an attack energy budget, bounded angular sweep subdivision, occlusion/reach semantics. Point attack has a configured hit time; sweep attacks have active intervals and moving hit volumes. Tests cover skipped render frames, boundaries and no repeated full damage.
* `Gameplay` in gameplay.hpp/cpp: `Gameplay(const Content&)`; `configure(Json config)`; `load(Json state)`; `save()->Json`; `tick(double dt)`; `command(string name,Json args)->Json`; `view()->Json`; `count(string id)->double`; `grant(Json items,string claim="")->Json`; `spend(Json items,string claim="")->Json`. Own inventory/equipment, research/craft jobs, placements/energy/logistics, community/faith, campaign records and game rules. Public API command result always includes ok/reason. Preserve all catalog entries and enable UI to reach all supported commands. Give root a complete command list and what fields require UI. Do not implement placeholder success or discard unhandled saved data.
* `Simulation` in simulation.hpp/cpp: `Simulation(const Content&)`; `configure(Json config)`; `load(Json state)`; `save()->Json`; `tick(double dt,Vec3 player,World&,Gameplay&)`; `command(string name,Json args,World&,Gameplay&)->Json`; `view()->Json`. Own creatures/AI/ecology/body damage/corpses, dungeons/devices/bosses, machine assemblies/forces, first-signal world modules and field examples. Typed entity/force/pose interfaces may be added; root integrates rendering and the single Godot physics world. Report unsupported requirements honestly and implement, do not simulate them with fake success.
* `Storage` in storage.hpp/cpp: native atomic world catalogue/snapshots, authoritative state schema and lossless legacy conversion; C++ std::filesystem/JSON. Define API early. Preserve source/unknown fields, never delete or reset legacy saves. Own Android migration bridge/plugin in `native/android/` if needed; coordinate SDK/Gradle with build agent. Native schema wraps subsystems + source world config. Root supplies actual gameplay payload and attaches migration UI.
* Build owner: native/SConstruct, native/project.godot, native/feral.gdextension, native/main.tscn, native/export_presets.cfg, tools/native build scripts and pinned dependency bootstrap. Root owns src/register_types.*, src/feral_game.* and generated data exporter. Extension entrypoint `feral_library_init`; registered root class `FeralGame : Node3D`. Android package `com.kgb.feral`, keep existing shared test signing key; new native version will be selected by root. Main scene root custom FeralGame. Desktop and Android arm64 builds must execute native code. Godot headless integration smoke mode to be supplied by root.

Root owns rendering, Godot physics integration, input and game UI, version/release changes and final verification.
