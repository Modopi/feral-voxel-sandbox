# 0.12.0 화면 연결 검증

게임 0.12.0 / 1200, 네이티브·최소 네이티브 0.3.3 / 303, 저장 스키마 2. 이미 구현된 기능을 화면·입력·알림에 연결한 버전이다. 연결 목록과 근거는 [화면 연결 감사](../docs/UI-REACHABILITY.md)에 있다. 이 기록은 전체 기획 Goal 완료 판정과 구분한다.

## 실행 환경

- Linux 개발 환경, Node 22. 브라우저는 Playwright Chromium(SwiftShader WebGL)이며 Android 기기가 아니다.
- 로컬 Android SDK Platform 35 / Build Tools 35.0.0으로 APK를 빌드했다.

## 자동 검사

- 전체 회귀: `node --test tests/*.test.js` — **502개 모두 통과**, 건너뜀0·실패0([기록](0.12.0-local-tests.log)). 0.11.0의 496개에 신규 6개를 더했다. 이 실행은 version.json을 올리기 전 코드로 했고, 버전 변경 뒤 버전·업데이트 패키지·런타임 콘텐츠·신규 검사 21개를 다시 실행해 통과했다. 병합 커밋에서 GitHub CI가 전체를 다시 실행한다.
- 신규 `tests/ui-reachability.test.js` 6개:
  - 실패 코드 250종의 한국어 안내 전수 검사.
  - 제작 취소와 재료 반환, 우선 진행, 막힌 이유.
  - 연구 일시정지·재개(표본 재지불 없음).
  - 던전 공급선 분리(철거된 공급 설비 포함)와 구조 부품 복구, 저장 유지.
  - 보스·생명체·던전·공동체 이벤트의 알림·경고.
  - 바라보는 전장 장치의 근접 파괴, 압축 날개바람 밀림 1m 이하.
- 에셋 하네스 `node tools/check-visual-assets.mjs`: 119개 모델, 재현성·충돌·점유 계약 통과. 에셋 원본은 바뀌지 않았다.
- `node tools/build-runtime-content.mjs --check`: 6문서·119모델, 생성 파일 일치.

## 실제 입력 경로

`tools/verify-ui-reachability.mjs` — [보고서](0.12.0-ui/report.json). 콘텐츠 탐험은 390×844 터치, 기본 섬은 900×412 터치 화면에서 실행했다. 페이지 오류는 0건이다.

기존 [터치 레이아웃 검사](0.12.0-ui/touch-layout/report.json)도 390×844·844×390·360×640에서 다시 실행했다. 조작부가 화면 안에 있었고, 시점·조이스틱·메뉴 일시정지·저장 재접속을 확인했다.

준비 단계에서 지급한 자원과 순간 이동은 정상 성장의 증거가 아니다. 보스 장치 파괴와 이벤트 알림은 모델 검사로 확인했고, 실제 보스전 화면 완주는 아니다.

## 빌드와 패키지

- `bash build-apk.sh`: `Feral-0.3.3-android.apk` 빌드와 v2/v3 서명 확인([로그](0.12.0-apk-build.log)). 네이티브 코드 변경이 없어 앱 0.3.3 / 303을 유지한다.
- `python3 tools/build-update.py`: 서명 업데이트 120개 파일, ZIP 2,796,223바이트, 해제 11,511,187바이트. 네이티브 한도(128파일·압축 8MiB·해제 32MiB) 안이다.
- APK에 동봉된 게임 파일 120개와 업데이트 패키지 파일이 모두 바이트 단위로 같다. [측정값](0.12.0-package.json)
- 새 파일은 `content-runtime/reasons.js`, `content-runtime/anchor-markers.js` 두 개다. 0.11.0의 118개에서 120개가 됐다.

## 남은 검증

- Android 실기기의 터치 크기·표시, 프레임·메모리·발열, 장시간 세션.
- 휴대폰 앱에서의 0.12.0 업데이트 적용·재시작·저장 복원.
- 공개 게시 결과는 병합 후 이 문서에 이어 기록한다.
