## 원인과 재현

사용자 신고는 **콘텐츠 탐험**에서 나무 세 그루를 분리한 뒤, 추가 행동을 하지 않아도 게임이 급격히 느려지는 현상이다. 이전 섬 나무 검사에서는 나무가 똑바로 내려앉고 잠들어 이 경로를 놓쳤다.

0.18.1 / 1810, seed 63026, 0.5 m 셀 좌표 `[-7,8,25]`, `[26,8,25]`, `[-26,8,-27]`의 줄기 아래층을 제거하고 실제 `detachAround()`로 나무 세 그루(260 / 284 / 260칸)를 분리했다. 두 번째 나무가 넘어지는 충격으로 잎 한 칸(7.5 kg)이 떨어졌다.

1. 잎은 원래 비고체라 Rapier의 동적 sensor가 된다. 중력은 받지만 지면과 접촉하지 않는다.
2. 물체 활성 범위가 XZ 거리만 보므로, 플레이어 발밑 수백·수천 m로 내려가도 계속 계산된다.
3. `bodyBounds()`가 센서를 고체처럼 취급해, `terrainAt()`가 떨어지는 잎 주위 지하 충돌 구역을 계속 생성·제거한다. 지형 변경은 질의 갱신을 위한 추가 `worldStep(1e-6)`도 유발한다.
4. 낙하가 가속될수록 쓸모없는 지형 작업이 늘어난다. 단순히 나무 객체 세 개를 그리는 비용이 아니었다.

카메라·플레이어·나무 세 그루를 유지한 채 문제 잎만 제거·복원한 대조 실험으로 인과 관계를 확인했다([원시 기록](0.18.2-cause-ablation.json)). 제거는 진단용 임시 브라우저 상태에만 적용했으며 최종 패치에서는 재료를 삭제하지 않는다.

| 잎 상태 | JS 루프 평균 | 지형 구역 생성 | 관찰 시간 |
| --- | ---: | ---: | ---: |
| 낙하 중 | 33.56 ms | 3,706회 | 10초 |
| 잎만 제거 | 13.90 ms | 0회 | 6초 |
| 동일 잎 복원 | 40.13 ms | 3,504회 | 6초 |
| 잎 다시 제거 | 16.12 ms | 40회 | 6초 |

첫 제거 후와 복원 후의 렌더 카운터는 모두 481 calls / 69,766 triangles였다. 복원 시 세 나무는 모두 잠든 상태였다. 첫 제거 직전 잎 높이는 -824.67 m, 복원 관찰 후 -1,591.15 m였다. 테스트는 Chromium SwiftShader이며 Android 실기기나 GPU 시간의 측정이 아니다.

## 수정

- `physics.js`: 지형과 구조물의 충돌 요구 범위에서 sensor를 제외한다. 고체·센서 혼합 몸체는 고체만으로 경계를 계산하고, 센서만 있는 몸체는 지형 요구 범위를 만들지 않는다.
- `object-physics.js`: 비고체 파편만 플레이어에서 원점까지의 3차원 64 m 범위에서 계산한다. 멀어지면 물리 몸체만 제거하고 칸·질량·자세·속도를 저장한다. 다시 접근하면 같은 물체로 활성화한다. 이미 지하에 떨어진 파편이 있는 저장에도 적용한다.
- 고체를 포함한 물체는 기존 수평 64 m 규칙을 유지한다. 원점은 멀지만 일부가 플레이어 근처에 있는 긴 고체의 충돌을 없애지 않는다. 고체 포함 여부는 칸 배열이 바뀔 때만 다시 계산한다.
- `tools/profile-runtime.mjs debris`: 콘텐츠 탐험에서 나무 세 그루를 분리한 뒤 실제 `damageAt(knockLoose)`로 잎 한 칸을 분리하고 30초간 기록한다. 바닥 절단·카메라 이동은 준비 상태이며 실제 터치 채굴 완주 증거로 표현하지 않는다. 파편이 저절로 생길 때까지 기다리는 대신 실제 파손 함수를 써 재현 조건을 고정한다.

## 네이티브 검토의 범위

현재 Java WebView 진입점, Three.js 렌더러, Rapier Wasm, APK 빌드와 서명된 자산 업데이트 경로를 확인했다. Android NDK로 C++/Rust 계산 코어를 ARM64 기계어 `.so`로 빌드·실행할 수 있다. 기존 JS/DOM/Three.js 전체를 그대로 컴파일하는 방식은 아니며, 상태 소유권·JNI/WebView 전달·렌더링·저장 연결을 이식해야 한다. 새 네이티브 코드에는 새 APK가 필요하다. Android용 네이티브 바이너리의 로딩·실행이나 네이티브 전환 성능은 아직 검증하지 않았다.
