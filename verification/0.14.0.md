# 0.14.0 기본 섬의 통합 런타임 이식 검증

게임 0.14.0 / 1400, 네이티브·최소 네이티브 0.3.3 / 303, 저장 스키마 2. 게임 파일만 바꾼 릴리스다. 기준은 [하나의 게임으로 통합](../docs/UNIFIED-GAME.md)의 P2 완료 기준이다.

## 바뀐 구조

- `game.js`가 기본 섬(`island`)과 콘텐츠 탐험(`expedition`)을 모두 `content-runtime/game.js`로 시작한다. 개척 원정만 아직 `main.js`이고 기계 시험장은 `machine.html`이다.
- 맵 설정 `content-runtime/maps.js`가 지형 생성기·규칙·시작 소지품·장소·지역 범위만 정한다. 생명체·아이템·연구·제작·저장·화면은 같은 `ExpeditionRuntime`과 공용 화면을 쓴다.
  - `IslandAtlas`는 원본 섬 생성기(`world.js`의 `World.generate()`)가 만든 칸을 그대로 읽고, 원본 블록 번호를 설계 블록으로 대응한다(`LEGACY_BLOCKS`). 섬 밖은 바다다.
  - 섬 규칙은 평화(체력·식량 고정)·샌드박스(관찰·물·불·산·개체 생성·24마리, 캔 자원으로 블록 쌓기)·시작 건축물 없음이다. 생태는 설계 데이터 숲 환경의 같은 세 종(이끼사슴·구리여우·청금딱정)이다.
- 기존 섬 저장(`feral.world.v1`, `feral.slot.<id>`, 형식 1·2)은 처음 열 때 한 번 변환한다. 원본 키는 그대로 두고, 원본 로더가 만든 지형과 새로 생성한 섬을 칸 단위로 비교해 다른 칸만 옮긴다. 대응되는 아이템·위치·발견 장소를 옮기고, 옮기지 못한 항목은 저장의 `conversion`과 여정 페이지에 남는다.
- 섬의 채집·채굴은 설계 데이터를 따른다. 돌·원목·모래는 캐면 자원이 되고, 흙·잔디는 원자재가 없어 부수면 사라진다.
- 업데이트 파일은 123개다(앱 상한 128개).

## 검증

- 전체 회귀 `node --test tests/*.test.js`: **518개 모두 통과**, 실패 0([기록](0.14.0-local-tests.log)). 0.13.0의 512개에 신규 `tests/island-map.test.js` 6개를 더했다.
  - 설계 대응표: 기존 블록·아이템·종이 실제 설계 항목을 가리키고, 섬 숲 환경에 같은 세 종이 있는지 확인한다.
  - 섬 지형: 통합 런타임의 섬이 원본 섬 생성기와 격자 2만여 칸·청크 표본에서 같은 칸을 만들고, 섬 밖은 바다이며, 시작 건축물이 없고, 생명체·채집 지점이 섬 안에 있으며, 시작 소지품이 섬 설정과 같은지 확인한다.
  - 평화 규칙과 저장: 피해·이동 후에도 체력·식량이 그대로이고, 맵·발견 장소가 저장과 복원 뒤 유지되며, 콘텐츠 탐험은 생존 규칙을 유지한다.
  - 기존 섬 저장 변환: 원본 객체를 바꾸지 않고, 바뀐 칸·판자·아이템(광석 결정 → 철 원광, 나무 곡괭이 → 돌 곡괭이)·위치·발견 장소를 옮기며, 화살·펄스 무기·부은 물·동물 개체를 목록에 남기고, 변환 결과가 저장·복원된다. 새 월드 시작 소지품을 더하지 않는다.
  - 블록 쌓기: 샌드박스 맵에서 캔 자원 0.5 m 칸당 1개(1 m는 8개), 이미 찬 칸·캐릭터와 겹치는 칸 거부, 쌓을 수 없는 아이템 거부, 콘텐츠 탐험은 블록을 쌓지 않음. 물이 든 칸에 놓으면 물을 위로 밀어내 부피가 보존된다.
  - 기존 회귀의 새 실패 코드(`not_buildable`)에도 한국어 안내가 있다.
- 하나의 게임 화면 검증 `tools/verify-ui-reachability.mjs`: 앱과 같은 MIME·CSP 규칙의 서버에서 17개 경로를 실제 터치로 확인했고 페이지 오류는 0건이다([보고서](0.14.0-ui/report.json)). 콘텐츠 탐험 9개·개척 원정 1개·공통 1개는 0.13.0과 같은 경로이고, 기본 섬은 6개다.
  - 기존 섬 저장 변환: 0.13.0 형식 저장(판자 발판·들열매·화살·동물 20마리)을 넣고 열면 같은 런타임의 섬으로 시작하고, 판자 발판과 들열매가 옮겨지며, 원본 키 길이가 그대로이고, 두 세대 저장이 생기며, 옮기지 못한 아이템·동물이 여정 페이지에 보인다. 평화 규칙이라 체력·식량 표시가 없다([여정](0.14.0-ui/island-journey.png)).
  - 빈 손 관찰 렌즈, 메뉴의 물 붓기 도구와 사용 버튼, 핫바의 주운 돌로 0.5 m 블록 놓기, 미니맵 설정과 장소 발견 알림([섬](0.14.0-ui/island.png)).
  - 새 섬: 시작 소지품(돌 곡괭이 1·미가공 목재 4·주운 돌 4·씨앗 4), 공용 스틱으로 4.1 m 이동, 공격 버튼 16회로 잔디 칸 파기, 생태 탭의 24마리 버튼(30 → 54마리), 메뉴 저장 후 다시 열기에서 섬 맵·파낸 칸·위치·소지품·발견 장소 유지([새 섬](0.14.0-ui/island-new.png)).
- 기존 화면 검사 `tests/*-check.cjs` 19개를 저장소 루트에서 다시 실행했다(경로·포트가 루트 기준인 검사라 0.13.0과 같은 방식). 커밋된 예전 검증 이미지는 실행 뒤 원래대로 되돌렸다.

  - updates-ui와 machine은 기본 섬이 통합 런타임으로 옮겨져 단언을 고쳤다. updates-ui: 섬은 시작 버튼 없이 바로 시작하고, 적용 전 저장은 두 세대 저장(`feral.world.v1.a/.b`)의 세대 번호가 올라가는지로 확인한다. 앱에 보내는 시작 성공 보고(게임 코드 1400)는 그대로 통과한다. machine: 새 섬 월드의 시드 123이 통합 런타임(`FERAL.runtime.seed`)과 섬 맵에 전달되는지 확인한다.
  - browser-check·progression-check는 기존 섬 엔진(`main.js` 섬 모드)의 API·좌표·흙 조각·망치 연구를 확인하는 검사다. 섬이 그 엔진을 쓰지 않으므로 0.13.0까지의 기록으로 남기고(파일 머리에 표시), 섬의 시작·이동·땅 파기·저장 복원은 위의 통합 화면 검증과 `tests/island-map.test.js`에서 확인한다. 개척 원정이 쓰는 기존 엔진 기능은 개척 원정 검사들이 계속 확인한다.

## 빌드와 패키지

- `bash build-apk.sh`: APK 빌드와 v2/v3 서명 확인([로그](0.14.0-apk-build.log)).
- `python3 tools/build-update.py`: 서명 업데이트 123개 파일(앱 상한 128개), ZIP 2,816,521바이트, 해제 11,563,288바이트. 새 파일은 `content-runtime/maps.js` 하나이고 `.mjs` 파일은 없다.
- APK 동봉 게임 파일과 업데이트 패키지 파일이 바이트 단위로 같다. 패키지 SHA256 `0328f681…1235`, 내부 아카이브 SHA256 `0383b3c6…0046`(로컬 공유 시험 키 서명, 병합 후 CI가 다시 빌드해 게시). [측정값](0.14.0-package.json)
- `node tools/build-runtime-content.mjs --check`, `npm run audit:design`(오류 0), `npm run check:assets` 통과. 콘텐츠 데이터와 에셋 원본은 바뀌지 않았다.

## 남은 검증과 범위

- Android 실기기에서 0.14.0을 업데이트한 뒤 기존 섬 저장 변환과 섬의 터치 조작을 확인해야 한다. 데스크톱 SwiftShader 결과는 휴대폰 결과를 대신하지 않는다.
- 개척 원정(첫 신호 캠페인·마을·지역·기계 비행·운반·충격 피해)은 아직 기존 런타임(`main.js`)이다. 다음 단계 0.15.x에서 같은 방식으로 옮기고 저장을 변환한다. 기계 시험장과 기존 런타임 은퇴는 0.16.x.
- `main.js`에 남은 섬 전용 분기(섬 지형 생성·샌드박스 도구)는 더 이상 실행되지 않으며, `main.js`와 함께 0.16.x에서 삭제한다.
- 조준 대상 정보 카드(월드에 고정된 라벨)가 가까운 대상을 내려다볼 때 오른쪽 위 지도·상태 버튼과 겹칠 수 있다. 0.13.0 콘텐츠 탐험부터 있던 표시 방식이며 후속 과제로 남긴다.
