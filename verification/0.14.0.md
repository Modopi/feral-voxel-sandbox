# 0.14.0 개척 원정 감각의 통합 런타임과 기본 섬 이식 검증

게임 0.14.0 / 1400, 네이티브·최소 네이티브 0.3.3 / 303, 저장 스키마 2. 게임 파일만 바꾼 릴리스다. 기준은 [하나의 게임으로 통합](../docs/UNIFIED-GAME.md)의 P2 완료 기준과, 사용자 결정으로 추가한 "화면·감각은 개척 원정 기준"이다.

## 바뀐 구조

- `game.js`가 기본 섬(`island`)과 콘텐츠 탐험(`expedition`)을 모두 `content-runtime/game.js`로 시작한다. 개척 원정 맵은 아직 `main.js`이고 기계 시험장은 `machine.html`이다.
- 맵 설정 `content-runtime/maps.js`가 지형 생성기·규칙·시작 소지품·장소·지역 범위와, 설계 블록의 채굴 분류(흙·나무·돌·광석)·채굴 산출·설계 도구의 개척 원정 도구 대응표를 둔다.
  - `IslandAtlas`는 원본 섬 생성기(`world.js`)가 만든 칸을 그대로 읽고, 원본 블록 번호를 설계 블록으로 대응한다. 섬 밖은 바다다.
  - 섬 규칙은 평화·샌드박스(관찰·물·불·산·개체 생성·24마리, 캔 자원으로 블록 쌓기)·시작 건축물 없음이다. 생태는 설계 데이터 숲 환경의 같은 세 종이다.
- 채굴(`runtime.mine`·`mineObject`)과 즉시 채집(`runtime.harvest`)이 런타임에 있고, 공격은 지형·분리된 덩어리에서는 채굴, 생명체에서는 타격이다. 지형 상처는 칸의 캔 비율로 저장한다(0.14 이전 저장의 남은 HP는 읽을 때 비율로 바꾼다).
- 생명체 상처는 `creatures.js`의 부위별 상처 상자(부위 좌표)로 저장하고, `creature-animation.js`가 외피 상자에서 상처를 빼고 골격 상자를 만든다. 골격은 외피 박스 안쪽에만 두고 얇거나 듬성한 부위(뿔·귀·꼬리)에는 두지 않는다.
- 공용 `shell.js`에 `renderCharacterSheet`(상태 페이지)와 `renderMapPage`(지도 페이지)를 두고 `frontier/view.js`와 `content-runtime/game.js`가 함께 쓴다. 런타임 장면은 개척 원정의 `firstPersonHands`를 쓴다.
- 기존 섬 저장(`feral.world.v1`, `feral.slot.<id>`, 형식 1·2)은 처음 열 때 한 번 변환한다. 원본 키는 그대로 두고, 바뀐 칸·반쯤 캔 칸의 균열·대응되는 아이템(흙 조각 → 흙)·위치·발견 장소를 옮긴다. 옮기지 못한 항목은 저장의 `conversion`과 여정 페이지에 남는다.
- 설계 데이터: 원천 16개의 시간을 0으로, 아이템 `soil`(흙)과 원천 `source_soil`을 추가했다. 업데이트 파일은 123개다(앱 상한 128개).

## 검증

- 전체 회귀 `node --test tests/*.test.js`: **526개 모두 통과**, 실패 0([기록](0.14.0-local-tests.log)). 0.13.0의 512개에 신규 `tests/island-map.test.js` 6개와 `tests/frontier-feel.test.js` 8개를 더했다.
  - 개척 원정 감각: 공용 채굴 공식이 개척 원정 숫자와 같고, 섬에도 있던 블록은 개척 원정 경도를 쓴다. 채집 지점은 즉시 아이템을 주고 재생 전에는 다시 얻을 수 없다. 흙·잔디 2번, 원목 3번, 돌 4번(돌 곡괭이 2번), 철 원광 돌 곡괭이 3번, 원목 돌 절삭도구 2번에 칸이 빠지고 도구는 칸이 빠질 때마다 닳는다. 1 m 채굴은 8칸을 3번에 파고 흙 8개와 씨앗 1개를 준다. 분리된 원목 덩어리는 맨손 3번에 한 칸이 깎이고 남은 덩어리는 물체로 남는다. 0.14 이전 저장의 지형 남은 HP는 비율로 바뀐다.
  - 생명체 층 구조: 사슴 몸통의 척추·갈비뼈가 모두 외피 박스 안에 있고 뿔에는 뼈가 없다. 맨손 타격은 12.5 cm 폭·6.25 cm 깊이로 타격 방향을 따라 깎는다. 외피 타격은 외피 장갑만 줄이고 다리뼈는 그대로이며, 드러난 뼈를 치면 다리뼈가 상한다. 상처는 저장·복원된다.
  - 기본 섬: 대응표, 원본 생성기와 같은 섬 지형, 평화 규칙과 저장, 기존 저장 변환(반쯤 캔 칸의 균열 포함), 블록 쌓기, 물 밀어내기.
  - 바뀐 기존 테스트: 채집 시간 테스트는 즉시 채집과 도구·환경·재생·중복 방지 확인으로, 지형 채굴 테스트 2개는 개척 원정 규칙(0.18초 간격·저장 후 균열 유지)으로 고쳤다.
- 하나의 게임 화면 검증 `tools/verify-ui-reachability.mjs`: 앱과 같은 MIME·CSP 규칙의 서버에서 17개 경로를 실제 터치로 확인했고 페이지 오류는 0건이다([보고서](0.14.0-ui/report.json)). 콘텐츠 탐험 9개·개척 원정 1개·공통 1개·기본 섬 6개.
  - 새 섬(공격·캐기·상호작용 버튼 실제 터치): 시작 소지품, 스틱 이동, 잔디 칸을 **2번**에 파기, 나뭇가지 앞에서 상호작용 한 번에 미가공 목재 4 → 5, 옆에 세운 사슴의 옆구리를 공격 버튼으로 5번 쳐서 외피 상처 2개와 몸통 뼈 체력 17 → 5, 메뉴 저장 후 다시 열기에서 섬 맵·파낸 칸·위치·소지품·발견 장소·사슴 상처 2개 유지([사슴 상처](0.14.0-ui/island-creature-wound.png), [새 섬](0.14.0-ui/island-new.png)). 사슴 배치와 위치 고정, 플레이어 순간 이동은 준비 단계로 보고서에 적었다.
  - 기존 섬 저장 변환과 여정 목록([여정](0.14.0-ui/island-journey.png)), 빈 손 관찰, 메뉴의 물 붓기 도구, 핫바의 주운 돌로 0.5 m 블록 놓기, 미니맵 설정과 장소 발견([섬](0.14.0-ui/island.png)).
  - 콘텐츠 탐험: 지도 버튼이 개척 원정과 같은 지도 페이지(지도+목적지 표시)를 열고, 여정 탭에 보상 회수 기록이 남는다. 나머지 경로는 0.13.0과 같다.
  - 개척 원정: 공용 상태 페이지·지도 페이지로 바꾼 뒤에도 현장 HUD·장부 창·가방이 그대로 동작한다.
- 기존 화면 검사 `tests/*-check.cjs` 19개를 저장소 루트에서 다시 실행했다(경로·포트가 루트 기준인 검사라 0.13.0과 같은 방식). 커밋된 예전 검증 이미지는 실행 뒤 원래대로 되돌렸다.

  - browser-check·progression-check는 기존 섬 엔진(`main.js` 섬 모드)의 API·좌표·흙 조각·망치 연구를 확인하는 검사다. 섬이 그 엔진을 쓰지 않으므로 0.13.0까지의 기록으로 남기고(파일 머리에 표시), 섬의 시작·이동·땅 파기·저장 복원은 위의 통합 화면 검증과 `tests/island-map.test.js`·`tests/frontier-feel.test.js`에서 확인한다.

## 남은 검증과 범위

- Android 실기기에서 0.14.0을 업데이트한 뒤 채굴·채집·생명체 상처·기존 섬 저장 변환·터치 조작을 확인해야 한다. 데스크톱 SwiftShader 결과는 휴대폰 결과를 대신하지 않는다.
- 개척 원정 맵(첫 신호 캠페인·마을·지역·기계 비행·운반·충격 피해)은 아직 기존 런타임(`main.js`)이다. 0.15.x에서 같은 감각을 유지하며 옮긴다. 기계 시험장과 기존 런타임 은퇴는 0.16.x.
- 생명체 상처의 한계: 뼈가 부러져 떨어져 나간 부위 조각은 상처 없는 원래 모양으로 떨어진다. 개척 원정처럼 뼈와 끊긴 외피 조각이 따로 떨어지는 처리는 아직 없다.
- 분리된 덩어리의 렌치 고정·복셀 붙이기·운반 무게 규칙은 개척 원정에만 있다(0.15.x 개척 원정 이식 때 옮긴다).
- 조준 대상 정보 카드(월드에 고정된 라벨)가 가까운 대상을 볼 때 오른쪽 위 지도·상태 버튼과 겹칠 수 있다(0.13.0부터 있던 표시).
- `main.js`에 남은 섬 전용 분기는 더 이상 실행되지 않으며, `main.js`와 함께 0.16.x에서 삭제한다.
