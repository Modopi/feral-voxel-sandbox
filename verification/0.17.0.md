## 바뀐 것

- 바퀴 접지(`content-runtime/machines.js` `WHEEL_DRIVE`, `machine-physics.js`): 전에는 Rapier 물리에서 바퀴 기계가 움직이지 않았다(모든 복셀이 마찰 0.6으로 땅에 끌렸고 바퀴 모형이 없었다, 측정 아래). 이제 바퀴마다 땅을 찾아 서스펜션 힘으로 기계를 받치고(복셀이 땅에 닿지 않아 지형 구역 이음매에서 튀지 않는다), 땅에 닿은 바퀴로 견인·옆 미끄럼 방지·조향을 준다. 바퀴 복셀은 마찰이 없다.
- `MachineSystem`: `importDesign`(이미 지은 기계를 가방에서 꺼내지 않고 들여옴: 저장 변환·시험장 예제), `place`(출발 패드로), `removeMachine`(시험장 예제 정리), `wheelsOnGround`(계기).
- `content-runtime/maps.js`: 지형 생성기 `machine-field`(`MachineFieldAtlas`)와 옛 시험장 저장 가져오기.
- `content-runtime/machine-field.js`(새 파일): 시작 장비 한 번, 경량·중량 예제, 출발 패드로, 옛 시험장 저장 변환 `applyLegacyMachineField`.
- `content-runtime/machine-field-view.js`(새 파일): HUD 장소·목표, 기계 패널의 시험장 카드.
- `content-runtime/machine-panel.js`: 격자 조립(층·도구·재료, 칸 누르기로 배치·회수·수리·선택), 모듈 카드 훅.
- `content-runtime/game.js`: 모듈 화면 `machine-field`, 기계 계기(조종 중 여정 줄 자리), `FERAL.machinePanel`(검사용).
- `world-slots.js`·`game.js`: 기계 시험장 프리셋을 통합 런타임으로, 프리셋의 `engine`과 라우터의 엔진 분기 삭제, 월드를 지우면 늘 `.a`/`.b`도 지운다.
- 삭제: `machine.html`, `machine/view.js`·`model.js`·`assembly-state.js`·`style.css`, `inventory.js`, `acquisition.js`, `entities.js`, `anatomy.js`, `animal-art.js`, `animal-skeleton.js`. 옮김: `machine/aerodynamics.js` → `content-runtime/aerodynamics.js`, 쿼터니언 회전 → `structure.js`. `item-art.js`는 카탈로그가 다시 쓰는 그림만 남겼다(같은 아이템의 그림 출력이 바이트 단위로 같음을 확인). `inventory-ui.js`의 옛 카탈로그 기본값, 옛 시험장 CSS(`.machineShell`), 옛 개척 원정 조립 격자 CSS를 지웠다.
- 업데이트 파일 112개 → 103개(앱 한도 128).

## 성능 측정

같은 도구로 0.16.0(공개된 main 체크아웃에서 서빙)과 0.17.0을 차례로 쟀다([측정](0.17.0-perf.json)). 0.16.0은 기계 시험장을 옛 페이지로 열어 기계 장면이 없다. Chromium SwiftShader 수치이며 실기기 수치가 아니다. 프레임 루프의 JS 작업(`FERAL.perf`)과 물리 단계(`physics.step`)의 프레임당 시간이다.

| 장면 | 루프 JS 0.16.0 | 루프 JS 0.17.0 | 물리 단계 0.16.0 | 물리 단계 0.17.0 |
| --- | --- | --- | --- | --- |
| 섬 대기 | 16.9 ms | 15.5 ms | 3.24 ms | 2.46 ms |
| 섬 걷기 | 17.5 ms | 15.7 ms | 2.96 ms | 2.32 ms |
| 나무 채굴 1·2·3 | 14.9 · 10.3 · 8.6 ms | 12.3 · 10.2 · 9.3 ms | 1.89 · 1.81 · 1.41 ms | 1.77 · 1.72 · 1.66 ms |
| 분리된 나무 옆 · 걷기 | 8.9 · 8.2 ms | 10.0 · 7.0 ms | 1.81 · 1.49 ms | 1.71 · 1.37 ms |
| 콘텐츠 탐험 대기 · 걷기 | 17.5 · 18.3 ms | 16.3 · 17.9 ms | 2.35 · 2.28 ms | 2.17 · 2.52 ms |
| 개척 원정 야영지 · 걷기 · 수호자 | 15.9 · 14.8 · 7.4 ms | 17.3 · 15.2 · 8.6 ms | 2.54 · 2.11 · 0.56 ms | 3.10 · 2.27 · 0.62 ms |
| 기계 시험장 대기 · 예제 주행 | 옛 페이지 | 4.3 · 3.2 ms | 옛 페이지 | 0.35 · 0.44 ms |

- 개척 원정이 1~1.4 ms 높게 나와, 이 변경이 개척 원정에 닿는 곳이 없는지 보려고 개척 원정만 두 빌드를 번갈아 두 번 더 쟀다: 0.16.0 14.6 · 15.5 ms, 0.17.0 20.5 · 15.7 ms(야영지). 0.17.0 첫 회는 모든 장면이 함께 높았고(GC 비율 2.2%, 다른 회 1.4%) CPU 상위 함수 구성(지형 표본 `atlas.sample`·`memo`)은 두 빌드가 같았다. 측정 잡음으로 본다.
- 기계 시험장은 지형이 단순해(충돌체 44개) 다른 맵보다 가볍다.

## 한계

- 바퀴 힘(견인 340 N/EU·감쇠·옆 미끄럼 방지·조향)은 옛 시험장 예제의 속도에 맞춘 잠정 게임 보정값이다. 동력 1 EU를 100 J로 보는 다른 기계 힘과 물리적으로 맞추지 않았다(로터 양력처럼 별도 보정).
- 바퀴는 지형 칸과 건축물(`runtime.isSolid`) 위에서만 땅을 찾는다. 다른 기계나 지형 물체 위에서는 바퀴가 땅에 닿지 않은 것으로 본다.
- 50 cm 복셀 한 칸이 125 L라 가방(36칸 × 64)으로는 50 cm 기계를 몇 칸밖에 짓지 못한다. 시험장 예제와 변환 기계는 가방에서 꺼내지 않고 들여온다. 옛 화면의 "예제는 자원을 초기화" 동작은 옮기지 않았다.
- 옛 시험장의 탄성 충돌·국소 손상 규칙은 통합 런타임의 충돌 파손 규칙(0.15.8)으로 바뀌었다.
- 기계 물리 다리는 아직 프레임마다 기계의 질량 분포를 비교한다(연료가 타며 질량이 바뀐다). P2에서 다룬다.
- Android 실기기 확인은 하지 않았다.
