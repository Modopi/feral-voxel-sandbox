# 설비 에너지 검증

이 검증은 **준비된 저장 상태의 기능 검증**이다. 빈 가방에서 모든 설비까지 성장했다는 증거가 아니다. 브라우저 준비 단계에서 연구, 원재료, 설비 아이템, 최초 신성 20 EU와 안전한 발판을 지급한다. 실물 설비 설치와 저장을 마친 후에는 일반 화면의 버튼·선택 입력만으로 배선, 연료, 공정, 액체, 개인 충전 및 저장/재개를 조작한다. `prepared-save.json`은 이 준비 상태다.

재현:

```sh
python3 -m http.server 8081 --directory .
node tools/verify-expedition-energy.mjs
node --test --test-reporter=tap tests/content-fixture-energy.test.js
```

`FERAL_TEST_URL`은 기본 `http://127.0.0.1:8081/app/src/main/assets/`, `CHROMIUM_PATH`는 기본 `/usr/bin/chromium`이다. Node에서 `playwright`를 찾을 수 있어야 한다. 보고서의 파일 SHA-256과 변경 목록을 확인해야 한다. 개발 도중 코드가 바뀐 실행은 그 당시 해시의 동작 근거이며, 후속 변경 전체까지 검증했다고 해석하지 않는다. 이번 실행 중 추가한 무위치 tick 캐시와 보존 제작 설비 지정은 별도 모델 회귀로 검증한다.

브라우저 시나리오는 발전기→전지→소비 설비, 배선 차단, 연료 소진, 응집기→액체 용기, 개인 마나 입출력, 저장 재개 및 첫 성물의 명시적인 개인 신성 예약이다. 첫 성물은 다른 제작 대기열을 제거하는 비제품 API를 사용하지 않도록 준비 저장을 별도 월드 슬롯으로 불러오는 시나리오다. 같은 실행 중 저장을 주입하면 기존 런타임의 비동기 자동저장이 덮어쓸 수 있어, 먼저 월드 목록으로 이동하고 별도 슬롯에 기록한다. `FERAL_ENERGY_PHASE=relic node tools/verify-expedition-energy.mjs`는 기존 `prepared-save.json`과 주 보고서의 셋업 ID를 사용하여 성물 단계만 재현하고 `relic-report.json`을 남긴다. 최초 신성은 획득 검증 대상이 아닌 지급된 입력이다.

모델 회귀는 두 시간의 게임 시간 동안 생성·저장·소모·소실 수지를 검사하고, 미연결 근처/다른 거점 격리, 연결 비용 재시도, 고장·수리와 연결 단절, 범위 밖 작업 중지/현장 자동 발전, 저장 복원을 검사한다. 브라우저의 실제 시간 두 시간을 실행한다는 뜻은 아니다.

## 이번 구현에서 추가한 수치 제안

- 배선 최대 8m. 역학 목재 0.25 L/m, 전기·열 잡철 0.1 L/m, 화학·마법 점토 0.1 L/m, 신성 돌 0.1 L/m. 최소 유효 길이 0.25m, 비용은 0.001L 단위 올림. 철거한 절단 배선은 환급하지 않는다.
- 액체 용기 포트는 선택한 액체만 전달한다. 마나 100 EU/L, 산성액 40 EU/L는 기존 데이터다. 배관 상한 1 L/s와 고정 작업 설비 입력 상한 100 EU/s는 구현 제안이다.
- 작업 설비는 일반 저장기가 아니다. 대기 중인 해당 설비의 제작량까지만 개인 에너지를 선예약할 수 있고, 예약 에너지를 다른 설비로 출력하지 않는다.
- 전달축은 입력 역학 에너지만 전달하며 자체 발전·대기 소모가 없다. 변환기와 저장기의 출력·효율은 카탈로그 값을 사용한다. 분기는 출력을 나누고 비저장 잉여는 소실한다.
- 수피컵 한 개의 원래 용량 1L를 선택한 휴대 마나 용기로 사용한다. 고정 용기의 에너지는 개인 마나에 합산하지 않는다.
- 이전 무위치 설비·저장 에너지는 명시 회수/이체로만 이관한다. 신규 고정 저장기의 파손·철거는 에너지를 전세계 공용 잔액으로 되돌리지 않는다.

스크린샷은 Linux Chromium의 SwiftShader 소프트웨어 WebGL 출력이다. Android/실제 모바일 GPU 성능 검증이 아니다.

## 보존된 제작의 실물 설비 지정

`Progression.bindCraftJob(jobId, fixtureId)`와 에너지 탭의 선택 설비에 나타나는 “보존된 작업 지정” 버튼은 옛 무위치 제작 또는 철거되어 없어진 작업 설비만 복구한다. 예약한 입력과 진행량은 그대로 유지하고 추가 비용을 차감하지 않는다. 기존 실물 설비가 남아 있으면 다른 설비로 옮길 수 없어 작업 예약 에너지가 이동하지 않는다. 옛 자동 설치 작업은 결과를 가방으로 돌려받는다. 미지정 작업은 무에너지 공정도 진행하지 않으며 올바른 종류의 접근 가능한 정상 설비를 지정해야 한다.

무위치 tick 캐시의 측정은 `legacy-tick-benchmark.json`에 기록했다. 동일 저장의 게임 시간 1,000초를 동일 0.1초 간격으로 계산했고, 직렬화 결과가 바이트 단위로 일치했다. 공유 호스트에서 예열 후 중앙값 약 718→199ms이며 모바일 성능 수치가 아니다. 캐시는 한 동기 tick 안에서만 존재하고 고정 에너지망에는 적용하지 않는다.
