## 바뀐 것

- `content-runtime/terrain-worker.js`(새 파일): 월드 아틀라스의 사본(같은 생성기·시드·생성기 옵션·예약 구역, 편집 없음)으로 청크의 기본 칸, 열마다의 자연 수면, 청크 바깥 경계 칸(6면 × 32 × 32)을 만들어 버퍼를 복사 없이 넘긴다. Node 시험은 처리기를 `MessageChannel`로 돌린다.
- `content-runtime/atlas.js`:
  - `attachGenerator`·`detachGenerator`·`generatorState`, 생성 리비전 `generationRevision`(예약 구역이 바뀌면 오르고 이전 결과는 버린다), 요청 최대 6개, 도착 청크 설치 프레임당 최대 4개(`arrivalBudget`). 워커가 준비되기 전과 실패 뒤에는 화면 스레드 경로.
  - `chunkBorder`: 로드된 이웃 → 워커 경계(이웃 편집 반영) → 칸 조회 순. `naturalWater`: 청크 생성이 기록한 열마다의 자연 수면. `setReservations`(워커 사본용), `_installChunk`(가장 먼 청크 제거를 할당 없이).
- `content-runtime/maps.js`: 개척 원정 아틀라스의 생성기 옵션(지역 지형 버전).
- `content-runtime/scene.js`: `chunkGeometry`가 경계 칸을 `atlas.chunkBorder`로 읽는다. 먼 생물을 갱신 사이에 보간한다(`glide`).
- `content-runtime/environment-view.js`: 물 화면이 청크의 자연 수면 요약을 읽는다(없으면 전처럼 표본).
- `content-runtime/creatures.js`: 거리별 갱신(`AI_LOD`·`_lodTier`·`updateInterval`), 먼 생물의 굵은 이동 보폭, 이동 후보점·지형 표본 재사용, 숫자 칸 키. `runtime.js`: 생물 묘사에 갱신 간격.
- `content-runtime/machine-physics.js`·`machines.js`: 질량을 재사용 배열에 써서 비교하고 충돌체 질량이 0.1% 넘게 바뀔 때만 다시 설정(`MASS_TOLERANCE`, `writePhysicsMasses`). `sync`가 프레임마다 만들던 `Set`과 배열을 없앴다.
- `content-runtime/game.js`: 장면을 준비할 때 지형 워커를 띄운다. `FERAL.stats().terrainGenerator`.
- `tools/profile-runtime.mjs`: 맵마다 첫 채움 장면.
- 업데이트 파일 103개 → 104개(앱 한도 128).

## 성능 측정

같은 도구(`tools/profile-runtime.mjs`, 이번에 첫 채움 장면을 더한 판)로 0.17.0(공개된 main 체크아웃에서 서빙)과 0.18.0을 쟀다. 기록은 첫 라운드([0.18.0](0.18.0-perf.json), [기준선 0.17.0](0.18.0-perf-baseline-0.17.0.json))이고, 괄호는 두 빌드를 번갈아 다시 잰 둘째 라운드(섬·탐험·개척 원정)다. Chromium SwiftShader(4코어 컨테이너) 수치이며 실기기 수치가 아니다. 값은 프레임 루프의 JS 작업(`FERAL.perf`) ms/프레임이다.

### 첫 측정에서 찾아 고친 것

지형 워커만 넣은 첫 측정에서는 첫 채움이 빨라진 대신 채우는 동안 콘텐츠 탐험의 루프 JS가 16.3 → 33.8 ms로 올랐다. 지형 메시 단계가 0.71 → 18.1 ms였다. 원인은 두 가지였다.

1. 이웃 청크가 아직 없으면 `chunkGeometry`가 경계 칸 6144개를 칸 조회로 읽어 화면 스레드에서 기본 지형을 생성했다(Node, 이웃 없는 청크 메시 약 30 ms 중 경계가 25 ms 이상). 예전에는 화면 스레드 생성이 느려 청크가 드물게 도착해 드러나지 않았다. → 워커가 경계 칸을 함께 넘긴다. 같은 청크의 메시가 23~24 ms → 1~2 ms(Node, JIT 예열 뒤)이고 메시는 같다.
2. 물 화면이 청크마다 1024열의 지형 표본을 다시 계산했다(예전에는 화면 스레드 생성이 같은 표본 캐시를 데워 두었다). → 청크 생성이 열마다의 자연 수면을 기록하고 물 화면이 그것을 읽는다.

### 생물 AI

Node에서 같은 시드·같은 장면을 5초 돌린 생물 `_step` 시간: 콘텐츠 탐험 146 → 72 ms, 섬 72 → 32 ms(약 절반). 가까운 생물(32 m 안)의 갱신은 그대로다.
