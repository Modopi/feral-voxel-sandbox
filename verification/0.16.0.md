# 0.16.0 개척 원정을 통합 런타임으로 (통합 S2d) 검증

게임 0.16.0 / 1600, 네이티브·최소 네이티브 0.3.3 / 303, 저장 스키마 3. 게임 파일만 바꾼 릴리스다. 기준은 [소프트웨어 구조](../docs/ARCHITECTURE.md) 4·5·6장, [게임 규칙](../docs/GAME-RULES.md) 7장, [로드맵](../docs/ROADMAP.md)의 S2d다.

## 사용자 결정과 0.16.0

| 결정 | 0.16.0 |
| --- | --- |

| 사망 시 소지품 남김: 개척 원정 기본 끔 | 프리셋 기본값 `dropOnDeath: false`, 런처에서 바꿀 수 있다 |

| 새 복셀 에셋은 VoxelAssetBuilder로 | 캠페인 물건 25종을 런타임에서 `VoxelAssetBuilder`로 만든다(`signal-assets.js`). 모든 서술의 에셋이 `assertAuthoringInvariant`를 통과한다 |

## 바뀐 것

- `world-slots.js`: 개척 원정 프리셋(`runtime`, `modules: ["first-signal"]`, 생존 켬·사망 시 소지품 남김 끔). `worldConfig`가 프리셋의 `modules`를 내보낸다. 월드를 지우면 런타임 월드는 모두 `.a`/`.b`도 지운다.
- `game.js`(세션 라우터): 기계 시험장 외에는 통합 런타임으로 시작한다. `main.js` 분기를 지웠다.
- `content-runtime/first-signal.js`
  - 새 원정의 시작 보급(첫 단계에 한 번, 불러온 원정·변환한 원정은 받지 않음, `supplied` 저장).
  - `descriptors()`: 지역의 캠페인 물건(보급함·송신탑·등·빛줄기·시설·작물·측량 표석·중계기·공명 핵·채집 지점·마을 표지·주민·수호자). 상태가 바뀔 때(리비전)만 목록을 다시 만들고, 수호자 위치와 작물 단계는 그 자리에서 갱신한다.
  - `strike(hit, 피해)`: 수호자만 맞는다. `guardianZones()`: 경고 중인 공격 범위(월드 좌표, 한 번의 경고 동안 같은 값).
  - 불러올 때 중계기·관찰·의뢰의 중복과 범위 밖 값을 거부한다(옛 개척 원정 로더와 같은 검사).
- `content-runtime/first-signal-view.js`(새 파일): 여정 4쪽, 마을, 지도 이동 표와 장소, 상태 기록, HUD 목표·목적지·지역 이름, 초점 카드, 상호작용·관찰 기록, 수호자 경고(공용 `BossView`).
- `content-runtime/signal-assets.js`(새 파일): 캠페인 물건의 모양(옛 개척 원정 화면의 상자 모양과 같은 자리·색).
- `content-runtime/runtime.js`: 모듈 물건(`kind: 'module'`)을 런타임 공격으로 모듈에 넘김, 모듈 서술을 장면 목록에 더함, `loadModule`, 새 월드의 지형 옵션(`atlas`).
- `content-runtime/maps.js`: `FRONTIER_ITEMS`·`RECORD_WORK`(모듈과 변환이 함께 씀), 개척 원정 저장 변환 `applyLegacyFrontier`와 지역 지형 버전(`atlasOptions`), 섬 변환과 함께 쓰는 칸 비교 `copyLegacyCells`.
- `content-runtime/game.js`: 모듈 화면 훅(`MODULE_VIEWS`), 변환 보고서의 연구 작업·유적 핵 표시, 변환 시 원본 키 이름 전달.
- 삭제: `render.js`, `art-direction.js`, `animal-view.js`, `character-body-view.js`, `edit-grid.js`, `loose-view.js`, `loose-physics.js`, `impact-physics.js`, `machine/assembly-physics.js`, `frontier/view.js`, `frontier/campaign-view.js`, `frontier/assembly-view.js`, `frontier/motion.js`, `frontier/model.js`. `main.js`는 설명만 있는 빈 모듈(앱 0.3.3의 업데이트 검사가 `main.js`를 요구한다, `UpdateCore.java`). `play.html`의 숨은 시작 버튼과 옛 엔진만 쓰던 CSS 규칙(시작 버튼, `body.frontier` 핫바, 약탈 확인 창)도 지웠다.

## 성능 측정

같은 도구로 0.15.8(그 커밋의 체크아웃에서 서빙)과 0.16.0을 차례로 쟀다([측정](0.16.0-perf.json)). 0.15.8은 개척 원정을 옛 엔진에서 돌려 섬·콘텐츠 탐험만 비교한다. Chromium SwiftShader 수치이며 실기기 수치가 아니다.

| 장면 | 게임 JS 0.15.8 | 게임 JS 0.16.0 | 물리 단계 0.15.8 | 물리 단계 0.16.0 |
| --- | --- | --- | --- | --- |
| 섬 대기 | 15.3 ms | 15.1 ms | 2.62 ms | 2.28 ms |
| 섬 걷기 | 16.4 ms | 16.4 ms | 2.52 ms | 2.37 ms |
| 나무 채굴 1·2·3 | 13.1 · 8.5 · 10.6 ms | 13.3 · 10.4 · 10.1 ms | 1.93 · 1.40 · 2.02 ms | 2.08 · 1.78 · 2.00 ms |
| 분리된 나무 옆 | 12.7 ms | 8.9 ms | 1.99 ms | 1.74 ms |
| 분리된 나무 옆 걷기 | 9.6 ms | 10.5 ms | 1.55 ms | 1.94 ms |
| 콘텐츠 탐험 대기 | 16.1 ms | 15.4 ms | 2.14 ms | 1.84 ms |
| 콘텐츠 탐험 걷기 | 19.1 ms | 19.2 ms | 2.58 ms | 2.45 ms |
| 개척 원정 야영지 | — | 15.5 ms | — | 2.37 ms |
| 개척 원정 야영지 걷기 | — | 15.0 ms | — | 2.22 ms |
| 개척 원정 수호자 전투 | — | 7.2 ms | — | 0.59 ms |

- 물리 단계는 프레임당 값이다. 몇 분 앞서 잰 0.16.0(측정 파일의 `earlierRun`)과 비교하면 같은 빌드에서도 장면마다 게임 JS가 0.4~1.2 ms, 물리 단계가 0.1~0.4 ms 달랐다. 섬·콘텐츠 탐험의 차이는 이 범위 안이다.
- 개척 원정 야영지는 캠페인 물건 약 30개가 장면에 있는 상태로 섬 대기와 비슷하다. 물건 목록은 상태가 바뀔 때만 다시 만들고, 프레임마다 하는 일은 수호자 위치·방향과 작물 단계 갱신, 경고 중일 때의 경고 범위 표시다.
- 수호자 전투 장면은 플레이어 피해를 끈 채 수호자 7 m 옆에서 쟀다(지역 가장자리라 보이는 지형이 적다).

## 한계

- 옛 개척 원정 화면에만 있던 훈련용 몸체, 동맹 지원 인물, 해체·운반 작업장 표지는 옮기지 않았다. 동맹의 수호자 전투 지원 피해는 그대로다.
- 첫 신호 화면의 문구 일부(시설·원정 설명)는 개척 원정 문구를 그대로 쓰고, 개척 원정 아이템 이름(합금·원목·회복약)만 카탈로그 이름으로 바꿔 보인다.
- 옛 엔진을 위해 있던 화면 요소 중 주변 사건 알림(`#events`)과 비행 계기(`#flightReadout`)는 지금 아무것도 채우지 않는다([구조 문서](../docs/ARCHITECTURE.md#알려진-구조-문제-현재)).
- 기계 설계(옛 개척 원정 조립대)는 변환하지 않고 목록에 남긴다. 기계 탭에서 다시 조립한다.
- 이전 빌드로 돌아가면 개척 원정은 변환 전 원본에서 이어지고, 0.16.0에서의 진행은 그 빌드에서 보이지 않는다(저장 스키마 3).
- Android 실기기 확인은 하지 않았다.
