# 0.18.1 쓰러진 나무를 깎을 때의 렉 수정 (P2a 보충) 검증

게임 0.18.1 / 1810, 네이티브·최소 네이티브 0.3.3 / 303, 저장 스키마 4(그대로). 게임 파일만 바꾼 릴리스다. 기준은 [소프트웨어 구조](../docs/ARCHITECTURE.md) 7장("분리된 덩어리"), [로드맵](../docs/ROADMAP.md)의 P2a 보충이다.

## 신고와 재현

사용자 신고(0.18.0): "나무 세 개를 부수니까 플레이 불가능할 정도로 렉이 걸린다."

측정 도구의 나무 장면은 나무 한 그루만 쓰러뜨려서 이 경우를 잡지 못했다. 섬에서 나무 세 그루를 줄기 맨 아래 층을 잘라 쓰러뜨렸다. 이것은 마지막 줄기 칸을 캐면 나무가 분리되는 것과 같은 경로다. 그다음 실제 공격 버튼으로 그중 한 그루를 깎으며 쟀다(Chromium SwiftShader, 실기기 아님).

| 장면(0.18.0) | 루프 JS 평균 / p95 / 최대 | 50 ms 넘는 프레임(8초) |
| --- | --- | --- |
| 쓰러진 나무 세 그루 옆 | 14.0 / 25.0 / 34.2 ms | — |
| 쓰러진 나무를 깎는 동안 | 19.2 / 55.6 / 73.9 ms | 59번(최장 150 ms) |

CPU 프로파일과 Node 측정으로 찾은 원인은 모두 덩어리 크기(나무 약 550칸)에 비례하는 일을 반복하는 것이었다.

1. 물리 다리(`object-physics.js`)가 프레임마다, 그리고 물리 단계마다 모든 덩어리의 칸 목록 전체를 JSON으로 만들어 비교했다(나무 하나 0.5 ms × 나무 3그루 × 프레임당 4번). 쓰러진 나무가 있기만 해도 CPU 1위였다.
2. 덩어리 충돌체가 칸마다 하나였다. 나무 세 그루면 물리 세계에 충돌체 1644개가 더해지고, Rapier의 접촉 쌍과 JS 접촉 필터가 그만큼 늘었다(물리 단계 2.5 → 4.7 ms).
3. 칸 하나를 깨면 화면 모델을 통째로 지우고 비동기로 다시 만들었다. 표면 계산(`surfaceGroups`)이 면마다 같은 평면의 상자를 전부 훑어서, 나무 한 그루에 66 ms가 걸렸다(Node).
4. 같은 순간 물리 몸체의 충돌체 약 550개를 지우고 다시 만들었다.
5. 지형 칸을 캐서 깰 때마다 받침 탐색(`detachAround`)이 돌았다. 모든 블록은 받침이 없으면 떨어지므로, 땅으로 이어지면 2048칸 상한까지 훑으며 칸마다 배열과 문자열 키를 만들고, 같은 칸의 고정 판정을 여러 번 했다. 땅 칸 하나에 5~8 ms(Node)였고, 나무 줄기든 땅이든 칸이 깨질 때마다 걸렸다.

## 바뀐 것

- `objects.js`: 받침 탐색은 깬 칸 기준 상대 좌표를 재사용하는 형식 배열 표(`CellTable`)에 둔다. 고정 판정은 탐색 한 번 안에서 칸마다 한 번만 한다. 방문 순서·상한·판정은 같다. `physicsBodies()`는 사본 배열 대신 덩어리 자체를 순회한다. `setPhysicsPose`는 `structuredClone` 대신 값을 그대로 복사한다.
- `runtime.js`: 던전·설치물이 하나도 없으면 고정 판정이 바로 거짓을 돌려준다.
- `object-physics.js`:
  - 충돌체를 같은 블록 칸을 정확히 덮는 큰 상자로 합친다(`matterShapes`, 지형 구역과 같은 방식, 빈 칸을 덮지 않음).
  - JSON 비교를 없애고, 칸 목록 배열이 새로 만들어질 때(칸이 깨지거나, 분할·부착·고정이 바뀔 때)만 몸체를 다시 만든다.
  - 잠든 몸체는 자세를 다시 쓰지 않는다.
- `render-surfaces.js`·`scene.js`:
  - 덩어리 표면을 2 m 구역마다 캐시한다(`SectionedSurfaces`). 바뀐 구역과 경계 칸이 바뀐 이웃 구역만 다시 만든다.
  - 모델을 지우지 않고 같은 메시의 지오메트리만 바꾼다(깎는 동안 깜빡이지 않음). 그리기 횟수는 재질 묶음마다 하나로 그대로다.
- `voxel/solid.js`(공용 SDK, `tools/asset-pipeline/solid.mjs`와 같은 코드): `surfaceGroups`가 면에 닿지 않는 상자를 숫자 비교로 먼저 거른다. 앞의 `emit`개 상자만 면을 만들고 나머지는 가리기만 하는 인자를 더했다.
- `tools/profile-runtime.mjs`: 섬에 "쓰러진 나무 세 그루"와 "쓰러진 나무 깎기"(실제 공격 버튼, 조준은 가장 큰 덩어리의 칸에 고정) 장면을 더했다.

## 남은 것

- 덩어리 SDK 재구성은 칸이 깨질 때마다 덩어리 전체를 복제하고 겹침을 검사한다(SDK 규칙). SDK의 부분 삭제 경로는 목표로 남겼다([구조 7장](../docs/ARCHITECTURE.md)).
- 휴대폰 수치는 아직 없다([로드맵](../docs/ROADMAP.md) P2b).
