## 원인 (0.15.0 측정과 코드)

1. **분리된 덩어리의 흔들림이 지형 충돌체 전체 재생성을 부름.** `physics.js` `terrainAt`의 캐시 키에 모든 동적 몸체의 위치·회전·속도가 들어 있었다. 나무가 받침을 잃고 분리된 덩어리(564칸)가 되면, 쉬는 중의 미세한 흔들림만으로 키가 바뀌었다. 그때마다 플레이어 주변 지형과 덩어리 주변 지형을 칸 단위로 다시 훑어 충돌체를 새로 만들었다. 이 일이 물리 단계마다, 플레이어 이동 1 m마다, 프레임마다 일어났다.
2. **전역 리비전으로 전체 재생성.** 칸 하나만 캐도 지형 리비전이 올라가 반경 40 m 물 메시(최대 4096칸, 칸마다 유체·고체 조회 약 10번)를 0.15초마다 처음부터 다시 만들었다. 섬에서는 자연 물 열 탐색 결과가 바뀔 때나 1 m만 움직여도 다시 만들어, 가만히 있어도 프레임당 유체 조회 약 5,900번, 고체 조회 약 14,000번이 일어났다.
3. **할당이 많은 지형 메시 생성.** 칸마다 좌표 배열을 새로 만들어 32³ 청크 하나에 24~54ms가 걸렸다. 채굴할 때마다 그 청크를 다시 만들었다.
4. **생물 부위 충돌체의 매 프레임 재생성.** 행렬 분해로 얻은 크기의 끝자리(`0.09375` ↔ `0.09374999999999999`) 때문에 부위 형상 키가 바뀌었다. 그래서 머리·귀·꼬리 몸체를 프레임마다 약 10개씩 지우고 다시 만들었다.
5. **생물 AI를 한 프레임에 몰아 처리.** 0.25초마다 활성 생물 전부를 한 번에 처리해, 콘텐츠 탐험에서 그 프레임이 최대 84ms 걸렸다.
6. **느린 프레임의 악순환.** 고정 단계 누적을 0.5초까지 따라잡아(프레임당 최대 6번), 무거운 프레임 뒤의 프레임이 물리·월드 갱신을 더 많이 돌려 더 무거워졌다.

## 바뀐 구조

- `atlas.js`: 바뀐 칸의 4m 구역(8×8×8칸, `SECTION_CELLS`)을 변경 기록에 남긴다. 구역 면에 닿은 칸은 이웃 구역도 남긴다. 연속 같은 구역은 한 줄로 합치고, 4096개를 넘으면 오래된 절반을 버린다(그보다 오래 안 읽은 소비자는 전체 무효화). 예약 구역 변경은 전체 무효화다. API: `changesSince(cursor)`, `terrainSectionRevision(sx,sy,sz)`, `fluidCellsInSection()`.
- `atlas.js` 칸 조회: 불러온 청크는 편집이 이미 반영돼 있어 편집 맵을 보지 않는다. 마지막 청크를 기억하고(청크 맵 버전으로 무효화), 고체 여부는 팔레트 번호 표로 본다. 문자열·배열을 만들지 않는다.
- 지형 충돌체(`physics.js` `terrainAt`):
  - 4m 구역 단위로 둔다. 원하는 범위는 플레이어 주변과, 움직이는 몸체마다의 몸체 경계 상자+여유다. 몸체 경계 상자는 몸체 기준으로 한 번 재 둔다.
  - 구역이 범위에 들어올 때, 구역 안 고체 칸이 바뀔 때만 다시 만든다.
  - 고체 칸은 x→z→y로 키운 큰 상자로 합친다. 정확한 합집합이라 빈 공간을 막지 않고, 꽉 찬 구역은 상자 하나다.
- 물 메시(`environment-view.js`): 4m 구역마다 메시 배열을 캐시한다. 바뀐 구역만 다시 만들고 걸을 때는 구역을 더하고 빼기만 한다. 셀 수 상한(4096)은 가까운 구역부터 구역 단위로 채운다. 화면에 그리는 칸 선택 규칙(저장된 유체 + 자연 물 열의 수면)은 그대로다.
- 지형 메시(`scene.js`):
  - 생성기는 이웃 칸을 한 번 읽은 34³ 볼륨에서 인덱스 계산만 한다. 결과는 바이트 단위로 같다(실제 청크 55개 비교).
  - 고친 청크를 먼저, 가까운 순서로, 시간 예산 안에서 그린다(매 호출 최소 한 개).
- 생물 부위 충돌체: 형상을 부위·크기별로 캐시하고 크기를 1/10000로 반올림한다. 거리 판정을 먼저 해 범위 밖 생물의 행렬 갱신을 건너뛴다.
- 물리 광역 갱신: 몸체를 더하거나 지웠을 때, 플레이어 캡슐이 움직였을 때만 질의 전에 빈 물리 단계를 돈다. 충돌 어댑터에 몸체 리비전을 뒀다(원본 `tools/asset-pipeline/physics.mjs`, `npm run build:runtime`으로 생성).
- 프레임 루프(`content-runtime/game.js`, 새 `content-runtime/frame-profiler.js`):
  - 고정 단계는 프레임당 최대 3번이다. 남은 누적은 버린다.
  - 지형 메시와 청크 생성은 이전 프레임 작업이 남긴 시간(16ms 목표에서 뺀 값, 1.5~6ms) 안에서만 한다.
  - 단계별 시간을 `FERAL.perf`(`start()`/`stop()`)로 잰다.
- 생물(`creatures.js`):
  - 활성 생물을 5개 조로 나눠 0.05초마다 한 조씩 처리한다. 각 생물은 그대로 0.25초마다 dt 0.25초로 갱신된다. 오프라인 따라잡기는 예전처럼 한 번에 처리한다.
  - 플레이어 시야 광선은 가깝고 적대적일 때만 쏜다(결과가 판단을 바꿀 때만).

## 성능 측정

- 도구: `tools/profile-runtime.mjs`. 앱 MIME·CSP 규칙 서버, Chromium SwiftShader, 900×412 터치 화면이다.
- 장면은 실제 입력(이동 키, 실제 공격 버튼 누르기)으로 만든다. 분리된 나무는 준비 상태다. 가까운 나무 중 실제로 분리되는 나무의 밑동 줄기 칸을 지워 나무 전체가 덩어리 하나로 떨어지게 한다(564칸, 잎이 이웃과 이어져 한도를 넘는 나무 3그루는 원상 복구하고 건너뜀).
- 0.15.0 기준은 같은 도구로 0.15.0 빌드(`origin/main` `41b43f6`)를 서버에 올려 쟀다.
- 원자료: [0.15.1](0.15.1-perf.json), [0.15.0 기준](0.15.1-perf-baseline-0.15.0.json).

"게임 JS"는 두 버전에 모두 있는 메서드(월드 갱신·물리 단계·플레이어 이동·물리 동기화·지형 메시·모델 갱신·그리기 호출·청크 생성·환경 표시)의 프레임당 시간 합이다. "프레임 간격"은 SwiftShader가 CPU로 그리는 시간이 대부분이라 실기기 FPS가 아니다.

| 장면 | 게임 JS 0.15.0 | 게임 JS 0.15.1 | 프레임 간격 평균/p95 0.15.0 | 0.15.1 |
| --- | --- | --- | --- | --- |
| 섬 대기 | 34.3ms | 14.0ms | 49.2 / 83ms | 41.6 / 67ms |
| 섬 걷기 | 28.4ms | 13.6ms | 44.0 / 83ms | 38.5 / 67ms |
| 나무 채굴 1 | 23.2ms | 10.0ms | 38.1 / 100ms | 30.3 / 50ms |
| 나무 채굴 2 | 15.1ms | 9.9ms | 35.4 / 83ms | 36.1 / 67ms |
| 나무 채굴 3 | 14.3ms | 8.3ms | 33.1 / 67ms | 31.2 / 50ms |
| **분리된 나무 옆** | **92.3ms** | **9.3ms** | **97.9 / 183ms** | **40.8 / 67ms** |
| **분리된 나무 옆 걷기** | **130.9ms** | **8.3ms** | **134.7 / 200ms** | **35.8 / 67ms** |
| 콘텐츠 탐험 대기 | 23.8ms | 14.2ms | 56.3 / 83ms | 50.3 / 83ms |
| 콘텐츠 탐험 걷기 | 28.1ms | 17.1ms | 62.6 / 100ms | 54.2 / 83ms |

- 생물 AI의 한 번 최대 시간: 콘텐츠 탐험 24~25ms → 6~7ms, 섬 6~11ms → 1~5ms.
- 프레임당 고정 단계: 0.15.0 섬 대기 3.9번 → 0.15.1 2.3번.
- 0.15.1의 남은 비용(섬 대기, `FERAL.perf`):

  | 단계 | ms/프레임 |
  | --- | --- |
  | 물리 동기화 | 3.7 |
  | 청크 생성(로딩 직후, 예산 안) | 3.5 |
  | 물리 단계 | 2.3 |
  | 그리기 호출 | 2.0 |
  | 지형 메시 | 0.5 |
  | 물 표시 포함 환경 | 0.4 |

  청크 생성은 로딩이 끝나면 0이 된다. 섬은 시작 뒤 약 17초에 끝나고, 콘텐츠 탐험은 지형 생성이 느려 주변을 다 채우는 데 약 30초가 걸린다(로드맵 P2: 웹 워커).

## 한계

- 측정은 데스크톱 Chromium SwiftShader다. 실제 Android 기기의 프레임·발열 수치는 아니다. 기기에서 `FERAL.perf`로 받는 것은 로드맵 P2에 있다.
- 개척 원정·기계 시험장 옛 엔진은 이번 구조 밖이다(S2·S3에서 통합 런타임으로 옮기면 이 구조 위에서 돈다).
- 업데이트 파일 124개로 앱 상한 128개까지 여유가 4개뿐이다. 다음에 파일을 더하려면 은퇴 파일을 함께 정리하거나 새 APK가 필요하다.
