# 0.11.0 콘텐츠 탐험 검증

게임 0.11.0 / 1100, 네이티브·최소 네이티브 0.3.3 / 303, 저장 스키마 2. 기존 월드 유형과 저장은 유지하고 새 콘텐츠는 **내 월드 → 콘텐츠 탐험**으로 시작한다. 이 기록은 전체 기획 Goal 완료 판정과 구분한다.

## 실행 환경과 증거

- Linux 개발 환경, Node 24 및 GitHub Actions Node 22. 브라우저는 Chromium의 SwiftShader WebGL이며 Android 기기가 아니다.
- [요구사항별 구현 상태](../docs/content/IMPLEMENTATION-STATUS.md), [전체 Goal](../docs/IMPLEMENTATION-GOAL.md), [PR #16](https://github.com/Modopi/feral-voxel-sandbox/pull/16).
- 119개 SDK 복셀 모델, 131개 렌더 해시, Khronos glTF Validator의 오류·경고 0. [형식 검사](visual-assets/gltf-validation.json), [렌더 목록](visual-assets/render.json).
- [일반 입력 경로](screenshots/expedition-browser-report.json): 보존된 초기 플레이 저장에서 채집 → 돌 곡괭이 제작 → 목재 가공 → 메뉴 저장 → 재접속. 인벤토리·연구·설비·배치가 보존된다. 이후 고티어·보스까지 정상 입력으로 완주했다는 의미는 아니다.
- [전투](expedition-combat/), [에너지 설비](expedition-energy/), [3가지 화면 크기 터치](expedition-touch/report.json). 준비된 상태에서 검증한 경우 정상 성장의 증거로 세지 않는다.
- [집중 회귀 66개](0.11.0-focused-final.log): 실제 Rapier의 문 통과/정적 건물 충돌 유지, 동력·유체·열·회전·관성 장치, 설치 배치, HP 소진 사망과 골격 행동 변화. 부유하는 목재 선체와 유료 강철 화물로 인한 침수도 포함한다.

[전체 자동 테스트](0.11.0-local-tests.log)는 **495개 모두 통과**, 건너뜀0·실패0이다. 이후 안착 접촉 수정은 [실제 물리·조립·배치 회귀 46개](0.11.0-contact-regressions.log)와 [접촉 회귀1개](../tests/expedition-placement-contact.test.js)로 확인했고, 최종 변경 전체는 GitHub CI에서 다시 실행한다. [빈 상태의 전체 비용 경로](expedition-progression/0.11.0-report.json)는 39연구·27설비·31재료·10단계 장구와 저장 복원까지 통과했다. ## 실제 조립·전투에서 확인한 수정

고정 설비의 유한 저장분을 선택한 기계 컴포넌트로 이전하는 화면을 추가했다. 실제 입력으로 전지 설치, 기계4칸과 차폐벽12칸 조립, 전기40 EU 충전, 20 EU 두 번 발사와 저장 재개를 확인했다. 첫 발사는 보스 HP를28.5 줄였고 차폐벽 뒤의 두 번째 발사는 HP를 줄이지 않았다. 차폐 검사에서는 보스가 벽 앞으로 이동하지 않도록 저장에120초 기절을 준비했으므로 실전 회피·보스 완주 증거는 아니다.

Rapier가 바닥에 안착시킨 몸체의 약0.000033m 접촉 침투 때문에 옆 칸을 추가하지 못하는 결함도 이 검사에서 발견했다. 조립 후보 검사에만 최대1mm, 작은 격자는 칸 크기1/32 이내의 접촉 여유를 적용한다. 실제 충돌 형상은 줄이지 않으며 외부 물체와의 유의미한 겹침은 계속 거부한다.

## 성장과 성능의 범위

전 구간 비용 검사는 실제 생성된 채집 노드·원광과 채집 시간·도구 마모·연구 샘플·제작 입력·생산 에너지를 소비한다. 발견 보상이나 외부 자원·에너지 지급은 금지한다. 무좌표 경제 모델에서 시뮬레이션 시간을 진행하며, 실제 걷기·설비 배치·포트 배선·전투를 대신하지 않는다. 로컬 재개 검사는 원본 SHA256이 고정된 이미 비용을 지불한 checkpoint에서 계속하며, GitHub 기본 검사는 빈 상태에서 시작한다.

수정 이력은 [초기 회귀 실패](0.11.0-tests-before-fixes.log)와 [에너지 누적 오차 검사 실패](0.11.0-tests-before-energy-tolerance.log)에 보존했다. 후자는 491개 중 490개가 통과하고, 약 3,574만 EU의 최종 합산 차이 0.000750 EU가 고정 절대 오차 한도를 넘었다. 수백만 번의 부동소수 누적을 고려해 최종 총합에만 상대 한도 `5e-11`을 적용했다. 개별 제작비·수량 검사는 기존 엄격도를 유지하며, 같은 규모에서 0.01 EU 불균형은 여전히 실패한다. 수정 후 빈 상태에서 전체 경로를 다시 실행해 통과했다.

활성 범위 제한·2시간 생태 진행·공간 인덱스의 상태 동일성·큰 저장의 압축/복구는 자동 검사로 확인했다. 활성 집합은 제한되지만 방문한 지역의 보존 이력 전체를 디스크로 분할한 무한 저장 구조는 구현하지 않았다. 현재의 장거리 메모리 상한과 실제 기기 성능은 확인된 범위 밖이다.

[최종 경제 경로의 브라우저 저장 측정](expedition-save/0.11.0-final-profile.json)은 7,392,216글자의 상태를 동기 3회·worker 3회 저장하고 매번 완전 동일하게 복원했다. 두 세대 합계는 1,191,002글자다. worker 요청의 메인 스레드 시간은 93.7~112.1ms, 커밋은 14.7~21.4ms, 압축을 포함한 전체 시간은 3.10~3.95초였다. 동기 저장은 2.72~3.38초였다. 이는 고정된 성장/지형 스냅샷의 Chromium 측정이며 모든 생명체·기계가 누적된 전체 월드나 실제 모바일 수치가 아니다.

실기기 성능 기준과 필요한 기기 정보는 구현 상태표에 기록했다. Android 설치·업데이트 적용·프로세스 종료/복귀·발열·30분 및 2시간 연속 세션은 실제 Android 환경이 필요하다. 이 환경에는 연결된 Android 기기나 에뮬레이터가 없다.

## 후속 확인 (0.12.1)

이 버전의 브라우저 검사는 일반 개발 서버로 실행해서, Android 앱이 `.mjs` 모듈을 `application/octet-stream`으로 응답한다는 점을 반영하지 못했다. 그 결과 0.11.0의 콘텐츠 탐험은 Android 앱에서 로딩 화면에 멈춘다. 0.12.1에서 수정했고, 이후 검증은 앱과 같은 규칙으로 실행한다. [0.12.1 검증 기록](0.12.1.md)
