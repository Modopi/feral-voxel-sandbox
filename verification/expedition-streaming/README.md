# 장거리 왕복·영속 상태 검증

2026-10-17. [자동 검사](../../tests/expedition-streaming.test.js)는 실제 `ExpeditionRuntime`, `WorldAtlas`, 저장 서비스와 생태 서비스를 사용한다. 장거리 왕복 결과와 당시 코드 해시는 [report.json](report.json)에 있다. 생태 순회 인덱스의 이전/이후 동등성·시간 비교는 [ecology-index.json](ecology-index.json)에 별도로 기록했다.

## 사전에 정한 범위와 기준

- 원점에서 좌표 크기 1,024m, 8,192m, 32,768m의 양수·음수 조합 12곳을 방문하고 역순으로 돌아온다. 가장 먼 점은 `(-32768, -32768)`이다.
- 채굴로 제거한 셀, 음수 좌표에 변경한 셀, 파괴한 실제 던전 벽, 재료를 소비해 설치하고 손상시킨 작업대, 플레이어 기계, 분리 사물 16개, 사망 원장 128개, 회수와 생명체 드롭 원장을 확인한다.
- 청크는 기본 상한 96개 이내인지 확인하고, 별도 4개 상한 시험에서 상한까지 채운 뒤 교체한다. 야외 생명체 48, 야외 포식자 8, 표시하는 미회수 사체 32, 표시하는 자원 48 제한을 검사한다.
- 저장 예산은 두 압축 세대의 문자열 길이 합계 × 2가 **5MiB 미만**인 것으로 미리 고정했다. 다른 월드·레거시 저장과 저장소 키 크기는 포함하지 않는 추정치다.
- 별도 초기 월드에서 비활성 생태 7,200초와 대기 시간 300초를 저장·재로드를 사이에 두고 처리한다.

## 결과

검사 **3개 모두 통과**했다.

| 상태 | 초기 | 첫 원거리 방문 완료 | 왕복 완료 | 재로드 |
| --- | ---: | ---: | ---: | ---: |
| 영속 생태 지역 | 10 | 118 | 118 | 118 |
| 영속 생명체 소유자 | 70 | 836 | 836 | 836 |
| 방문한 야외 생태 셀 | 9 | 117 | 117 | 117 |
| 분리 사물 | 0 | 16 | 16 | 16 |
| 변경 셀 | 0 | 115 | 115 | 115 |

기존 소유자 ID를 보존했고 재방문과 반복 `refreshWorld()`가 개체를 추가 생성하지 않았다. 모든 사망 원장, 이미 회수한 드롭의 멱등성, 작업대 상태, 기계 원장, 사물의 원본 재질·질량·저장 포즈가 복원 후 일치했다. 고의로 부순 건물 위치와 채굴 위치도 비어 있었다.

최종 원본 JSON은 **1,942,820 UTF-8 바이트**였다. 두 압축 세대의 UTF-16 추정 합계는 **544,192바이트(약 0.52MiB)**로 기준을 통과했고 전체 원문 저장·복원 결과가 일치했다.

축소 청크 시험은 음수 소수 좌표와 정확한 `-16m` 경계를 포함한다. 항상 활성 4개 이내였고, 음수 셀의 변경값이 실제 청크 버퍼에도 반영됐다. 다른 위치로 이동한 뒤 이전 청크와 작업 큐를 제거했고, 재로드 시 청크를 영속 상태로 중복 저장하지 않았다. 캐시 중 열/샘플 8,192개, 해시 32,768개, 노이즈 코너 4,096개 제한도 검사했다.

별도 헤드리스 장면에서는 실제 SDK 자원 모델을 서로 다른 인스턴스 20개로 차례로 로드했다. 그때 필요한 모델은 1개로 유지하고 마지막에 0개로 제거했다. 실제 WebGL 할당이나 GPU 메모리는 측정하지 않았다.

2시간 비활성 생태 처리 후 대기 300초를 재로드 뒤 한 번만 소진했다. 초기 70개 소유자는 모두 이력으로 남고, 번식 이후 총 소유자 100개 중 20개가 죽은 상태였다. 시간·칼로리·HP는 유효했고 중복 ID나 대기 시간 재처리가 없었다. 이는 생태 API 검사이며 2시간 전체 플레이/물리/렌더 시뮬레이션은 아니다.

## 보존되는 데이터와 확장성 한계

방문한 생태 지역, 생명체와 사체 이력, 건물 인스턴스, 플레이어 변경, 회수 원장은 재방문 일관성을 위해 정상적으로 누적된다. 왕복에서 이 수가 다시 증가하지 않은 것으로 중복 스폰과 재방문 누적을 구분했다. 이 누적 자체를 메모리 누수라고 판정하지 않는다.

후속 생태 최적화는 공간 인덱스와 due queue를 사용해 활성 근처 개체 및 갱신 시점이 된 비활성 지역·개체만 선택한다. 80개 지역에서 활성 120초(480개체)와 비활성 7,200초(987개체)를 이전 구현과 비교했을 때 최종 저장 상태가 두 경우 모두 `deepEqual`이었다. 공유 Linux Node 환경의 시간은 활성 169.5ms→107.3ms, 비활성 3,112.0ms→702.3ms였다. 관련 creature/streaming 검사 33개가 통과했다. 이 수치는 모델 실행 비교이며 실기기 성능을 뜻하지 않는다.

공간·갱신 인덱스는 반복적인 전체 순회를 줄였지만 영속 생태 지역과 모든 소유자를 메모리에 계속 보관한다. 무한히 새 지역을 방문할 때 메모리 사용이 일정하다는 보장은 없다. 변경·이력을 지우지 않는 지역별 저장과 메모리 교체는 추후 확장성 작업이다. `report.json`은 이 인덱스 최적화 이전의 장거리 왕복 측정이며, 해당 기존 보고서의 `creatures.js` 해시는 [ecology-index.json](ecology-index.json)의 `beforeSha256`과 일치한다.

표시 범위 안에 있는 사용자 제작 사물/기계와 던전 생명체 전체에 하나의 공통 모델 개수 상한이 있는 것은 아니다. 위 검사로 모든 종류의 모델 수가 48개로 제한된다고 주장할 수 없다.

이동은 시험 코드가 좌표를 직접 바꿨고 설치용 자원도 명시적인 시험 준비값을 지급했다. 실제 입력으로 이동해 정상 성장한 플레이 증거가 아니다. 순수 Node 시험이며 실기기 메모리/프레임/Android 검증을 포함하지 않는다.

재현:

```sh
FERAL_STREAMING_REPORT=verification/expedition-streaming/report.json node --test tests/expedition-streaming.test.js
```

환경 변수를 생략하면 검사는 실행하되 근거 파일을 덮어쓰지 않는다.
