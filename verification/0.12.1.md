# 0.12.1 Android 콘텐츠 탐험 로딩 수정 검증

게임 0.12.1 / 1201, 네이티브·최소 네이티브 0.3.3 / 303, 저장 스키마 2. 게임 파일만 바꾼 핫픽스다.

## 증상과 원인

Android 앱에서 콘텐츠 탐험을 열면 "숲과 오래된 건축물을 준비하고 있습니다." 화면에서 더 진행되지 않았다.

앱의 자산 응답(`MainActivity.shouldInterceptRequest`)은 `.js`·`.css`·`.html`·`.json`만 해당 형식으로 보내고, 나머지는 `application/octet-stream`으로 보낸다. 0.11.0부터 콘텐츠 탐험은 `.mjs` 모듈 5개를 불러왔다. 복셀 도구 `content-runtime/voxel/{authoring,model,solid,physics}.mjs`와 저장 압축 `vendor/lz-string.mjs`다. 브라우저는 형식이 맞지 않는 모듈 스크립트를 거부하므로 `entry.js`의 모듈 전체가 실행되지 않았고, 오류 표시 없이 로딩 화면만 남았다.

이전 브라우저 검사는 `.mjs`를 JavaScript로 응답하는 일반 개발 서버로 실행해서 이 문제를 보지 못했다.

**재현:** 앱과 같은 규칙으로 응답하는 `tools/android-asset-server.mjs`에서 0.12.0 코드를 열었다. 60초 동안 같은 로딩 문구에 머물렀고, 콘솔에는 "Expected a JavaScript-or-Wasm module script but the server responded with a MIME type of application/octet-stream" 오류만 남았다.

## 수정

- 런타임 모듈 5개를 `.js`로 바꿨다. `tools/build-runtime-content.mjs`는 도구 원본을 그대로 복사하되 형제 import의 확장자만 `.js`로 바꿔 생성한다.
- 로딩 화면에 진행 막대·단계·퍼센트·경과 시간을 표시한다.
  - 단계: 저장 확인 → 건축물 모델(개수별) → 세계 구성 → 설비 → 장면 → 물리 엔진 → 시작.
  - 한 단계가 25초 넘게 이어지면 안내와 다시 시도 버튼을 표시한다.
  - 게임 파일을 불러오지 못하면 실패 문구·멈춘 단계·다시 시도 버튼을 보여 주고 앱에 시작 실패를 알린다.
  - 이 표시는 일반 스크립트라서 게임 모듈이 실패해도 동작한다.

## 검증

- 신규 `tests/android-asset-mime.test.js`(3개)는 `MainActivity.java`에서 MIME·CSP 규칙을 읽어 검사한다.
  - 게임이 불러오는 모든 스크립트·스타일 경로가 JavaScript·CSS로 응답되는지 확인한다.
  - 자산 폴더에 `.mjs`가 없는지 확인한다.
  - 콘텐츠 탐험이 CSP로 막힌 네트워크 요청을 쓰지 않는지 확인한다.
  - 수정 전 코드에서는 두 번째 검사가 실패하는 것을 확인했다.
- 전체 회귀 `node --test tests/*.test.js`: **505개 모두 통과**, 실패 0([기록](0.12.1-local-tests.log)). 0.12.0의 502개에 신규 3개를 더했고, 0.12.1 버전으로 실행했다.
- `tools/verify-ui-reachability.mjs`는 이제 앱 규칙 서버를 기본으로 실행한다. 콘텐츠 탐험 10개, 기본 섬 3개 경로를 확인했고 페이지 오류는 0건이다([보고서](0.12.1-ui/report.json)).
  - 로딩 단계가 차례대로 표시된 뒤 게임이 시작된다. 데스크톱 SwiftShader에서 약 1~2초 걸렸다.
  - 단계별 시간 기록은 보고서의 `bootTimings`에 있다.
  - 모듈 하나를 잘못된 형식으로 응답하게 만들면 실패 안내·다시 시도·`runtimeFailed` 호출이 나타난다([화면](0.12.1/loading-failure.png)).
  - 0.12.0의 화면 연결 경로와 기본 섬 경로도 같은 규칙에서 다시 통과했다.
- 로딩 진행 [화면](0.12.1/loading-progress.png).

## 빌드와 패키지

- `bash build-apk.sh`: APK 빌드와 v2/v3 서명 확인([로그](0.12.1-apk-build.log)).
- `python3 tools/build-update.py`: 서명 업데이트 120개 파일, ZIP 2,797,982바이트, 해제 11,515,898바이트. 패키지 안에 `.mjs` 파일은 없다.
- APK 동봉 게임 파일과 업데이트 패키지 파일이 바이트 단위로 같다. [측정값](0.12.1-package.json)
- `node tools/build-runtime-content.mjs --check`가 통과해 생성 파일 11개가 원본과 일치한다. 에셋 원본은 바뀌지 않았다.

## 남은 검증

- Android 실기기에서 0.12.1을 업데이트한 뒤 콘텐츠 탐험이 실제로 시작되는지, 단계별 시간이 얼마인지 확인해야 한다. 데스크톱 측정값은 휴대폰 시간을 대신하지 않는다.
