# 0.15.0 런처와 게임 세션 분리 · 버전이 바뀌어도 저장 유지 검증

게임 0.15.0 / 1500, 네이티브·최소 네이티브 0.3.3 / 303, 저장 스키마 2. 게임 파일만 바꾼 릴리스다. 기준은 [소프트웨어 구조](../docs/ARCHITECTURE.md)와 [로드맵](../docs/ROADMAP.md)의 L1 완료 기준이다.

## 사용자 요청과 결정

| 요청 | 0.15.0 |
| --- | --- |
| 첫 화면은 랜딩, 게임 들어가기 전 맵 선택·새 맵·맵 설정·전역 환경설정을 하는 관제 화면(런처). 맵에 들어가면 시스템은 하나 | 앱을 켜면 런처(`index.html`)가 나온다. 월드 선택·만들기·설정·삭제, 환경 설정, 업데이트를 여기서 한다. 월드에 들어가면 게임 세션(`play.html?world=<id>`)이 그 월드 설정을 따른다. 세션 안의 엔진 통합은 다음 단계에서 다듬는다(사용자 결정 순서) |
| 업데이트할 때마다 이전 맵이 초기화됨. 세이브 시스템을 제대로 | 원인은 앱 0.3.3의 게임 버전 목록 선택이었다. 목록에서 고른 빌드는 그 빌드 몫의 `feral.*` 저장만 받아, 처음 실행하는 빌드는 빈 저장으로 시작하고 자동 업데이트도 꺼졌다. 저장 보관함(IndexedDB)이 최신 저장 전체를 두고 런처가 되살린다 |

## 원인 확인 (코드)

- `UpdateManager.chooseVersions` → `UpdateCore.stage(..., manual=true)`가 `pendingManual=1`로 표시하고 `pinned=true`로 자동 확인을 끈다.
- 다음 실행의 `UpdateCore.beginTrial`은 현재 빌드의 `feral.*` 저장을 `saves/<현재 코드>.json`에 두고 `isolateTrial=1`로 바꾼다. `activationSnapshot()`은 고른 빌드의 `saves/<코드>.json`을 돌려주고, 없으면 `{}`를 돌려준다.
- `MainActivity.bootstrapHtml`은 그 값으로 `feral.*` 키를 모두 지운 뒤 다시 채운다. 처음 실행하는 빌드는 빈 저장이 된다.
- 일반 업데이트(`check` → `stage(..., manual=false)`)는 `isolateTrial=0`이라 저장을 그대로 둔다.
- 이 동작은 APK에 있다. 바꾸려면 새 APK와 `minNativeCode` 증가가 필요하고, 그러면 모두가 APK를 다시 설치해야 0.15.0을 받을 수 있다. 그래서 게임 파일로 해결했다. 앱은 IndexedDB를 건드리지 않는다.

## 바뀐 구조

- 런처: `index.html` + `launcher.js`.
  - 랜딩: 이어하기·월드 선택·환경 설정·업데이트.
  - 월드 목록: 맵·시드·설정·저장 유무·마지막 플레이.
  - 월드 만들기·설정 대화상자: 프리셋별로 세션이 읽는 항목만 보이고, 만든 뒤 바꿀 수 없는 항목은 잠근다.
  - 엔진은 띄우지 않는다. 화면을 그린 뒤 `content-runtime/game.js`를 실행하지 않고 불러 보고 나서 앱에 시작 성공을 알린다.
- 저장소 계층: `world-slots.js`.
  - 월드 설정(`PRESETS`·`RULES`·`worldConfig`·`createWorld`·`updateWorld`·`touchWorld`)과 저장 보관함(`reconcileVault`·`mirrorVault`·`syncVault`·`restoreFromVault`)을 둔다.
  - 전역 설정은 `settings.js`가 맡고, 런처와 세션 메뉴가 같은 양식을 쓴다. 업데이트 화면도 `updates.js`가 그린다.
- 게임 세션: `play.html`(이전 `index.html`의 게임 화면) + `game.js`.
  - `game.js`는 세션 라우터다. 옛 엔진(개척 원정·기계 시험장)을 고르는 유일한 곳이다.
  - 통합 런타임은 `start(world)`로 시작하고, 생존·샌드박스·시작 건축물·시작 소지품을 월드 설정에서 읽는다. 불러오기만으로는 아무것도 시작하지 않는다.
- 저장 보관함: 모든 `feral.*` 키의 최신 전체 사본을 IndexedDB `feral-vault`에 둔다.
  - 엔진이 저장할 때마다(통합 런타임 자동·수동, 개척 원정 저장·지역 이동, 기계 시험장)와 런처에서 바꿀 때 바뀐 키만 복사한다. 지운 키는 사본에서도 지운다.
  - 런처가 시작할 때 이 빌드의 저장이 비었거나 사본보다 오래됐으면 사본 전체로 바꾼다. 쓰다 실패하면 원래 저장을 되돌린다.
  - 보관함을 모르는 빌드(0.14.1 이하)의 저장이 있으면 그대로 두고 사본을 그것으로 바꾼다.
  - 더 높은 `saveSchema`의 사본은 가져오지도 덮지도 않는다.
- 은퇴: `worlds.html`, `world-menu.js`, `expedition.html`. 예전 주소 `index.html?world=…`는 게임 세션으로 넘어간다. 업데이트 파일 수는 123개 그대로다.

## 검증

- 전체 회귀 `node --test tests/*.test.js`: **540개 모두 통과**, 실패 0([기록](0.15.0-local-tests.log)). 0.14.1의 527개에 신규 `tests/launcher.test.js` 13개를 더했다.
  - 월드 설정:
    - 0.15 이전 월드는 프리셋 기본값으로 읽히고, 이전 빌드가 읽는 항목은 바뀌지 않는다.
    - 세션이 읽지 않는 설정은 거부하고, 만든 뒤 바꿀 수 없는 설정의 수정도 거부한다.
    - 더 새로운 설정 형식은 잘못 읽지 않고 거부한다.
    - 마지막 플레이 시각만 기록한다.
  - 구조:
    - 런처와 세션은 다른 페이지이고, 엔진 선택은 세션 라우터에만 있다.
    - 런타임 진입 모듈은 DOM에 손대지 않고 불러진다.
    - 런타임은 월드 설정을 맵 프리셋보다 우선하고, 설정을 저장에 복사하지 않는다.
  - 저장 보관함(앱 0.3.3의 버전 목록 전환을 그대로 흉내 냄):
    - 처음 실행하는 빌드가 빈 저장을 받아도 월드·저장·설정이 돌아오고, 다음 빌드로 최신 진행이 이어진다.
    - 같은 스키마에서는 이전 빌드로 돌아가도 최신 사본을 받는다. 더 높은 스키마의 사본은 낮은 스키마 빌드가 가져오거나 덮지 않는다.
    - 보관함 이전 빌드의 저장은 그대로 두고 사본 전체를 바꾸며(두 빌드의 키가 섞이지 않음), 지운 월드는 되살아나지 않는다.
    - 바뀌지 않은 저장은 다시 쓰지 않는다. 저장 공간이 차서 되살리기가 실패하면 원래 저장을 되돌린다.
  - 바뀐 기존 테스트: `unified-game.test.js`의 경로 시험(모든 월드가 `play.html`, 런처는 `index.html`), 세션이 읽는 요소 목록에 `settings.js`·`updates.js` 포함.
- 런처·게임 세션 화면 검증 `tools/verify-ui-reachability.mjs`: 앱과 같은 MIME·CSP 규칙의 서버에서 **25개 경로 통과, 페이지 오류 0**([보고서](0.15.0-ui/report.json)). 신규 런처 8개는 다음과 같다(844×390 휴대폰 가로, 실제 터치).
  - 앱 시작이 런처 랜딩을 연다. 엔진·3D 캔버스가 없다. 세션 파일 확인 뒤 앱에 시작 성공(1500)을 알린다([랜딩](0.15.0-ui/launcher-landing.png)).
  - 콘텐츠 탐험 월드를 생존 끔·시작 건축물 켬으로 만든다([만들기](0.15.0-ui/launcher-create.png)). 저장된 설정을 확인한다.
  - 설정 편집에서 이름을 바꾼다. 시작 건축물은 잠긴다.
  - 런처 환경 설정에서 주변 사건 알림을 켜고, 업데이트 화면에 게임 0.15.0이 보인다([설정](0.15.0-ui/launcher-settings.png)).
  - 플레이:
    - 세션이 월드 설정(평화 규칙·체력 막대 숨김)과 런처에서 바꾼 전역 설정을 따른다.
    - "저장 후 런처로"로 돌아오면 이어하기에 그 월드가 보인다([이어하기](0.15.0-ui/launcher-continue.png)).
  - 버전 전환 시 저장 유지:
    - 앱이 버전 목록 전환 때 하듯 `feral.*`를 모두 지우고 런처를 다시 연다.
    - 키 4개가 모두 같은 값으로 돌아오고 "이전 게임 버전의 저장 4개를 가져왔습니다"가 보인다([되살리기](0.15.0-ui/launcher-vault-restored.png)).
    - 이어하기로 들어간 월드는 저장된 시간·규칙에서 이어진다.
  - 기계 시험장도 같은 입구(`play.html` → `machine.html`)로 들어간다. 삭제는 확인 창을 거치고 저장도 지운다. Android 뒤로 가기는 대화상자를 닫고 랜딩으로 돌아간다.
  - 세션 파일이 깨진 버전(`runtime.js` 404): 런처가 시작 성공 대신 실패를 알린다(`runtimeFailed` 1회, `runtimeHealthy` 0회).
  - 기존 17개 경로(콘텐츠 탐험 9·기본 섬 6·개척 원정 1·로딩 실패 1)는 `play.html` 주소로 그대로 통과했다. 예전 주소 `index.html?world=ui-check`는 `play.html`로 넘어간다. 로딩 실패 화면에 런처로 돌아가기가 보인다.
- 기존 화면 검사 `tests/*-check.cjs` 19개: 아래 표. 월드 목록을 쓰던 machine·interface-editor·menu-reachability 검사는 런처 화면으로, updates-ui는 세션 주소로 단언을 옮겼다.

## 남은 검증과 범위

- Android 실기기 확인이 필요하다: 런처 시작·시작 성공 신호, 버전 목록 전환 뒤 저장 되살리기, WebView IndexedDB. 데스크톱 Chromium 결과는 대신하지 않는다. IndexedDB를 쓸 수 없는 환경이면 보관함은 꺼지고 지금처럼 앱의 저장 동작만 남는다.
- 0.14.1 이하에서 버전 목록으로 0.15.0을 고르면 그때는 보관함이 비어 빈 저장으로 시작한다. 이번 업데이트는 "지금 확인 → 저장 후 적용"으로 받아야 한다. 이미 빈 저장이 됐다면 버전 목록에서 이전 버전을 다시 골라 저장을 되찾은 뒤 지금 확인으로 올린다(앱이 빌드별로 보관 중).
- 세션 안의 엔진 통합(S1 세션 입구 정리, S2 개척 원정, S3 기계 시험장)은 로드맵의 다음 단계다. 남은 구조 문제는 [구조 문서 6장](../docs/ARCHITECTURE.md#알려진-구조-문제-현재).
- 앱의 버전별 저장 분리 자체를 없애는 것은 새 APK가 필요한 별도 결정이다.
