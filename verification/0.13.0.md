# 0.13.0 하나의 게임 화면 검증

게임 0.13.0 / 1300, 네이티브·최소 네이티브 0.3.3 / 303, 저장 스키마 2. 게임 파일만 바꾼 릴리스다. 기준은 [하나의 게임으로 통합](../docs/archive/UNIFIED-GAME.md)의 P1 완료 기준이다.

## 바뀐 구조

- 모든 월드(기계 시험장 제외)가 `index.html`과 `game.js`에서 시작한다. `game.js`는 월드 유형에 따라 섬·개척 원정(`main.js`) 또는 콘텐츠 탐험(`content-runtime/game.js`)을 같은 화면 위에 올린다. 예전 `expedition.html`은 같은 월드의 `index.html`로 넘기는 페이지만 남겼다.
- `main.js`와 `frontier/view.js`에 있던 조작·알림·설정·메뉴·이동 버튼 상태·오류 화면·현장 HUD·장부 창을 공용 `shell.js`로 옮겼다. 콘텐츠 탐험의 `entry.js`·`expedition.css`와 전용 패널·알림 큐·조작 코드는 삭제했다.
- `inventory-ui.js`는 아이템 카탈로그 어댑터를 받는다. 섬·개척 원정은 기존 아이템(`legacyCatalog`), 콘텐츠 탐험은 설계 데이터(`designCatalog`)를 같은 36칸·9칸 핫바에 표시한다. 콘텐츠 탐험의 수량 기반 인벤토리는 `content-runtime/item-slots.js`가 64개 묶음 칸으로 배치하며, 칸 배치는 저장의 선택 필드 `itemSlots`에 남는다.
- 앱의 업데이트 파일 상한(128개) 때문에 공용 모듈은 한 파일로 두었다. 업데이트 파일은 122개다.

## 검증

- 전체 회귀 `node --test tests/*.test.js`: **512개 모두 통과**, 실패 0([기록](0.13.0-local-tests.log)). 0.12.1의 505개에 신규 `tests/unified-game.test.js` 7개를 더했다.
  - 섬·개척 원정·콘텐츠 탐험이 `index.html`로 열리고 기계 시험장만 `machine.html`로 남는지, 예전 `expedition.html`이 넘기기만 하는지 확인한다.
  - 세 맵이 `shell.js`의 조작·알림·설정·메뉴·이동 버튼·현장 HUD·장부 창을 쓰고, 콘텐츠 탐험에 전용 CSS·페이지·`entry.js`·자체 알림 큐·자체 버튼 코드가 없는지 확인한다.
  - 콘텐츠 탐험 화면이 읽는 모든 요소 id가 공용 페이지나 공용 모듈에 있는지 확인한다.
  - 수량 기반 인벤토리의 36칸 배치(64개 묶음·소수 수량·칸 이동·저장 복원·사용 후 칸 비움·보관품), 설계 아이템의 이름·그림·마모·얻는 곳·제작법, 알림 대기열을 검사한다.
  - 업데이트 파일 수가 앱 상한(128개)보다 4개 이상 적은지 확인한다.
- 하나의 게임 화면 검증 `tools/verify-ui-reachability.mjs`: 앱과 같은 MIME·CSP 규칙의 서버에서 14개 경로를 실제 터치로 확인했고 페이지 오류는 0건이다([보고서](0.13.0-ui/report.json)). 아이템 지급·순간 이동 같은 준비 단계는 보고서에 따로 적었다.
  - 콘텐츠 탐험 9개: 예전 주소에서 `index.html`로 넘어와 공용 로딩·HUD로 시작, 공용 스틱·달리기, 기계 하강·제동과 상호작용 버튼으로 내리기, 경고와 알림 대기열, 장부 창의 연구 멈추기·이어서, 가방의 제작·대기열(먼저 진행·취소 반환), 핫바 마모·음식 사용, 공용 그래픽 설정·HUD 편집기, 던전 보상 표식·상호작용 라벨·회수·여정 기록·장치 공급선 분리.
  - 개척 원정 1개: 공용 모듈의 현장 HUD·장부 창·가방.
  - 기본 섬 3개: 공용 로딩 표시, 빈 손 관찰, 메뉴의 물 붓기 도구, 미니맵 설정·장소 발견 알림.
  - 공통 1개: 모듈을 불러오지 못하면 공용 로딩 화면에 실패·다시 시도가 나오고 앱에 시작 실패를 한 번 알린다([화면](0.13.0-ui/loading-failure.png)).
  - 화면: [가방·제작 대기열](0.13.0-ui/bag-craft-queue.png), [장부 창 연구](0.13.0-ui/research.png), [던전 장치](0.13.0-ui/devices.png), [보상 표식](0.13.0-ui/reward-marker.png), [HUD 편집기](0.13.0-ui/hud-editor.png), [개척 원정 가방](0.13.0-ui/frontier-bag.png), [기본 섬](0.13.0-ui/island.png).
- 기존 화면 검사 `tests/*-check.cjs` 19개를 같은 방식으로 다시 실행했다. 커밋된 검증 이미지를 덮어쓰지 않도록 별도 작업 폴더에서 실행했고, 실패한 검사는 수정 전 main(0.12.1)에서도 같은 조건으로 실행해 비교했다.

## 빌드와 패키지

- `bash build-apk.sh`: APK 빌드와 v2/v3 서명 확인([로그](0.13.0-apk-build.log)).
- `python3 tools/build-update.py`: 서명 업데이트 122개 파일(앱 상한 128개), ZIP 2,807,300바이트, 해제 11,540,935바이트. `entry.js`·`expedition.css`·`.mjs` 파일은 없다.
- APK 동봉 게임 파일과 업데이트 패키지 파일이 바이트 단위로 같다. [측정값](0.13.0-package.json)
- `node tools/build-runtime-content.mjs --check`, `npm run audit:design`(오류 0), `npm run check:assets` 통과. 콘텐츠 데이터와 에셋 원본은 바뀌지 않았다.

## 남은 검증과 범위

- Android 실기기에서 0.13.0을 업데이트한 뒤 세 맵의 화면·터치 조작을 확인해야 한다. 데스크톱 SwiftShader 결과는 휴대폰 결과를 대신하지 않는다.
- 이번 단계는 화면 통합이다. 아이템·생명체·월드 규칙과 런타임은 아직 섬·개척 원정(`main.js` 계열)과 콘텐츠 탐험(`content-runtime/`)으로 나뉘어 있고, 기계 시험장은 별도 페이지다. 다음 단계는 [통합 문서](../docs/archive/UNIFIED-GAME.md#4-단계)의 P2·P3이다.
- 콘텐츠 탐험은 1인칭 손에 든 아이템 모델과 3D 캐릭터 상태 화면이 아직 없다(P2의 캐릭터 표시 이식).
